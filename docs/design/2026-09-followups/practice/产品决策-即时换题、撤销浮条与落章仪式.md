# 产品决策：即时换题、撤销浮条与落章仪式

决策日期：2026-09-03  
状态：已拍板，替代本批此前关于“1.8 秒反馈页”和“重盖”的全部要求。

## 一、用户真正需要什么

用户完成自评后，主要意图是继续写下一题，而不是停留观看系统重复确认。产品同时要提供一个低成本的反悔机会，但不能用新的阻塞步骤换取安全感。

“重盖”要求用户先理解产品内部的盖章隐喻。当前判断动作本身并没有被命名为“盖章”，因此该词不够直白，正式界面删除。

## 二、最终交互

1. 用户在揭晓页点击“写对了”或“写错了”。
2. 记录只提交一次，界面立即进入下一题；不出现反馈等待页，不显示“下一题”按钮。
3. 下一题顶部显示约 5 秒的非模态浮条：
   - `已记为写对　撤销`
   - `已记为写错，稍后再练　撤销`
4. 点击“撤销”恢复上一题的题目、提交笔迹与揭晓状态，让用户重新选择对错。
5. 下一题落下第一笔时浮条立即消失，撤销窗口随之提交，不能为撤回上一题而丢失下一题笔迹。
6. 快速连点只能记录和推进一次，不能越过下一张未作答卡。
7. 跳过采用同一原则：立即展示真实下一题，并在下一题提供可撤销的轻提示，不停在中间反馈页。

浮条不是系统弹窗或模态框，不抢焦点、不遮挡题目和手写区。VoiceOver 通过 live region 朗读记录结果，并提供可访问名称“撤销上一题判断”。

## 三、盖章是否保留

**保留，但只保留仪式感，不保留理解成本。**

- 点击判断时可出现约 180ms 的落章动效和轻触觉反馈，换题同时开始，不等待动画结束。
- 下一题浮条可以带一个小印记，提示刚才的结果已经记录。
- 一组结束后的结果页继续展示累计印章，让零散动作形成完成感。
- 不把“盖章、重盖”作为按钮、提示或流程名称；用户不理解印章含义也能完整操作。
- 减少动态模式取消落章运动，但保留文字、符号和触觉之外的静态结果表达。

## 四、设计修正范围

本轮无需重做 C1–C11 的主体视觉，只修正结果推进相关状态：

1. 将旧 C12/C13 从独立等待页改成“下一题 + 写对/写错撤销浮条”。
2. 将 C14 改为点击“撤销”后返回上一题揭晓，不出现“重盖”。
3. 将 C15 改成跳过后立即进入真实下一题，并保留撤销跳过浮条。
4. 删除所有可见的“1.8 秒后下一题”“重盖”“已盖某章”等需要解释的操作文案。
5. 保留非阻塞落章动效，并给出普通、减少动态和 VoiceOver 三种状态说明。

## 五、验收路径

- 独立写对 → 立即下一题 → 显示写对撤销浮条 → 不撤销继续写。
- 写错 → 立即下一题 → 显示稍后再练与撤销 → 点击撤销回到原揭晓页。
- 下一题第一笔落下 → 浮条消失 → 不再允许撤回上一题。
- 判断按钮快速三连点 → 只记录一次，只前进一题。
- 跳过 → 立即下一题 → 撤销跳过可恢复原字、原位置、墨迹和提示。
- 减少动态 → 无落章运动，但即时换题、文字结果和撤销仍成立。

设计原型只需演示这些状态和因果关系。正式数据回滚、幂等记账、队列恢复和调度由开发接入项目现有状态机实现。
