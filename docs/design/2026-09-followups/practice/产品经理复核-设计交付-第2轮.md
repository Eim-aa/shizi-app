## 二、必须修正

### P1-1：跳过后停在不可操作的 C15，用户无法继续下一字

当前点击“跳过”后，C15 只显示一个变暗的下一字占位和撤销按钮。下一字区域没有 canvas，且 `.skip-ghost` 为 `pointer-events:none`；页面也没有自动推进计时器或“继续”动作。

独立实测：点击跳过后等待 2.2 秒，状态仍是 C15；页面始终只有“返回”和“撤销”两个按钮，用户若不撤销，只能被困在这里。

这违反状态矩阵中 C15 的允许动作“撤销、继续下一字”和路径 E 的 `C15 → 下一字`，也意味着当前原型并未真正跑通 A–E 五条路径。

证据：`app.js` 第 225–230、446–449、477–498 行；`styles.css` 第 209–218 行。

修正要求：

1. 跳过反馈采用与单字反馈一致的短暂停留：约 1.8 秒后自动进入真实可书写的下一字。
2. 用户可点击反馈区域立即进入下一字；“撤销”仍在短窗口内恢复被跳过的原字、原组位置、墨迹和提示。
3. 自动推进只能发生一次；快速连点不能越过下一张未作答卡。
4. 减少动态模式只取消动画，不能取消自动进入下一字这一状态变化。
5. C15 不再把下一字画成永久不可操作的假页面。可以在反馈期保留轻量预告，但反馈结束后必须进入真实 C3/C2 状态。

### P1-2：首次校准的下一字与进度是伪造的，真实首旅程会出现不可能状态

单独打开 C2 时首卡内容已经正确，但连续操作后仍会落入普通示例的固定数据：

- 从 C2 的“尴”独立书写并自评后，下一张从 `已练 0 / 15 个` 直接变成 `已练 3 / 15 个 · 另有 2 个字要再练`，题目也跳成普通示例“植”。
- 在 C2 首卡直接跳过，C15 同样显示 `下一字 · 已练 3 / 15 个`，并预告“叶”。跳过本来不产生练习记录，不能凭空增加 3 个已练字。

固定代码快照的校准组前两张为“尴、嚏”；第一张完成后应继续校准组，进度为 1/15。若第一张被跳过，应由校准组替补字接续，已练仍为 0/15。当前行为会直接破坏首次用户对校准、进度和数据可信度的理解。

根因是原型的 `nextCard()` 和 `skipMarkup()` 使用固定普通示例，没有保存最小的组模式、完成数量与下一目标；现有 E01/E15/E20 从预置状态验证单页，没有覆盖 C1 起步后的真实连续推进。

证据：`app.js` 第 32–35、77、225–230、466–475 行；固定代码快照 `index.html` 中校准钩子为“尴、嚏”，正式进度由已产生的 `roundStats` 唯一字数计算。

修正要求：

1. 原型增加最小但真实的旅程状态：至少保存当前模式、已完成基础字数、待再练字数和下一目标，不再由页面 ID 硬编码进度。
2. 首次校准首卡“尴”完成后，下一张仍是校准组“嚏”，显示 `已练 1 / 15 个`。
3. 首卡“尴”被跳过后，跳过不增加已练数；反馈结束进入校准替补字，显示 `已练 0 / 15 个`。
4. 普通示例从 `3 / 15` 完成一张后也应推进到 `4 / 15`；使用提示、描写或写错时，按已确认规则同步更新“另有 N 个字要再练”。
5. 不在设计原型中重新发明选题或调度算法；只做足以让真人测试看见诚实连续结果的最小状态模型。

## 三、第 3 轮复核的最小证据

不需要重做本轮已经通过的 14 张画面。请更新原型、状态验收记录、修正回执和自动证据，并补充以下真实点击路径：

1. `C1 → 开始第一组 → C2 尴 0/15 → 独立落笔 → 揭晓 → 写对 → 反馈 → 嚏 1/15`。
2. `C1 → C2 尴 0/15 → 跳过 → C15 → 自动进入校准替补字 0/15`。
3. 上一路径在 C15 反馈期点击“撤销”，恢复 `尴 / gān / 尬 / 0/15`，且原墨迹和提示按跳过前状态恢复。
4. 普通卡从 `3/15` 完成后进入 `4/15`，不会重置或跳数。
5. C15 等待 2 秒内进入真实下一卡；点击反馈可立即进入；快速连点不会多推进一张。
6. 减少动态模式下 C15 仍会推进；控制台无错误。

完成这两个 P1 后进行第 3 轮快速复核。通过后，才进入 3 至 5 位首次用户的无引导理解测试。
