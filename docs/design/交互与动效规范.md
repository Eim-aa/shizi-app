# 拾字 · 交互与动效规范 v1

- **地位**：与 [设计系统 v1](design-system-v1/README.md)（D43，管「长什么样」）同级，管「怎么动、怎么走、怎么回应」。两者冲突时，静态外观以设计系统为准，行为与时间以本规范为准。
- **来由**：产品负责人 2026-10-12：「判断那一步也要能左滑返回……交互、动画等也应该有统一的标准的一个体系……小的细节就不用一一改了，都会按照体系来设计或设定。」
- **上位原则**（decisions.md D55 ⑤ 等）：常用操作必须一次点击、不为画面简洁增加步骤；没有操作意义的提示不出现；产品负责人亲手试用的判断优先于审查打分。
- **吸收的已定事项**：D36（返回阈值）、D46 / D51 / D53（时刻与过渡）、D50 ⑦（声音与触觉）、D52（弹层出口）、D55（一次点击、不提示成功）、D56 ②（全 App 左缘右滑）、D57（A7、B1 / B3、减少动态效果 150ms）；Claude Design「时刻编排」`moments/moments.js` 的曲线与时刻上限；第三轮审查 I3 / A3 的交互与无障碍意见。
- **配套**：可视化版见 Claude Design「拾字设计系统 / 交互与动效规范.html」；现状不合规清单见 [交互规范-审计清单.md](交互规范-审计清单.md)。
- **规范的写法**：每条 = 规则 + 理由 + 取值 + 例外处理。**原则上没有例外**；确需例外的，必须登记在 §9 例外登记表并给出替代做法，未登记的偏离一律按缺陷处理。规则编号（N1、T2……）供审计、测试与 PR 引用。

## 0. 五条总则（记不住细则时，只记这五条）

1. **左上就是返回，左缘右滑就是点左上。**凡不是 Tab 根的画面，左上角都有一个返回元素；从屏幕左缘右滑与点它是同一件事、同一个结果、同一条动画路径。没有「这一步不能滑」。
2. **常用操作一次点击。**每组都会用到的操作不进菜单、不要二次确认、不藏在长按里。
3. **只有五种转场。**推入、纸展开（B1）、安静淡入（B3）、弹层、页内阶段切换。新页面只能从这五种里选，时长与曲线只能取 motion 令牌。
4. **反馈只在有用时出现。**成功不提示（状态变化本身就是反馈）；提示条只给失败与「可撤销」；触觉与声音只挂在一个看得见的画面事件上。
5. **任何设置下都完整可用。**减少动态效果、最大字号、读屏、色弱下，每一个操作都在、每一条路径都通，只是样子变了。

## 1. 导航模型

### N1 页面层级（只有这六类）

| 层 | 是什么 | 例 | 左上元素 | 进 / 出转场 |
|---|---|---|---|---|
| L0 Tab 根 | 底部 Tab 的三个根页 | 首页、字库、我的 | 无（不是返回目标的终点） | Tab 间：无动画直接切换（同 UITabBar） |
| L1 推入页 | 从任何页推入的内容页、设置页 | 字详情、练习记录、月字帖、年报、设置、备份、换库、全部字、关于及子页 | 「‹」 | T-push |
| L2 流程页 | 写字流程：写字页 → 结果页（结果页**替换**写字页，不叠在它上面）；结果页 →（推入）重写错字页，写完回到结果页（D66 ③） | 写字页（全部阶段）、结果页、没有要写的字页、重写错字页 | 写字页「‹」；结果页「×」；重写错字页「‹」 | T-paper（从首页进）/ T-push（从其他页点进）/ T-quiet（无来源按钮） |
| L3 弹层 | 底部弹层（Sheet）与居中确认框（Confirm） | 查字、排序筛选、外观、写字方式、分享预览、修改判断、清空确认 | 不在左上；弹层有自己的可见出口（§N4） | T-sheet / T-confirm |
| L4 浮条 | 不改变层级的临时条；外观是「浮起的浅面」，不得像按钮（§F3，D71 ③） | 撤销条、失败提示条、Toast | 无 | T-fade |
| L5 页内阶段 | 同一页面里状态的切换（不是新页面） | 写字页的回忆 / 看答案 / 描一遍 / 自己写 / 判断；结果页作品显现 | 仍是该页的左上元素，含义可随阶段变（§N3） | T-phase |

- **理由**：层级越少，「我在哪、怎么回去」越不用想。拾字只有一条主线（写字），其余都是「看」与「设置」。
- **规则**：新增画面必须先声明它属于哪一层；不允许出现第七类（例如「全屏弹出的推入页」「从底部推上来的整页」）。
- **阻断页**（数据损坏、版本过低，`screens/block`）是 L0 的替身：不画 Tab、不能返回，见 §9 E2。

### N2 左上返回元素：只有两种形态

| 形态 | 含义 | 何时用 | 读屏名称 |
|---|---|---|---|
| 「‹」 | **回到上一个状态**：上一层页面，或同一页的上一个阶段（唯一例外 D70 ①：结果页「再写一组」进入的写字页，回到首页，见 T0-6） | L1、L2 写字页的所有阶段 | 默认「返回」；回到页内上一阶段时用该阶段的动词（判断阶段「接着写」） |
| 「×」 | **这一段已经完成，关掉它**：上一个状态已不存在（被替换），回到来源 | 只用于 L2 结果页（写字页已被它替换） | 「关闭」 |

- **取值**：图标 22pt 框、44 × 44 点击区，图标描边外缘落在 20pt 页边线（`Page.js` `sz-page__ico--back` / `--close` 的负外边距）；写字页所有阶段的「‹」x 坐标完全相同（I3-03）。
- **理由**：「‹」与「×」在 iOS 里各有固定语义（返回 / 关闭）。拾字只有结果页一处真正「上一个状态已经没有了」，所以 × 只在那里。
- **规则**：
  - 左上不放文字按钮（「取消」「完成」「接着写」等文字）；页内阶段的回退也用「‹」，用读屏名称区分含义。
  - 左上元素**只做返回**：不得兼任保存、提交、切换。
  - 推入页一律「‹」，不因「看起来像弹出的」而用「×」（审计中字详情的「旧版本的记录」页、没有要写的字页即属此类）。

### N3 左缘右滑 = 点左上（全 App，无例外）

- **规则**：
  1. 凡是有左上返回元素的画面（L1、L2 的**每一个阶段**），左缘右滑都可用，且完成时执行的是**左上元素的同一个函数**（`ui/back-action.js` 登记），不是另写一套逻辑。
  2. 页面登记返回动作时，只能登记「函数」，不得登记 `null`（「这一层不能滑」）。`useBackAction(null)` 只允许出现在 L0 与阻断页。
  3. 返回动作分两类，手势画面不同、判定相同：
     - **出页**（离开这一页，`kind:'page'`）：跟手画面用该页进来时的那种转场倒放（推入页 = T-push 倒放；写字页 = T-paper / T-quiet / T-push 倒放，看它是怎么进来的）。
     - **页内回退**（回到同一页的上一阶段，`kind:'phase'`）：跟手画面用该阶段进来时的 T-phase 倒放（判断 → 回忆：上下两格的上格长回书写格、参考格淡出、题面不动），完成后停在上一阶段，页面不出栈。
  4. **判断阶段**：左上「‹」（读屏「接着写」），含义「回到刚才写字的状态」：书写格与墨原样回来，可继续写、撤销、清空；左缘右滑同义、同画面。**判断阶段不再禁用手势**（推翻 P270「判断阶段不能滑动返回」的门控，属 D56 ② 的本意）。
  5. **结果页**：「×」与右滑都执行 `leave`（先收起撤销条，再回来源）；来源是首页且写字页是从首页 B1 进来的时画面为 T-paper 倒放（纸缩回按钮），来源是练习记录 / 字详情时为 T-push 倒放。
  6. **弹层开着时**：左缘右滑作用在最上层弹层上，页面栈不动：弹层**随手指跟手**（位移、遮罩随位移变淡），**过阈值（同下「判定取值」）才关闭**，没过阈值回弹、弹层留在原处；关闭后结果与点遮罩一致（D58 补，与已实现的 IC-06 一致）。
  7. **书写中**：手指已在书写格里落笔时，左缘的第二根手指不触发（识别器 `maximumNumberOfTouches = 1`）；边缘起手后如有笔正在书写，丢弃这一笔（现行 `ink-canvas.js` 做法）。
- **判定取值**（已定 D36 / P270，进令牌 `gesture.*`）：起手区 屏幕左缘 0–20pt（原生系统边缘识别器 + 页边起手识别器；网页兜底 12px、页头以下）；方向判定 10pt；完成 = `v > 500pt/s` 或（位移 > 1/3 屏宽 且 `v > −200pt/s`）；否则回弹 200ms。
- **减少动态效果**：不跟手（页面不动），松手按同一阈值判定，完成后 150ms 淡化（`motion.duration.reduce`）。
- **读屏**：VoiceOver 两指 Z 形（`accessibilityPerformEscape`）与键盘 Esc **也等于点左上**：有弹层先关弹层，没有弹层就执行左上动作（现行只关弹层，见审计）。
- **理由**：同一个手势在不同页面有时灵有时不灵，用户就再也不会信任它（产品负责人原话「有些不灵、下半屏不行」「判断那一步也要能左滑返回」）。iOS 用户的肌肉记忆是「左缘右滑 = 返回上一步」，不区分「上一页」还是「上一状态」。

### N4 弹层的出口

- **规则**：每个弹层同时具备四个出口，结果相同：① 可见的「完成」（或决策弹层自己的「取消 / 先不 X」，D52）；② 点遮罩；③ 下滑关闭（跟手，阈值同 N3：位移 > 1/3 弹层高或 `v > 500pt/s`）；④ 左缘右滑 / 两指 Z 形 / Esc。
- **门控**：顶层是弹层时，左缘右滑永远可用（只关弹层），不看下面那一页能否返回、也不看是否在 Tab 根（现行 Tab 根上的弹层不能滑关）。
- **决策弹层**（修改判断、清空确认、结束这组）：没有默认项、焦点落在弹层本身（D03）；「取消类」在左、「确认类」在右。
- **弹层不叠弹层**：弹层里的操作需要再确认时，**就地换内容**（三段式也是就地换），不再开第二层。唯一例外是系统分享面板 / 相册权限（系统控件）。
- **理由**：弹层是「临时问一句」，出口越多越安心；叠层会让「关一下回到哪」变得不确定。

### N5 返回时的数据语义：返回永远不丢东西，也不问

- **规则**：
  1. **即时保存**：写字页抬笔 / 撤销 / 清空即存现场；设置项改了即生效；没有「保存」按钮，也没有「放弃更改？」的确认。
  2. 返回成功**不提示**（不出「已保存」，D55 ②）。
  3. 保存失败时：**不阻止返回**；回到来源页之前在原页就地给三段式（§S1），用户选「先不保存」才离开。
  4. 返回后回到**原滚动位置与原焦点**（被推入前点下的那个控件）；页面状态不重置。
  5. 冷启动恢复（P108）回到离开时的页面与阶段，左上元素与手势照常；**恢复不重演时刻**（不再落印、不再响 s1，I3-05）。
- **理由**：用户只需要知道一件事——随时可以走，回来还在。

### N6 Tab 栏

- 切换：无动画、无触觉；每个 Tab 记住自己的滚动位置。
- **再点当前 Tab**：滚回顶部（已在顶部时什么都不做）。不清空 Tab 上的推入栈（拾字的推入页都开在 Tab 根之上的全局栈里，切 Tab 前先返回到根）。
- 流程页（L2）与推入页（L1）上不显示 Tab 栏。

### N7 页面是固定的：整页不能被拖动（R6-J1，产品负责人 2026-10-12 真机反馈「年报……可以用手指移动整个页面，这在 App 里肯定不行」）

- **规则**：
  1. 每一页都是「固定页头 + 一个竖向内容滚动容器（+ 固定底栏 / Tab 栏）」。页头、底栏、Tab 栏永远不动；手指能拖动的**只有**内容滚动容器，而且**只竖向**。
  2. 内容滚动容器全 App 只有一种写法（`styles.js` `SCROLL_Y`：`overflow-x:hidden; overflow-y:auto; overscroll-behavior-x:none; overscroll-behavior-y:contain`）：页面正文 `.sz-page__body`、Tab 根面板 `.sz-tabroot__panel`、弹层 / 确认框 / 阻断页、查字的滚动区与底栏。不另写 `overflow:auto`，也不在容器里再套第二个竖向滚动层。
  3. 回弹（橡皮筋）只发生在内容滚动容器里、只在竖向：内容滚到顶 / 底再拖，正文在页头与底栏之间回弹，页头、底栏不跟着动；内容不够一屏的页面根本不能拖。
  4. 根文档永远是一屏：`html, body { height:100%; overflow:hidden; overscroll-behavior:none }`（`base.css`），没有横向溢出（`scrollWidth = 视口宽`），根文档的滚动位置永远是 (0, 0)（`root.js pinDocument`：系统把它挪了——键盘把输入框顶进可见区、读屏滚动——一帧内放回）。
  5. 原生壳：WKWebView 根 `scrollView` `isScrollEnabled = false`、`bounces = false`、`alwaysBounceVertical / Horizontal = false`、`contentInsetAdjustmentBehavior = .never`、不显示滚动条（`WebViewController.swift`）；页面里的内容滚动容器是 WebKit 另建的子 scrollView，不受影响。键盘弹起时不让 WebKit 顶起整页，弹层自己按 `visualViewport` 避让（查字弹层）。
  6. 横向滑动只属于两样东西：左缘右滑（N3，原生识别器 / 网页兜底起手带）与图片预览翻页（G1）；页面内容本身不能被横向拖动。
- **理由**：整页能被手指推来推去、松手弹回，是网页的手感；iOS App 的导航栏与 Tab 栏是钉住的，只有列表本身在动。
- **验证**：IC-22（e2e：每个页面根文档不可横向滚动、模拟触摸拖动后页头与 Tab 栏位置不变、根文档滚动位置为 0）；WebKit 探针「page does not pan」（§8d）。

## 2. 转场体系

### T0 只有五种转场 + 一种淡化

| 代号 | 名称 | 用在哪里 | 进 | 出 | 曲线 | 手势进度驱动 | 减少动态效果 |
|---|---|---|---|---|---|---|---|
| T-push | 推入 | L0 / L1 → L1 | 300ms 从右推入，下层视差 −30% | 300ms 反向；手势完成时按剩余距离缩短（≥150ms） | `ease.out` | 是（左缘右滑） | 150ms 交叉淡化 |
| T-paper | 纸展开 B1 | **只有从首页进入写字流程**（返回会回到首页那个入口）：从**被点元素的矩形**展开（首页主按钮「开始 / 继续 / 再写一组」、首页「接着写」；D62）。其他入口一律用 T-push（见 T0-6） | 420ms 被点元素长成整张纸 | 360ms 纸沿原路缩回被点元素；手势完成 300ms × 剩余 s（≥120ms）；取消 220ms | 进 `ease.paperOpen`、出 `ease.out` | 是 | 150ms 淡化 |
| T-quiet | 安静淡入 B3 | **只有屏上不存在来源元素**的写字流程入口：通知 / 提醒深链、冷启动恢复（D62 不变） | 220ms 下层先淡出、写字页从 0.96 放大淡入 | 180ms 反向 | `linear`（缩放 `ease.out`） | 是 | 150ms 淡化 |
| T-sheet / T-confirm | 弹层 | L3 | 弹层 280ms 自下而上；确认框 200ms 由 0.96 放大淡入；遮罩 200ms 淡入 | **必须有退场**：弹层 220ms 下滑、确认框 180ms 淡出、遮罩 180ms 淡出；**键盘开着时**弹层从此刻看得见的位置（被键盘抬高处）260ms 一路下滑出屏（`motion.role.sheetOutKeyboard`、`ease.out`，与键盘收起同一帧开始，T0-7） | 进 `ease.out`、出 `ease.in`（键盘开着时 `ease.out`） | 弹层：下滑跟手；确认框：否 | 150ms 淡化（进、出） |
| T-phase | 页内阶段切换 | L5（写字页阶段、换字） | 文字类先出后进（旧 0–75ms 淡出，新 75–150ms 淡入）；本人墨与书写格用 FLIP 纯缩放 200ms；框线背景同时淡化 150ms | 同一时间轴倒放（判断 → 回忆 280ms，`moments` 打断规则 3） | 淡化 `linear`、缩放 `ease.out` | 判断 → 回忆：是（N3-3） | 150ms 交叉淡化（**不是直接切换**） |
| T-fade | 淡化 | L4 浮条、页内小元素出现 / 消失（提示条、撤销条、说明位） | 150ms | 150ms | `linear` | 否 | 不变（淡化本身就是减少动态效果版本） |

- **规则**：
  1. 新页面、新状态**只能**从上表里选；需要新转场时先改本规范（加一行、给出令牌），再写代码。
  2. **每个进场都有对应的退场**（I2-09 / I18：现行弹层、确认框、Toast、撤销条只有入场）。
  3. **转场不能阻挡输入**：转场进行中点按 / 落笔，剩余动画一帧到终态，然后这次输入照常生效（`moments` 打断规则 1）。唯一允许的「可见的准备」是判断键（320ms 出现为 60%、440ms 变实可点）——它是看得见的，不是隐形锁；减少动态效果下判断键直接可点（不留看不见的 150ms 锁）。
  4. 页面进出与页内时刻**不得叠在一起播**：推入完成之前，新页面的时刻（作品显现、落印、提示显影）不开始。
  5. **同一件东西在过渡中始终是「一个」**：本人的墨、主按钮、页头元素不做两层同时半透明的交叉淡化（I3-02 / D53 ⑥）；内容不同的文字先出后进。
  6. **写字页转场按「回到哪里」定**（D62，产品负责人 2026-10-13 真机反馈；**覆盖 D57 / R6-J1 的 T0-6 原文「任何入口都 B1」**）：
     - **从首页进入**（首页主按钮「开始 / 继续 / 再写一组」、首页「接着写」——返回会回到首页的那个入口）：从**被点元素的矩形**展开成纸（B1），返回**沿同一路径**缩回该元素；
     - **其他所有入口**（字库「今日练习」行、区详情页「练这些字」、字详情「练这个字」、查字弹层「练这 N 个字」——即使弹层开在首页上、结果页「再写一组」、全部页「练这些字」，以及以后任何新入口）：**一律普通推入 T-push**——写字页从右推入，返回往右滑出回到上一页，左上「‹」与左缘右滑都可用，与进其他 L1 页**同一套**动画与手势（结果页「再写一组」是同一层换内容，新写字页同样从右推入盖在结果页上）；
     - **D70 ① 例外（「返回回到上一页」的唯一例外）**：从结果页「再写一组」进入的写字页，「‹」与左缘右滑**回到首页**（来源 tab 根），不回上一组的结果页——上一组已经结束，结果页被新写字页替换（不是被盖住）。动画仍是同一套横推（写字页往右滑出，露出首页），仍是同一个函数（`back-action` 登记的那一个），手势与点「‹」结果相同；除此之外任何入口的返回规则不变；
     - 判定写在 `paper-transition.js planPaper`：下层是 tab 根 `home` 且被点元素不在弹层（`role=dialog`）里才 B1，其余记成「普通推入进来的」，返回与左缘右滑都按横推；新入口**不得**自己登记来源或另写进出动画；
     - 来源由根组件统一记录（`root.js` 捕获阶段的 click → `paper-transition.js noteTap`：被点节点向上第一个 `button / [role=button] / a[href] / [data-paper-source]`），页面不各自登记；
     - 实心来源（主按钮）纸在元素大小时就是那个元素（同底色、同字）；透明来源（「接着写」文字按钮）纸在元素大小时透明、随展开淡入（`policy.paperTransition.veilTo`，P310），缩回时反向淡出；返回时被点元素还在下层页面里就重新量它的位置，已不在屏上就缩回它原来的位置并淡出；
     - 只有屏上不存在来源元素的入口（通知、冷启动恢复）用 B3（不变）；返回方式（点「‹」/ 左缘右滑 / 读屏两指 Z 形）效果完全相同（同一个函数、同一条进度 s）；
     - 减少动态效果：B1 / B3 / 普通推入各自按本规范的 150ms 淡化；
     - 验证：IC-23（首页入口：首帧矩形 = 被点元素矩形、返回末帧 = 被点元素当前矩形；其他入口：`data-nav-anim` 为 `push-slide` / `replace-slide`、写字页左边从屏宽走到 0、没有纸帧，返回为 `pop-slide`、从 0 走到屏宽）。
  7. **退场的性能与键盘编排**（R6-J1，产品负责人 2026-10-12「点其他区域弹窗会消失……但消失时有一个卡顿」）：
     - 所有弹层、确认框、提示条、键盘相关的退场都要 60fps：退场期间主线程不得有 > 50ms 的长任务（IC-24），不得有停住的帧（元素停在半路再突然消失）；
     - 键盘与弹层退场必须编排：关闭时弹层里的输入框**先同步失焦**（`Sheet.js useDialogFocus`），键盘在这一帧开始收起，弹层余影也在这一帧开始退场；弹层为避让键盘被抬高时，余影落回屏底、从此刻看得见的位置一路下滑出屏（`exit.js`，`motion.role.sheetOutKeyboard` 260ms ≈ 系统键盘 250ms，`ease.out`），不得带着「键盘高度」去播只够自身高度的下滑——那会停在半屏、等计时到点才消失（查字弹层的卡顿就是这样来的）；
     - 不允许两段动画打架：同一个元素同一时刻只有一条退场动画在动（余影用 Web Animations 覆盖 CSS 退场），键盘收起不再引起弹层重排或重渲染（弹层在关闭的同一帧已卸载）。
- **理由**：五种转场各对应一种空间关系——往深处走（推入）、展开一张纸（写字）、静静换场（没有来源）、临时问一句（弹层）、同一张纸上的状态变化（阶段）。用户从动画就能读出「我去了哪」，回去时沿原路返回。

### T1 页内时刻（不是转场，但同样受令牌约束）

时刻是页面内部为一个有意义的事件编排的短动画：判断键就绪、提示显影、看答案显影、描一遍笔顺快放、结果页作品显现与落印。

| 规则 | 取值 |
|---|---|
| 单个时刻上限 | ≤ 750ms（`motion.moment.max`）；结果页「归位成帖」≤ 1200ms（`motion.moment.resultMax`，阶段 2）；描一遍笔顺快放 ≤ 1600ms（`motion.moment.stepPlayMax`） |
| 可一点到底 | 任何点按 / 落笔让时刻一帧到终态，输入照常生效 |
| 只演一次 | 同一事件只演一次：冷启动恢复、返回再进、重新渲染不重演（I3-05）；描一遍笔顺每字只在第一次播（D46-17） |
| 触觉与声音同帧 | 触觉 / 声音挂在时刻里的某一帧（例：印着纸那一帧），不挂在动画结束回调上（I3-04） |
| 减少动态效果 | 直接终态或 150ms 淡化；触觉与声音照发 |

## 3. 按钮与操作层级

### B1 五种可点控件（不再有第六种）

| 种类 | 外观（设计系统 v1） | 尺寸 | 用途 |
|---|---|---|---|
| 主按钮 | 实心墨底、纸色字、黑 17/500、圆角 12 | 高 54；流程页满宽，首页 240 居中 | 这一屏「下一步」，每屏 ≤ 1 个 |
| 次按钮 | 透明底、1pt ink4 内描边、同字号 | 同主按钮 | **只**与主按钮成对出现在决策里（确认框「取消」、三段式「先不保存」不在此列——那是文字按钮） |
| 工具按钮（凹面） | field 色底、黑 17/500、图标在字前 | 高 48（AX 56），同一行等宽、间隔 12 | 写字页求助行（提示、看答案、自己写、下一个、再描一遍）：高频、次于主按钮（A7 / D57）。「下一个」的位置规则（R5M，审计 P2-24）：它不是这一步推荐的路径时（看答案、描一遍）固定在求助行右侧；它就是推荐路径时（自己写一遍：这张卡最后一步）升为主按钮，求助行右侧留空——同一个字的流程里，「下一个」只出现在这两个位置之一 |

### B2 位置规则

| 规则 | 取值 | 理由 |
|---|---|---|
| 主按钮底线 | 全 App 同一条：主按钮下沿 = 屏底 − max(24, 下安全区)（`Page` 底栏；写字页、结果页、备份页都是它，主按钮是底栏最后一个，同一底栏里的文字按钮放在主按钮正上方）；有 Tab 栏的根页 = Tab 栏上沿 − 24（R5M 由 20 改 24，与首页 `policy.mainButtonLine` 一致，03 P298） | 手指在每一页都落在同一高度（D53 ③） |
| 一屏主操作数 | 0 或 1 个主按钮；对等决策 2 个同级 | 一眼知道下一步 |
| 主按钮与相邻可点元素 | 视觉间距 ≥ 20pt；点击区不得重叠，间隔 ≥ 8pt | 误触距离（A7 求助行与主按钮 20） |
| 破坏性 / 跳过类操作 | 不与主按钮相邻：放页头右上或另一行的远端；与主按钮点击区距离 ≥ 44pt | 防「写好了」误点成「跳过 / 清空」 |
| 文字按钮行 | 左对齐 20pt 线起排；去处类行尾「›」 | D51 ⑥ |
| AX 档 | 同样的顺序与位置，放不下就折行（按词折），任何操作都不收起（D55 ①、P278） | 大字号用户同样一次点击 |

### B3 常用操作一次点击、菜单只给低频

- **常用操作清单**（任何字号、任何阶段都一次点击直达，不得进菜单、不得二次确认）：写好了、提示、看答案、跳过、撤销、清空、写对了 / 写错了、下一个、自己写、再描一遍、接着写（‹）、开始 / 继续 / 再写一组、返回、结果页「再写一组」、结果页「重写错字」（有写错的字才有，D66 ③）、对照 / 改判弹层「看这个字 ›」、保存图片、分享。
- **菜单（⋯ / 操作表）**：只允许装每组用不到一次的低频操作，且：① 菜单不是该操作的唯一入口时才可以用（例外：真正低频的整页操作，例如「删除这个字的记录」）；② 写字页、结果页不放菜单；③ 菜单弹层有标题（读屏名称，A3-07）。
- **二次确认**：只给**不可撤销且会丢掉用户东西**的操作（删除记录、替换备份、清空所有记录、结束这组时丢弃未判断的字）。能撤销的操作一律**不确认、给撤销**（跳过 → 撤销条；清空一格 → 撤销键）。
- **确认框写法**：标题说后果（「清空所有记录？」），正文一句说影响与能否撤销；按钮用动词「清空」/「先不清空」，不用「确定 / 取消」；确认类在右、不预选、不变红（D43：危险操作不再变色，靠文案）。
- **理由**：D55 原话「多了一个步骤……做的非常不好」。确认框的成本是每次都要多点一下，而撤销只在出错时才付出成本。

## 4. 手势

### G1 允许的手势（只有这八种）

| 手势 | 用途 | 位置 | 可见等价物（读屏 / 切换控制用） |
|---|---|---|---|
| 点按 | 一切操作 | 任何可点控件 | — |
| 左缘右滑 | 返回（= 点左上） | 屏幕左缘 0–20pt 起手，任意高度 | 左上「‹ / ×」 |
| 下滑 | 关闭底部弹层 | 弹层任意位置（内容已滚到顶时） | 「完成」/「取消」 |
| 纵向滚动 | 浏览 | 可滚动区域 | — |
| 书写 | 在书写格 / 描红格里写字 | 只在书写格内（格四周至少 20pt 页边）；原生写字页从页面空白处起手、滑进格的也算，从进入点开始（G3） | 「在纸上写」（设置 › 写字方式） |
| 横向翻页 | **只用于**图片预览的多页（分享 / 保存前的预览弹层）；翻页区左右各让出 20pt，不进入左缘起手区 | 预览区 | 「上一张 / 下一张」可见按钮或页码点可点 |
| 长按 | **只用于「叠看」**（判断阶段按住任一格，D46 ⑫，阶段 2），不教、不承载任何必需功能 | 判断两格 | 无需（叠看只看不评） |
| 读屏两指 Z 形 / Esc | 等于点左上（有弹层先关弹层） | — | 左上元素 |

- **不允许**：横向滑动切页面 / 切字 / 删除（左滑删除）、双击、捏合（图片预览除外：系统级缩放可保留）、摇一摇、任何只有手势没有按钮的功能。
- **理由**：每多一种手势，用户就多一种「不小心触发」的可能；隐藏手势对读屏与切换控制用户是新门槛（HIG Gestures、D34 拒绝「按住 0.5 秒看答案」）。

### G2 冲突优先级（从高到低）

1. 系统手势（屏底 Home 指示条、顶部通知中心）——永远让给系统。
2. 左缘右滑（起手 x ≤ 20pt、向右为主）——WKWebView 内滚动容器的平移识别器要求它先失败（P272）。
3. 书写——只在书写格内；书写格与屏幕左缘之间永远隔着 ≥ 20pt 页边，所以 2 与 3 不在同一位置竞争。落笔中边缘识别器不接受第二根手指。
4. 弹层下滑——弹层内容不在顶部时先滚动、到顶后再接管下滑。
5. 纵向滚动。
6. 点按——手指移动 > 10pt 即不再算点按。

### G3 书写区与系统手势边界

- 书写格任何边距离屏幕左右边 ≥ 20pt、距离屏底 Home 指示条区 ≥ 主按钮行高；书写格内不响应左缘右滑、不响应下滑。
- 书写格上方 / 下方的控件（工具行、求助行）不得盖住书写格（P280）。
- **格外起笔、滑进书写格（原生写字页，D72 ③）**：手指 / Apple Pencil 从页面空白处起手（不在任何按钮 / 可点控件上，也不在左缘返回起手区——系统左缘识别器的起手区 40.2pt 内，R10-A），滑进**可写**的书写格时，在**进入点**开始这一笔：进入点 = 轨迹与格边的交点，时间按前后两个采样插值；之后照常写，格外那段不画、不存。
  - 起手在按钮上：仍是按钮——滑走就是取消这次按下（系统按钮语义），不变成笔画；起手在左缘返回起手区：仍归左缘返回（N3），不出墨；返回识别成功时，已经开始的这一笔按中断丢弃（与格内起手被中断同语义）。
  - 这一笔与格内起手的笔同一套落笔规则：一次一笔（已在写时另一根手指滑进来不开第二笔）、Pencil 优先（Pencil 滑进来取消正在写的手指那笔）、手掌判定只在这块书写面用过 Pencil 后生效（D72 ①）、换字后 250ms 内进格的笔先持住到点补画（P227）；按钮的 0.4s 防误点照旧只管按钮。
  - 不生效：判断页等书写格不可写的阶段、书写格被弹层盖住时（进入点处命中的不是书写格）。
  - 起手在格内、写出格外（现状，不变）：这一笔不断，格外的点照常记进原始点（345 单位坐标可 < 0 或 > 345），画面只显示格内部分（书写面裁到格内）；滑回格内接着画；抬笔才结束。与网页 `ink-canvas.js`（setPointerCapture）同语义。
  - 网页写字页随 B2 切换退场，不改（网页书写面只收格内起手的 pointerdown）。

## 5. 反馈

### F1 触觉：五档，统一参数（与 `moments/moments.js` 触觉表同源）

| 令牌 | 原生 | 参数 | 用在（与画面事件同帧） |
|---|---|---|---|
| `haptic.judge` | `UIImpactFeedbackGenerator(.soft)` | intensity 0.7（D50 ⑦ 建议 0.6–0.7，阶段 2 真机调） | 判断落定「写对了 / 写错了」、修改判断成功（两种判断完全相同） |
| `haptic.seal` | `.rigid` | 0.8 | 结果页印着纸那一帧（全 App 只此一处） |
| `haptic.light` | `.light` | 0.5 | 「写好了」书写格开始收缩；看答案显影（阶段 2 改 soft 0.5）；结束这组确认 |
| `haptic.select` | `UISelectionFeedbackGenerator` | — | **推进与切换**：下一个、跳过、撤销跳过、进入描一遍、自己写、提示显影；（阶段 2）描到一笔、到达计数 |
| `haptic.none` | — | — | 书写、撤销一笔、清空（有撤销键兜底）、返回 / 推入 / 切 Tab、开关、单选、成功保存、失败、冷启动恢复 |

- **规则**：
  1. 判断、修改判断、撤销跳过等**会写记录**的操作：commit 成功后发；失败三段式不发触觉（失败不是用户的错，安静地说明即可），再试成功时补发。
  2. 不写记录的操作（写好了、提示、下一个、自己写）：随用户动作发，与该动作引起的第一帧画面变化同帧。
  3. 触觉必须对应一个**看得见的画面变化**；画面上没有变化就不震。一次用户动作 ≤ 1 次触觉（I2-03）。
  4. 触觉只属于写字流程（写字页、结果页）：字库、详情、「我的」、设置、备份、图片预览一律不发（那里没有「写字」这件事的节奏；撤销、换词、移除的反馈是画面本身）；系统控件（分享面板、时间轮）自带的触觉除外。
  5. 减少动态效果下触觉照发；系统关掉「系统触感反馈」时原生生成器自然静默。
- **现状差异**：判断现为 `.medium` 无强度、`undo / action / milestone` 三个旧档名、下一个 / 跳过 / 自己写无触觉——见审计。旧档名过渡：`stamp → judge`、`action / undo → light`（撤销跳过改 select）、`milestone` 删除。

### F2 声音：两个点位，不再增加

| 事件 | 素材 | 同帧 |
|---|---|---|
| 判断落定 / 修改判断 | j1「纸页落定」三变体轮换 | 与 `haptic.judge` 同帧 |
| 落印 | s1「木印·闷实」 | 与 `haptic.seal` 同帧，印着纸那一帧 |

- 书写、描红、按钮、返回、提示条一律无声；声音跟随「按键音」开关、遵守静音键、与音乐混音（D50 ⑦）。新增声音点位须改本规范。

### F3 提示条（Toast）与浮条

- **只在两种情况出现**：① **失败**，且失败发生的地方已经不在屏上（例：离开后才发现没存上）；② **可撤销**（撤销条）。
- **不出现**：成功（已保存、已复制、已存到相册、已换成……）、说明性提示（「下次接着写」）、引导。成功的反馈是状态本身：按钮变了、列表多了一行、页面回去了。
- 失败发生在当前屏上时，**就地**给三段式（§S1），不用提示条。
- 取值：最小高 48；无操作 `timing.toast`（3200ms）、带操作 `timing.toastWithAction`（5000ms）；不压主按钮（`toastBottom`）；进出 `T-fade`；`role=status` 播报。
- **外观：浮条不能像又一个主按钮**（D71 ③；Apple HIG：一屏只有一个突出的按钮）。实心深色填充只给每屏唯一的主按钮；L4 浮条（撤销条、失败提示条、Toast、顶部坏值提示）一律用「浮起的浅面」：
  - 面 `toast-bg`（= `elev`）+ 1px 细边 `toast-line`（= `line`）+ 轻阴影 `toast-shadow`；正文 `toast-fg`（= `ink1`）；
  - 操作（撤销 / 再试一次 / 先不保存）是文字按钮：`toast-act`（= `ink1`）、500 字重、无下划线，与 `ChangeLink` 等文字按钮同一写法，点击区 ≥ 44；
  - 圆角取容器档 `r-box`（24），最小高 48 时正好是胶囊；主 / 次按钮是 12 圆角（`r-ctl`）、满宽的实心墨或描边。**选更大一级圆角而不是另起胶囊令牌**：不新增圆角档，浮条与弹层同属「浮起的面」一档，两行说明时也不会变成怪异的长圆；
  - 倒计时细线保留：2px、`ink3`、40% 不透明；
  - 浅色 / 深色 / 各主题都必须与主按钮在颜色上分得开：`toastBg/btnBg` 对比度 ≥ 3（`tokens.json color.contrast.thresholds.toastVsPrimary`，`test/ui/contrast.test.mjs` 实算），原生逐屏对比的具名检查 L4-01 在网页参考与原生上都核对。
- **读屏补偿**：屏上看得见的状态变化，读屏可能感知不到——这类变化用视觉隐藏的 `aria-live=polite` 播报（例：「记下了：写对了」），不用可见的提示条。

### F4 加载与等待

| 等待时长 | 做法 |
|---|---|
| < `timing.loadingQuiet`（400ms） | 什么都不显示（不闪菊花）；按钮保持原样、不可重复触发 |
| 400ms – 2s | 就地：触发按钮变禁用并改为进行时文案（「正在生成…」），其余界面可用 |
| > 2s | 就地一行进度说明；可以取消的给「取消」文字按钮 |

- 不用全屏遮罩、不用居中菊花（系统分享面板与相册写入由系统负责）。

### F5 成功无需提示

- 成功 = 画面直接进入下一个状态。只有一个例外是「结果」本身（结果页、作品），那是内容不是提示。

## 6. 状态与出错

### S1 保存失败三段式（全 App 唯一写法）

1. **一句说明**：发生了什么 + 用户的东西是否还在（「没保存上，你写的字还在。」）。
2. **主按钮「再试一次」**：留在原位（替换原主按钮的文字，或在决策弹层里替换确认键）。
3. **文字按钮「先不保存 / 先不 X」**：放在主按钮上方的求助行 / 弹层的取消位。

- **位置**：失败发生在哪就在哪（写字页底栏、判断两键、弹层内容就地换），不新开弹层、不用提示条（除 F3 ①）。
- **不发触觉与声音**；读屏 `role=status` 播报第 1 句。
- 再试成功后**直接进入成功状态**，不提示「已保存」。

### S2 空状态

- 一句话说明这里将来会有什么 + 一个能让它变得不空的操作（没有就不放按钮）；不画插图、不讲「墨点」等内部概念（A3-06）；与有数据时同一页头、同一左上元素。

### S3 离线

- 拾字全部本地运行；**不出现任何离线提示**。只有依赖网络的地方（无）才需要；将来若加，按 S1 就地说明。

### S4 撤销窗口

| 场景 | 形式 | 寿命 |
|---|---|---|
| 跳过一个字 | 撤销条 | `timing.undoWindow` 5s；手指按住暂停；读屏 / 切换控制开启时不自动收起，到下一次操作（D36） |
| 清空一格 | 格下「撤销」键 | 到下一笔或换字 |
| 替换备份 / 清空所有记录 | 页内撤销条 | 离开这一页前（D24） |
| 撤销成功 | 撤销条换成「已撤销」 | `timing.undone` 2.4s |

- 撤销条不盖书写格、不盖主按钮（A3-05）；位置在格下说明位或主按钮上方，同一页里固定。
- **撤销窗口跟人走，不跟页走**：撤销条还在时离开这一页（点左上 / 右滑 / 写完进结果页），剩余的撤销机会交给目的页的撤销条接着显示（结果页已有 `handoffSkipUndo`；回首页同样交接）；不得无声丢失。

### S5 冷启动恢复

- 回到离开时的页面与阶段（P108 6 小时、未跨 0 点）；时刻不重演、不发触觉与声音；转场为 none。

## 7. 无障碍与系统设置

### A1 动态字体（含 AX1–AX5）

- 字号按层级分别放大（像系统 Text Style，D49），不统一乘系数；辅助字分层封顶（P243 / A3-03）。
- **不截断、不省略号、不缩小到看不清**：放不下就折行（按词折，A3-02）、就换版式（横排变竖排、并排变上下），最后才让正文滚动（写字页永不滚动，D51 ⑦：书写格到下限仍放不下时，书写格先低于下限、最小 180，再不行 AX 档题面整体按可用高度缩小、最多到 0.6，03 P299）。
- 页头、Tab 栏标签按系统行为（Tab 标签不放大，D49）；左上返回元素永远在、点击区永远 44。
- 任何字号下：常用操作（B3）全部可见、一次点击。

### A2 读屏

- 每个可点控件有名称：图标按钮名称 = 动作或去处（「返回」「关闭」「接着写」「撤销」「分享」）；去处类读「…，按钮」不读「›」。
- 推入后焦点落在新页标题；返回后焦点回到原控件；弹层打开焦点落在弹层本身、关闭后归还。
- 状态变化（判断记下、跳过、撤销、提示给出、笔数）用 `aria-live=polite` 播报，不抢焦点；不播报纯装饰动画。
- 两指 Z 形 = 点左上（N3）。
- 每个手势有可见等价物（G1）。

### A3 减少动态效果

- 规则见 T2 `reduceMotion`：位移、缩放、模糊、逐笔写出、笔顺快放全部换成 150ms 线性淡化；**不直接硬切**（硬切会让「发生了变化」不可察觉）；终态逐像素相同；触觉、声音照发。
- 全 App 只有一个减少动态效果时长：`motion.duration.reduce` 150ms（现行 120 / 150 / 直接切换三种并存，见审计）。

### A4 点击热区

- 所有可点元素点击区 ≥ 44 × 44pt（文字按钮、图标、开关行、列表行、字帖格、标签）；视觉小于 44 的用 `HIT_EXT` / `::after` 补足；相邻点击区不重叠。

### A5 色觉与对比

- 不靠颜色单独传达信息：写错 = 朱点（形状）+ 文字；提示 = 淡朱 + 起笔点与方向（阶段 2）；选中 = 实心图标 + 墨色。
- 「增强对比度」开启：令牌加深一档（A3-08）、淡朱加 1pt 描边（D46 ⑯）。

### A6 其它系统设置

- 「按键音」关：只关声音，触觉照发。静音键：声音静默。「降低透明度」：遮罩与弹层不透明（现已不透明）。粗体文本：随系统。

### 8d WebKit 版式门禁：`pnpm run verify:webkit-ax`（K2）

- Chromium 的 e2e 拦不住 WebKit 才出现的行盒 / 热区溢出（例：结果行「修改 ›」的点击区伸出按钮盒，WebKit 下按钮 `scrollWidth > clientWidth`、说明位 `scrollHeight` 多 2、正文区多出 2pt 可滚动量），所以写字页等版式改动要在 WKWebView 上量一遍。
- **覆盖四档字号**：L、XXXL、AX3、AX5（缺省 `SIZES=normal,xxxl,ax3,ax5`）× 三台评审模拟器（iPhone 17、SE 3、Pro Max）× 五个状态（write / answer / trace / judge / detail）；全部通过才算过。标准字号也要量，不能只量 AX 档。
- 断言：书写格等宽高、笔画比例不失真、文字不溢出视口 / 按钮（含 `scrollWidth ≤ clientWidth`）、文字不叠压、写字页正文不滚动、格下说明位在格下且在底栏之上、说明位内容不被裁。
- **整页不平移（N7，R6-J1）**：每个状态另量 `page does not pan`——根文档 `scrollWidth ≤ 视口宽`、`scrollHeight ≤ 视口高`，`scrollTo(40, 40)` 之后根文档仍在 (0, 0)、页头矩形不变，内容滚动容器横向不可滚（`scrollLeft` 写入后仍为 0）。
- 热区做法：视觉不足 44 的文字按钮要么把按钮盒做到 44 宽 / 高，要么让多出的部分只伸向上方 / 左右（不能伸向会被算进可滚动区的下方）。
- 跑前确认模拟器空闲；跑完恢复浅色外观与系统字号 L。
