## 1. 目标与边界

**逐判断笔迹存储（已决定 D27，阶段 1 P1-E3）**：`决定-D14` 原「另案暂停」，现由 `决定-D27` 覆盖——`features.perRecordInk=true`，立即开启，保留**每字第一次 + 最近一次**判断的墨迹，其余回收（§3.5、§9）；阶段 2 原生数据层后再升级为全部历次。开关仍在：关闭时全部页面按 10.12「有记录无笔迹」出货（F4 的 `…Glyph` 文案）。

**硬性约束**：
- 产品规则以 `决定-D01…D25` 与第十稿三份清单为准；未决项不能被代码默认值悄悄裁决——所有过渡默认值集中在 `src/config/policy.js`，每项带 P 编号，且必须在 [03-待产品决定](03-待产品决定.md) 有登记。

## 3. 数据模型（v2）

### 3.1 身份与顺序

- **卡片键** `cardKey`：`base:<字>`（题库字，可练）/ `custom:<字>`（库外字，仅可查看）。一字一卡。查询层提供 `practicable(cardKey)` 谓词，清单「练这些字」只选 `base:`。
- **记录 id** `r<序号>`、**会话 id** `s<序号>`：序号在启动时由 `max(records、sessions 中已用序号, meta.serial) + 1` 推导，`meta.serial` 只是缓存；id 允许空洞（跳过撤销会删记录）。
- **「最近一次」以 id 序号为准**；`at`（ms）与 `localDay` 只做展示与月归属（设备时钟改动、测试钩子 `setClock` 不破坏顺序不变式）。
- **日期**：`localDay = YYYY-MM-DD`（设备本地日，日界本地 0 点）；`at` ms。旧数据的 `dayKey` 按本地日导入。

### 3.2 记录（Record）与事件

```js
Record {
  id, cardKey, char, sessionId,
  kind: 'judged' | 'answer-seen' | 'skipped',   // 只有 judged 是「有效记录」（决定-D18/D23）
  judgment?: 'correct' | 'wrong',               // kind==='judged' 必填
  at, localDay,
  help: { hints: 0|1|2, answerSeen: bool, traced: bool },   // 帮助事实，永不因更正删除（决定-D07）；traced = 点过「描一遍」（进入描一遍阶段即置真，不看描红笔数）；answer-seen 记录不存墨迹
  corrections?: [{ from, at }],                 // 更正历史；更正不新增记录（决定-D19）
  inkId?: string,                               // 指向 ink 表；缺失 = 有记录无笔迹（10.12）
  legacy?: true,                                // 由 v1 数据合成（§12），无 fsrsBefore、无更正能力
  source?: 'screen' | 'paper'                   // 阶段 1 P1-E8：书写方式；缺省 = screen（旧数据不带、不迁移重写，读取时按 screen）；paper 只用于 judged、不带 inkId
}
```

规则：
- 文档与代码中的「记录」若未加限定，一律指 `kind==='judged'`；选字、清单、统计、首页 N 都只看 judged。
- 「写错过」= 某字最近一次 judged 的 judgment 为 wrong（K15）；「快忘了」= 最近一次 judged 为 correct 且 FSRS 到期（§5），两单互斥（K16）。更正为对同样离开写错过（I02）。
- 「今天记录了 N 个字」= 今天 judged 按字去重；首页墨迹行取最近 8 条 judged（按 id），数字仍 N（决定-D12）。
- 首页呈现（阶段 1 P1-E5，03 P155 / P156，设计稿「首练与首页」）：「今天记录了 N 个字」的说法改为「今天写了 N 个字」；首页按 `today.js homeViewOf` 分五态加首次打开——进行中的组（格子）> 首次打开 > 大写数字特别组 > 今天写过 > 离开 ≥7 天回来 > 今天还没写；首页不画朱点（D46 ①）；「昨天写的字」一行只放有本人墨迹的字；「字库里有 N 个字」N = 有过判断记录的字数。光影层取消（03 P143）。
- 更正（决定-D19）：只改 `judgment`、追加 `corrections`，`at/localDay/id` 不变；只对**本会话结果页仍可见**的记录开放（`Session.items[].fsrsBefore` 存在），看过答案/跳过不可改判（K25）。
- 跳过撤销（走查-W16）：跳过时立即 commit 一条 `skipped` 记录并推进；3 s 内撤销 = 再 commit 一次：删除该记录、字放回 cursor、current 回到 recall；提示随刷新/换页失效。
- `skipped` 只用于会话内排除、结果页列举与统计，不影响后续选字（决定表：不自行选当前组/长期排除）。
- **纸上记录（阶段 1 P1-E8，D46 ⑬ / D47，03 P165–P169）**：「在纸上写，回来自判」的判断记 `source:'paper'`、没有墨迹（ink = null，不写 `inkId`、不写 ink 月键）。它是有效记录——判断、FSRS、写错过 / 快忘了、字库字数、今天写了 N 个字、字墙（新旧档与朱点，不加标注）照常；凡是画「本人笔迹」的地方都没有它：结果页作品、这次 / 这天的图片、月字帖、年报，以及年报与月份的字数都只收 `core/records.js isWorkRecord`（= judged 且不在纸上；时间段视图先 `withoutPaper` 再交给 `core/ink-pick.js`，段内只有纸上记录的字不出现、不画衬底、不计数）。D27 留墨：纸上那次不占「第一次 / 最近一次」——`store/budget.js indexRecords` 另记屏幕上写的第一次 / 最近一次一起留，纸上判断不会让之前留墨的最近一次变成中间那次被回收。单字详情：纸上记录不占笔迹格，记录列表另起一行「{日期}　写对 · 纸上」（读屏「…，写对，纸上」）。旧记录与 v1 迁移、备份 v2 信封、保护副本都不带 `source`，按 screen 读，无需迁移。

### 3.3 会话（Session）

两个槽位（决定-D05）：`A` = `first` / `daily`；`B` = `picked`（这次选的字）。另有 `lastEnded[slot]` 保留最近结束的会话供结果页、来源行、离开按钮只读。

```js
Session {
  id, slot: 'A'|'B', kind: 'first'|'daily'|'picked',
  source: { view, char? },                      // 结束后回到来源（S05/R-R06）
  queue: [cardKey], cursor,
  items: [{ cardKey, recordId?, kind, fsrsBefore?: CompactCard }],   // fsrsBefore 只活在会话里，供本会话更正重放
  current: { phase: 'recall'|'compare'|'answer'|'trace'|'retrace', strokes:[[…]], hints, answerSeen, hintRange, referenceReady, paper? },
                                                // paper?（阶段 1 P1-E8）：只对这一个字切换写字方式（true 纸上 / false 屏幕，缺省跟 settings.writeMode）；进纸上判断页时写 true
  lastLine: { recordId, kind:'record'|'changed'|'saw' } | null,
  startedAt, startedDay, updatedAt, endedAt?, endedEarly?
}
```

- 状态机：`recall → (提示 ≤2) → compare → 判断 → 下一字`；`recall → 看答案确认 → answer → trace → retrace → 下一字`；`recall → 跳过 → 下一字`；任何阶段返回 = 保存现场；`picked` 可「结束这组」。最后一字处理完直接进结果页（决定-D20）。
- 恢复幂等：records 里已有 `sessionId===当前 && cardKey===当前字` 的 judged 记录时，恢复不再进 compare，而是补写 items、推进 cursor（D07 不重复计数）。`phase==='compare'` 且笔画为空时回退 recall（`current.paper===true` 的纸上判断页除外，阶段 1 P1-E8）。
- daily 跨天：首页读取时 `startedDay !== 今天` 即过期——已判断的保留，没写的按 D22 口径不算记录也不算跳过；自动结束、不进结果页（P37）。
- S02「结束那组，开新的」= 一次 commit：旧 B 置 `endedEarly/endedAt` 移入 `lastEnded.B` + 建新 B；过渡默认不进旧 B 结果页，有判断时轻提示（P38）。
- 结束时会话移到 `lastEnded[slot]`；下次开同槽或离开结果页后清掉；停在结果页刷新时由 lastEnded 恢复。

### 3.4 调度状态

```js
sched[cardKey] = { fsrs: CompactCard, due: 'YYYY-MM-DD'|null, lastJudgedAt, stoppedAt? }
```
`stoppedAt`（长期排除）本轮不写入（P06）。不变式：`sched[key]` 存在 ⇒ 该字至少有一条 judged Record（迁移保证，§12）。

### 3.5 其余域

- `custom`: `{ added: [{char, at}] }`（自选的字；加入需明确点「加入」，决定-D21；是否进每日安排见 P33，过渡默认不进）。
- `wordOff`: `{ [cardKey]: at }`（「换掉这个词语」停用当前语境、改释义题面，可撤销）。
- `photos`: `{ [char]: {day, at, dataURL} }`（旧拍字照片，只读；≤64KiB/张、≤30 张、≤420KiB，超预算按最旧淘汰；不生成记录，不进图片；是否算「有记录」见 P10b，默认不算）。
- `settings`: `{ library, sound, remind:{enabled, hour, minute, permission}, large, appearance:'auto'|'light'|'dark', remindInvite?:{shown, last, answered?:'yes'|'no'|'denied'}, capitalDeferredDay?:'YYYY-MM-DD', writeMode?:'screen'|'paper', paperSuggested?:true }`（`writeMode` = 设置 › 写字方式，缺省 screen，`paperSuggested` = 读屏开启时「改为在纸上写」的建议已出现过，阶段 1 P1-E8、03 P165 / P168；背景音随 P07 不存；`remindInvite` = 首练结果页提醒邀请的计次与回应，阶段 1 P1-E5、03 P157；`capitalDeferredDay` = 点了「这次先写平常的字」的那一天，03 P158）。
- `backupMeta`: `{ lastExportAt, lastExportSig, lastConclusion?: {kind, date, count} }`（K02 状态句；结论句刷新后仍显示）。

## 4. 存储与事务

- `storage.js`：`read(key)`、`writeAll(entries, {label})`：① 先写 `shizi.v2.txn = {label, at, keys, prev:{key: 原值|null}}`；② 按固定顺序写数据键（ink → records → sched → custom/… → meta → **sessions 最后**，因为它决定恢复阶段）；③ 逐键读回比对；④ 成功删 txn。任一步失败：用 prev 回滚（prev 为 null 的键 `removeItem`），回滚失败则把已写键搬到 `shizi.corrupt.*`（txn 复制一份作证据、**活的 txn 保留**，下次启动 `repair()` 据此自动恢复旧值）、进入 R-B09 阻断页并提供导出入口。峰值占用 = 当前占用 + 被改键旧值之和，所以大域一律分键（records/ink 按月），不分键的 sched 以 1000 字 ≈ 500KB 为上限计入 §9 预算。 **唯一的免事务写入** `storage.writeOne(key, value)`：只用于撞配额后把旧 ink 月键替换为其淘汰后的子集（单次 `setItem` 本身原子；值必须是原值的子集且更小；不用于任何其他域）——因为此时连 txn 的旧值副本都写不下；写完立即发布到内存，再重试原提交一次。**审查整改 F1 增加第二个免事务写入** `storage.writeRoute(raw)`（阻断页期间调用方不写）：只写路由提示键 `shizi.v2.route`（API 写死这个键，`writeAll` 拒绝它）。理由：它不是业务数据（不在 store 状态、不进备份、丢了只是「不恢复、落首页」），单次 `setItem` 原子、新旧值都合法，故不写 txn、不读回回滚、不阻断、不做预算回收，失败静默；若走 `store.commit`，每次导航都会多写一份 txn 旧值并通知全部 store 订阅者重渲染，撞配额时还会为了一个导航提示去折叠旧月份。它在 `writeAll` 之外，不改变「sessions 最后写」的提交顺序，也不会进 `txn.keys`——启动 `repair()` 回滚半写提交时路由提示保持离开时的值，由 `route-memory` 按修复后的状态再判能不能恢复（例如判断 commit 中断回滚后仍回到判断页，D07）。故障注入：不计入 `interruptAfterWrite` 次数（halted 后照样拒写），`failNextWrite` 只在 `matchKey` 明确指向它时命中。`repair()` 遇到坏的路由提示直接删除（`report.dropped`），不隔离、不触发坏值提示。启动时若存在 txn 即先回滚再做形状校验（进程被杀时的半写修复）。
- 配额：`QuotaExceededError` 单独分类；commit 撞配额时先按 §9 预算回收一次再重试，仍失败才进保存失败三段式并建议导出。启动时估算总占用，>80% 在备份页与首页状态句预警。
- `store.js`：`commit(label, mutate) → {ok, error}`。按域浅拷贝（copy-on-write）→ `mutate(draft)` → 形状校验 → 计算脏键 → `writeAll` → 成功才替换内存状态并通知订阅者。UI 只在 `ok` 后推进。
- **写入点 × 失败表现**（D07 全覆盖）：

| 写入点 | 失败表现 | 文案 |
|---|---|---|
| 判断 commit | 留在判断页，三段式 | C017「没保存上，你写的字还在。」 |
| 看答案确认 | 留在确认框，不进看答案页；事件不重复 | C017 类 |
| 跳过 / 跳过撤销 | 不推进，三段式 | T01 |
| 修改判断 | 弹层内三段式，记录与 FSRS 不变 | C034 |
| 加入自选 / 移除撤销 | 三段式 | C150 / C125 |
| 换库 | 就地重试 | C063 |
| 结束这组 | 留在写字页，重试成功后结束（D22） | 10.10 |
| 设置、wordOff | 三段式 | C125 |
| 抬笔写 sessions | **不阻断书写**：笔迹留内存，下次抬笔或 `visibilitychange` 重写；顶部一次性提示（按配额/通用两句）；到判断 commit 由三段式兜底（P52） | 沿旧两句 |
| 迁移 | 单次 writeAll，失败回滚且不写 `v2.meta`，展示 R-B09 迁移变体并建议导出旧数据，下次启动重试 | R-B09 |
| 保护副本 | 不替换（R-B04） | C205 |

- 启动：逐键形状校验（单一形状表 `schema.js`）；坏值搬到 `shizi.corrupt.<key>` 并顶部提示一次；存储不可用 → 「现在存不了记录」阻断页（R-B09），不允许写字。

## 5. 调度与选字

- FSRS：ts-fsrs 5.2.0 / FSRS-6，`request_retention 0.90`、`maximum_interval 365`、`enable_fuzz true`。评级（阶段 1 P1-E4，已决定 D41）：写错 → Again；写对 → Good，但**新字第一次判断就写对（无提示）→ Easy**（`policy.ratingFirstCorrect`，P127，初始稳定度约 8 天，不是 2 天）、**热身字写对（无提示）→ Easy**（`policy.warmup.easyOnCorrect`，P126）。**带提示的写对一律按 P34**（`policy.ratingWithHint='Good'`，首次写对带提示时也不升 Easy；记录里 `help.hints` 照实保存）。「第一次判断」= 该字的卡还没被评过级（`reps = 0`），所以结果页更正重放（`replay`）与首次判断同口径：首判写错后改为写对，重放得到的是 Easy。看过答案、跳过不评级、不改 `due`；看过答案当天是否再排进 daily 见 P36（过渡：可再出）。
- Again 后直接采用 FSRS 返回的 due（至少次日），不再悬置。
- 判断前把当前卡存到 `Session.items[i].fsrsBefore`；更正时以每条记录的 `at` 为 review 时间从 `fsrsBefore` 重放本会话此字后续记录（ts-fsrs 默认 seed 由 review_time 与卡状态决定，重放确定）。会话结束后不再更正。
- **今天的练习（daily）**（阶段 1 P1-E4，已决定 D41「保底一新 + 积压阀」、D28、D40；实现 `core/mix.js` + `core/sessions.js selectDaily`，参考实现 `phase1/tools/simulate-mix.mjs`，`test/core/mix.test.mjs` 逐项对照）：
  - **到期字**（`due ≤ 今天`）按逾期天数降序、稳定度升序；**新字**按「易忘度」顺序（D28，数据 `src/config/char-order.js`，由 `scripts/build_char_order.mjs` 从易忘度字表初稿生成；清单外的字排在清单之后按 SEED 字频序；姓氏 / 省份简称 / 常见地名（D39，独立主题）与大写数字（D40，特别组）不进默认排序）。排除**今天已有 judged 记录**的字（「刚写过的字当天不再出」，交接备注十.5）；`skipped` 只在本会话排除；自选未写字不进 daily（P33）。组大小 `policy.groupSize`（5，P03）。无可练字 → R-H11。
  - **配比（P125，`policy.groupMix`）**：积压天数 `p = 到期未写数 ÷（4 × 近 7 天平均每天组数，至少 1）`。新字目标：`p ≥ 4`（积压阀）→ 上一组有新字则 0、否则 1；`p ≥ 1.5` → 1；`p < 0.5` 且最近 10 个新字首次判断的写对率 ≥ 0.6 → 3；其余 2（写对率用先验 0.5、权重 2 平滑）。
  - 复习位 = `min(到期数, 5 − 新字目标, 今日复习预算)`；新字最多 3 个；到期不够时用**最快到期的字提前复习补位**（热身字不提前；**不计入**每日上限），仍不足才补第 4、5 个新字（首练后的第一组因此是 1 热身 + 4 新）。
  - 「上一组」= id 最大的判断所在的会话；**离开 ≥ 7 天回来的第一组**（今天还没有判断）把「上一组有新字」当作 false，积压阀照常给 1 个新字。「组」= 有判断的会话（旧数据迁移来的记录没有会话，按「那一天 1 组」算）。全部输入从 `records` / `sched` 推出（`practiceStats`），不新增存储。
  - **每日复习上限（P03）** `policy.dailyReviewCap`（30）降为保险：每组复习最多 5 个，一天写 7 组以上才会碰到；记账 = 今天已写的复习字数减去「写的时候还没到期」的提前复习（用该字记录重放判断，重放结果与现在的 `sched.due` 对不上时保守地计入）。
  - **热身字（P126，`policy.warmup`）**：每组至多 1 个（新热身字或热身字复习二选一）、放组首；只在**首练后 7 天内**（首练当天算第 1 天）或**最近 10 次判断写对率 < 0.6** 时放，占一个新字位（新字位 ≥ 2 时）；热身字写对记 Easy。

### 6.3 渲染与指针

## 7. 导航与页面

- `router.js` 以 **history 为唯一真相源**：`push()` 只 `pushState({depth, name, params})`；UI 返回按钮调用 `history.back()`；页面栈与遮罩栈的变化都在 `popstate` 处理器中按 depth 差执行。各屏 `registerScreen(name, component)` 自注册，无中心路由表。tab 根页 `replaceState`；`back()` 先关最上层遮罩。
- 转场：推入 300ms `cubic-bezier(.2,.7,.2,1)` 带左投影，返回反向；减少动态效果 120ms 交叉淡化。iOS 主屏 PWA（`display-mode: standalone`）下 popstate 引发的返回跳过自定义转场，避免与系统快照动画叠加。
- **左缘右滑返回（R-G01）在单 WKWebView 下的含义**：Web 页面栈 + 原生识别器驱动的跟手转场，属工程近似（P54）。手势唯一所有者是 Swift 的 `UIScreenEdgePanGestureRecognizer`：在 `.began/.changed/.ended/.cancelled` 派发 `shizi-native-back-progress {phase, translationX, progress, velocityX}`，达到阈值时派发 `shizi-native-back`；JS 只按事件渲染，不自行监听左缘 pointer；M6-5 实现：began 时遮罩开着先关遮罩，否则冻结底层并跟手（底层视差 0.3），ended 按 `v > 500 || (x > 50% 宽 && v > -200)`（D36）自行提交 `back` 并在 600ms 内吞掉紧随的 `shizi-native-back`（旧壳或丢事件时仍按一层返回），减少动态效果只提交不跟随（P103）。JS 通过 `postMessage({type:'backGestureEnabled', value})` 告知原生（实现：root 只在「页深度（不含遮罩）、阻断」变化时发；写字页以 `ownsBackGesture` 注册，在顶层时由它发 false、离开顶层/卸载时发回栈值；tab 根为 false，即使根上开着弹层也保持 false——M5 修复回合 K1）「写字页已挂载（整页期间为 false，不是只在落笔期间——M0-7 发现落指即拖的时序无法保证）/ 当前页不可返回（tab 根页、阻断页）」，Swift 在 `gestureRecognizerShouldBegin` 拒绝识别，避免靠左起笔被吞；写字页的返回走页头按钮。事件名以 `shizi-native-back-progress` 为准（M0-4 暂时兼容 `shizi-native-progress` 别名，M5-3 删除）。PWA 下的返回靠 popstate 兜底。
- **冷启动恢复（审查整改 F1，R-W13 / P32 / P108）**：同一页面内刷新从 `history.state` 恢复；但 App 进程被杀后 WKWebView 是全新会话（主屏 PWA、新标签页同理），`history.state` 为空。为此 `ui/route-memory.js` 把页面栈（只含页面，截到第一个遮罩为止——遮罩组件只活在内存里；`{n, p}` 与 history.state 同一份）写进 `shizi.v2.route`：挂载后写一次，之后页面栈或参数每变一次写一次（遮罩开关不写），`visibilitychange(hidden)` 与 `pagehide` 时刷新离开时刻 `at`。`router.start()` 发现 `history.state` 不是本模块写的时调用 `coldStart()`，按下列顺序判定，**任何一条不满足都整栈不恢复、落默认 tab 根（首页）**：① `policy.routeRestore.enabled`；② 阻断页优先（存储不可用 / 回滚失败 / 迁移失败）；③ 坏数据优先（本次启动隔离了坏值、要出顶部提示）；④ 提醒深链优先（桥上排着 `shiziOpenReminderTarget`）；⑤ 未过期（P108：离开不超过 `maxAgeMinutes`，过渡 360；`crossDay=false` 时跨本地 0 点不恢复）；⑥ 逐页有效性：写字页要该槽还有能续写的组（`resumableSession`，跨天作废的 daily 与写完的组不算）、结果页要 `lastEnded[slot]`（或槽里）还是那组、单字详情要这个字还在（题库 / 自选 / 有记录 / 旧照片）、旧照片页要照片还在、「现在没有要写的字」页不恢复；第一项必须是 tab 根、其余必须是已注册子页。通过后 router 用 `replaceState`（depth 0）+ 逐层 `pushState` 重建 history 条目（返回键照常按层退回），转场 `{kind:'none', cause:'restore', cold:true}`。写字页按 `sessions[slot].current` 的阶段与笔画自行恢复（§6；笔画抬笔即写、切后台再写，P52），所以回忆 / 判断 / 看答案 / 描一遍 / 自己写的阶段、笔迹与参考字形都在；备份页按 `cause:'restore'` 恢复撤销底栏（§9 P32）。**深链压过恢复**：iOS 冷启动时原生等 `pageReady` 才派发提醒深链，此时栈可能已恢复——`reminder.js` 经 `route-memory.runDeepLink` 执行：本次是冷恢复且用户还没动过（没导航、没切后台）→ 先 `switchTab(默认 tab)` 静默退回首页，`router.whenIdle` 等 history 落定后再开 B 组；否则直接叠在当前页上（热启动行为不变）。同页刷新从不读路由提示。
- 可访问性：所有可点控件用 `<button>`；禁用 `disabled + aria-disabled`；弹层 `role=dialog aria-modal` + 焦点陷阱 + 焦点归还；tab `role=tablist`；轻提示 `aria-live`。

## 9. 容量、保留与保护副本

**按键字节预算（UTF-16 估算，目标合计 ≤ 3.2MiB，对 5MiB 留 35% 余量）**

| 键 | 估算 | 预算/策略 |
|---|---|---|
| meta/settings/custom/wordOff/backupMeta/legacy | < 50KB | — |
| sched | ≈250 字符 × 练过字数（300 字 ≈ 150KB，1000 字 ≈ 500KB） | — |
| records（按月分键） | 单条 ≈ 225 字符（无 fsrsBefore） | 总预算 `policy.recordsBudgetBytes`（过渡 1.5MiB ≈ 3300 条）；超预算或超 400 天先到者触发最旧月份折叠为 `{month, byDay, chars}` |
| ink | v3 打包 + 自适应抽点（P121）后 12 画以上的字 ≈ 1.7KB / 条；300 字 × 2 份 ≈ 0.6–1.0MiB（阶段 1 P1-E3 实测） | `policy.inkBudgetBytes`（P05，1.5MiB）；**D27（阶段 1 P1-E3）**：每字第一次 judged 与每字最近一次 judged **永不回收**；先回收既非首次也非最近的：孤儿 → 其他月份的其余 → 本月其余 → 每月每字首/末条（P02） → 按时间（同层先旧）。原「每字第一条 judged（年报）可淘汰」一层取消 |
| sessions | < 100KB（strokes 抬笔写） | 结束移入 lastEnded |
| route（审查整改 F1） | < 1KB（页面栈通常 ≤ 4 层；编码后 > 8192 字符不写） | 单键覆盖，不进 txn |
| photos | ≤ 420KiB | 旧上限沿用 |
| v1 旧键（回退窗口内） | 实测 ≤ 1MB（导入后即删 session/safety 大键） | P53 |

- 被淘汰 / 回收墨迹的记录显示「没有笔迹」（10.12），不借别次墨迹（I03）。D27 下中间那次在写入下一次判断时就回收（§3.5），所以按时间段取「某一次」的页面（月字帖 P02 本月第一次、这次 / 这天的图片、年报首字）若只取偏好方向上的那一条，在旧月份常取到已回收的那次。**已决定 D42（解 P122）**：这类页面在该时间段内按原取法的偏好顺序（取第一次的从早到晚、取最后一次的从晚到早）找**留有墨迹**的那一次（共用纯函数 `core/ink-pick.js` `pickRecordInPeriod`，判「有没有墨迹」只做按月墨迹表的一次查找、不解码），时间段内一份都没有才如实显示「没有笔迹」；角标 / 说明行的日期随挑出的那一次，不拿时间段外的墨迹冒充（I03）。单字手写图片、字库墙、清单小图等本来取「最近一次」的地方不属于时间段视图，口径不变。
- 容量监测沿用 §4 / P57：占用 > 80% 假定配额时备份页与首页状态句预警，撞配额时按上表回收后重试一次、仍失败走保存失败三段式并建议导出；不新增文案。300 字两份 ≤ 1.2MiB 时常规提交不触发墨迹回收（61-perf 断言预算回收零淘汰）。
- 折叠月份形状：`{folded:true, month, byDay:{localDay:[char]}, chars:[char], kept:Record[]}`，`kept` 保留该月里仍是某字最新 judged 记录、或某字第一次 judged 记录（D27，阶段 1 P1-E3：首次的墨迹随记录留下）的条目（写错过/快忘了与 D23 口径不受折叠影响）。
- 占用预警阈值与假定配额为 policy 项（P57）；测试钩子 `failNextWrite(1,{kind:'quota'})` 会被「回收后重试一次」吸收，要稳定制造配额失败用 `n≥2` 或 `kind:'generic'`（M4-4 的保护副本失败注入按此写）。
- **保护副本（R12 / 10.14 / O04）**：替换或清空前先写单键 `shizi.v2.safety = {version, kind:'restore'|'clear', createdAt, backupDate, count, payload}`（v2 业务键 + 当时的 `sessions`，不含 v1 键；替换/清空同时把 A/B 置空、保留 lastEnded——P79，撤销时连会话一起还原）。保护副本与撤销经 `store.commit(label, mutate, {reclaim:false, replace:true})`：撞配额直接失败、不回收，避免在告诉用户「记录没有变」的同时折叠旧月份。写后读回核对；失败（含配额）→ 不替换，R-B04「没能换成备份，你现在的记录没有变。可以再试一次。」；成功后 `writeAll` 目标数据（失败回滚并删 safety）→ 撤销底栏。撤销 = 用 payload 原样 `writeAll`（不再规范化，避免记录数变化），失败按 R-B05，副本保留可再点。删除副本：路由离开备份页、撤销成功、下一次替换开始前；离开时写 `backupMeta.lastConclusion` 供结论句。启动时发现残留副本（进程被杀后重载）按 P32 处理（过渡：仍在备份页则恢复撤销底栏）——同页刷新由 history.state、进程被杀后的冷启动由路由提示（§7，审查整改 F1）把备份页恢复出来，转场 `cause:'restore'` 时恢复撤销底栏；从别处重新推入备份页时遗留副本视为过期、删掉；冷启动未恢复（过期 / 深链 / 阻断）时副本留到下次进入备份页再删。内存缓存同一份快照只为加速。

## 12. 迁移（v1 → v2）

首次启动检测到 `shizi.memory.v1` 且无 `shizi.v2.meta` 时执行一次（v1 备份文件导入走同一转换）。单次 `writeAll` 写全部 v2 键，最后写 `meta`；失败回滚不写 meta（§4）。

- FSRS：`memory[key].fsrsCard` → `sched[key].fsrs`；`dueDay` → `due`；`pendingLearning` 的字 `due = 明天`。
- 记录（`fsrsReviewLog.events`，≤120 天）：`Good` → judged correct（`help.hints = hintCount`，`traced`）；`Again & reason wrong` → judged wrong；`Again & reason dontKnow` → answer-seen；`Again & reason hinted && hintCount===0` → 旧「不太确定」，**不生成 judged**，只计入 `legacy.days` 与导入报告；`Again & reason hinted && hintCount>0` → 旧日志无法区分「用提示写对」与「用提示后不太确定」，过渡按 P35 处理（默认不生成 judged，保留帮助事实与练习日）。
- **有 memory 无事件的字**（`seen>0` 且 120 天内无事件）：用 `memory.lastOutcome/last/lastHints/traced/misses` 合成一条 `legacy:true` 记录（fast/slow → judged correct/wrong；miss → answer-seen；hinted 按 P35），保证 `sched` 存在 ⇒ 有 judged 记录（备选方案见 P35）。
- 墨迹：`recentInk.strokes` → 该字最近一次 correct 记录的 `ink`（仅 `perRecordInk` 开启时；D27 起默认开启，迁移不做留存回收，那条墨迹若既非首次也非最近，在这个字下次判断时按 §3.5 回收）。
- `wild.captures` → `photos`（沿旧预算）；`wishes`、OCR 链不迁。`added` → `custom.added`；`quality.badWord/hide` → `wordOff`；`library`（旧 id 映射沿用）；`sound.enabled` → `settings.sound`，`sound.scene` 丢弃（#166）；`reminder` → `settings.remind`（保留 permission）；`fontScale` → `settings.large`；`backupMeta.lastExportAt` 保留。
- 不迁：opens/streak、funnel 旧事件、tuning、quality 其余、session v3。
- `activity.practiceDays` → `legacy.days`（练习记录日历显示）。导入报告（各类条数、丢弃数、照片淘汰数）写入 `legacy.report` 与 funnel。旧键处理见 §3.6。

## 13. 性能与兼容目标

- 首屏：`index.html` + `app.js` 依赖树 < 150KB（不含 deck 与字体）；deck `defer` 不阻塞首绘；字体 `swap`。
- 书写：每帧只重画当前笔；15 画以上不掉帧（真机项）。
- 300 字：墙 ≤ 8 行 + 「还有 N 个字 ›」；有记录的字完整页按月折叠，一次 ≤ 72 格；总占用 < 3.2MiB（e2e 用 300 字一年量级种子断言）。
- 兼容：iOS 15.0 WKWebView、Safari 15+、Chromium。**禁用 API 表**（`verify:unit` 用 es-check/eslint-plugin-compat + browserslist `iOS >= 15` 拦截）：`structuredClone`、`Array.prototype.at`、`Object.hasOwn`、`inert`、`:has()`、顶层 `await` 以外的 ES2022+ 语法；`getCoalescedEvents` 特征检测。
