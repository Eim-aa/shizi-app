## 3. 数据模型（v2）

### 3.1 身份与顺序

- **卡片键** `cardKey`：`base:<字>`（题库字，可练）/ `custom:<字>`（库外字，仅可查看）。一字一卡。查询层提供 `practicable(cardKey)` 谓词，清单「练这些字」只选 `base:`。
- **记录 id** `r<序号>`、**会话 id** `s<序号>`：序号在启动时由 `max(records、sessions 中已用序号, meta.serial) + 1` 推导，`meta.serial` 只是缓存；id 允许空洞（跳过撤销会删记录）。
- **「最近一次」以 id 序号为准**；`at`（ms）与 `localDay` 只做展示与月归属（设备时钟改动、测试钩子 `setClock` 不破坏顺序不变式）。
- **日期**：`localDay = YYYY-MM-DD`（设备本地日；D66 ⑦ 起一天从凌晨 4 点开始，`policy.dayStartHour`，P320——0:00–3:59 归前一天，`core/dates.js localDay` 是唯一的归日函数；已存的 localDay 不改写）；`at` ms。旧数据的 `dayKey` 按本地日（0 点分界，`calendarDay`）导入。

### 3.2 记录（Record）与事件

```js
Record {
  id, cardKey, char, sessionId,
  kind: 'judged' | 'answer-seen' | 'skipped',   // 只有 judged 是「有效记录」（决定-D18/D23）
  judgment?: 'correct' | 'wrong',               // kind==='judged' 必填
  at, localDay,
  help: { hints: 0|1|2, answerSeen: bool, traced: bool },   // 帮助事实，永不因更正删除（决定-D07）；traced = 点过「描一遍」（进入描一遍阶段即置真，不看描红笔数）；answer-seen 记录只存「自己写一遍」的本人墨（Q1，见下）
  corrections?: [{ from, at }],                 // 更正历史；更正不新增记录（决定-D19）
  inkId?: string,                               // 指向 ink 表；缺失 = 有记录无笔迹（10.12）
  legacy?: true,                                // 由 v1 数据合成（§12），无 fsrsBefore、无更正能力
  source?: 'screen' | 'paper'                   // 阶段 1 P1-E8：书写方式；缺省 = screen（旧数据不带、不迁移重写，读取时按 screen）；paper 只用于 judged、不带 inkId
}
```

规则：
- 文档与代码中的「记录」若未加限定，一律指 `kind==='judged'`；选字、清单、统计、首页 N 都只看 judged。
- 「写错过」= 某字最近一次 judged 的 judgment 为 wrong（K15）；「快忘了」= 最近一次 judged 为 correct 且 FSRS 到期（§5），两单互斥（K16）。更正为对同样离开写错过（I02）。
- 「今天记录了 N 个字」= 今天 judged 按字去重；首页墨迹行取最近 8 条 judged（按 id），数字仍 N（决定-D12）。
- 首页呈现（阶段 1 P1-E5，03 P155 / P156，设计稿「首练与首页」）：「今天记录了 N 个字」的说法改为「今天写了 N 个字」；首页按 `today.js homeViewOf` 分五态加首次打开——进行中的组（格子）> 首次打开 > 大写数字特别组 > 今天写过 > 离开 ≥7 天回来 > 今天还没写；首页不画朱点（D46 ①）；「昨天写的字」一行只放有本人墨迹的字；「字库里有 N 个字」N = 有过判断记录的字数。光影层取消（03 P143）。
- 更正（决定-D19）：只改 `judgment`、追加 `corrections`，`at/localDay/id` 不变；结果页 / 写字页只对**本会话仍可见**的记录开放（`Session.items[].fsrsBefore` 存在），看过答案/跳过不可改判（K25）。D66 ④：字详情的记录格放大弹层里也能改判（`ui/screens/detail/correct.js`，label `detail:correct`）——会话还留着 fsrsBefore 就同上重放，否则从空卡起重放本字全部 judged 记录（`core/correct.js`，近似，见调度规则说明）；legacy 与纸上记录不可改。
- 跳过撤销（走查-W16）：跳过时立即 commit 一条 `skipped` 记录并推进；3 s 内撤销 = 再 commit 一次：删除该记录、字放回 cursor、current 回到 recall；提示随刷新/换页失效。
- `skipped` 只用于会话内排除、结果页列举与统计，不影响后续选字（决定表：不自行选当前组/长期排除）。
- **看后自写（Q1，QA simB D1；03 P176）**：看过答案后「自己写一遍」的本人墨迹存成**这条 answer-seen 记录的墨迹**（`write/answer.js storeSelfInkInDraft`：离开自己写一遍——「下一个」或「再描一遍」——的同一次 `store.commit`，按记录月份写 `shizi.v2.ink.<月>`、键 = 记录 id；看过答案后恢复到的 recall 同样算）。记录 kind 不变、不写判断、不动 sched（D18 不变，仍不是有效记录）；一次看答案后多次自己写只留最后一次（同键覆盖，最后一次没写留上一次）；描一遍的笔迹不存；`perRecordInk` 关时不存。作品出口把它与写对并列（D31「写对与看后自己写的字」，`core/records.js isAfterSeenWork / isWorkOrAfterSeen`）：结果页作品与这次的图片的「看后写的」格（`core/images/work.js`）、这天的图片与月字帖、年报（年字数、每月一段、卷尾；`core/images/pick.js`、`mine/model.js workRecordsOf`、`mine/annual-model.js slice.works`），D42 取段内留有墨迹的那一次时它也算；「今年第一个有记录的字」的字仍取第一条判断；日历、统计、清单不变。留存见 §3.5 / §9。
- **纸上记录（阶段 1 P1-E8，D46 ⑬ / D47，03 P165–P169）**：「在纸上写，回来自判」的判断记 `source:'paper'`、没有墨迹（ink = null，不写 `inkId`、不写 ink 月键）。它是有效记录——判断、FSRS、写错过 / 快忘了、字库字数、今天写了 N 个字、字墙（新旧档与朱点，不加标注）照常；凡是画「本人笔迹」的地方都没有它：结果页作品、这次 / 这天的图片、月字帖、年报，以及年报与月份的字数都只收 `core/records.js isWorkRecord`（= judged 且不在纸上；时间段视图先 `withoutPaper` 再交给 `core/ink-pick.js`，段内只有纸上记录的字不出现、不画衬底、不计数）。D27 留墨：纸上那次不占「第一次 / 最近一次」——`store/budget.js indexRecords` 另记屏幕上写的第一次 / 最近一次一起留，纸上判断不会让之前留墨的最近一次变成中间那次被回收。单字详情：纸上记录不占笔迹格，记录列表另起一行「{日期}　写对 · 纸上」（读屏「…，写对，纸上」）。旧记录与 v1 迁移、备份 v2 信封、保护副本都不带 `source`，按 screen 读，无需迁移。**折叠（P1-E78）**：`budget.js foldMonth` 另记 `paperOnly: {localDay: [char]}`（那天只在纸上写过的字，缺省 = 没有；`core/schema.js` 可缺省字段），日历 / 「写过的日子」仍读 `byDay`（纸上那天算写过），年报与月字数、月字帖成员经 `core/records.js foldWorkByDay`（`byDay` 去掉 `paperOnly`）只算作品；折叠发生在纸上记录出现之后才会有 `paperOnly`，更早的折叠本来就没有纸上记录。

### 3.3 会话（Session）

两个槽位（决定-D05）：`A` = `first` / `daily`；`B` = `picked`（这次选的字）。另有 `lastEnded[slot]` 保留最近结束的会话供结果页、来源行、离开按钮只读。

```js
Session {
  id, slot: 'A'|'B', kind: 'first'|'daily'|'picked',
  source: { view, char? },                      // 结束后回到来源（S05/R-R06）
  queue: [cardKey], cursor,
  items: [{ cardKey, recordId?, kind, fsrsBefore?: CompactCard }],   // fsrsBefore 只活在会话里，供本会话更正重放
  current: { phase: 'recall'|'compare'|'answer'|'trace'|'retrace', strokes:[[…]], hints, answerSeen, hintRange, referenceReady, paper? },
                                                // paper?（阶段 1 P1-E8）：只对这一个字切换写字方式（true 纸上 / false 屏幕，缺省跟 settings.writeMode）；进纸上判断页时写 true
  lastLine: { recordId, kind:'record'|'changed'|'saw' } | null,
  startedAt, startedDay, updatedAt, endedAt?, endedEarly?
}
```

- 状态机：`recall → (提示 ≤2) → compare → 判断 → 下一字`；`recall → 看答案确认 → answer → trace → retrace → 下一字`；`recall → 跳过 → 下一字`；任何阶段返回 = 保存现场；`picked` 可「结束这组」。最后一字处理完直接进结果页（决定-D20）。
- 恢复幂等：records 里已有 `sessionId===当前 && cardKey===当前字` 的 judged 记录时，恢复不再进 compare，而是补写 items、推进 cursor（D07 不重复计数）。`phase==='compare'` 且笔画为空时回退 recall（`current.paper===true` 的纸上判断页除外，阶段 1 P1-E8）。
- daily 跨天：首页读取时 `startedDay !== 今天` 即过期——已判断的保留，没写的按 D22 口径不算记录也不算跳过；自动结束、不进结果页（P37）。
- S02「结束那组，开新的」= 一次 commit：旧 B 置 `endedEarly/endedAt` 移入 `lastEnded.B` + 建新 B；过渡默认不进旧 B 结果页，有判断时轻提示（P38）。
- 结束时会话移到 `lastEnded[slot]`；下次开同槽或离开结果页后清掉；停在结果页刷新时由 lastEnded 恢复。

## 4. 存储与事务

- `storage.js`：`read(key)`、`writeAll(entries, {label})`：① 先写 `shizi.v2.txn = {label, at, keys, prev:{key: 原值|null}}`；② 按固定顺序写数据键（ink → records → sched → custom/… → meta → **sessions 最后**，因为它决定恢复阶段）；③ 逐键读回比对；④ 成功删 txn。任一步失败：用 prev 回滚（prev 为 null 的键 `removeItem`），回滚失败则把已写键搬到 `shizi.corrupt.*`（txn 复制一份作证据、**活的 txn 保留**，下次启动 `repair()` 据此自动恢复旧值）、进入 R-B09 阻断页并提供导出入口。峰值占用 = 当前占用 + 被改键旧值之和，所以大域一律分键（records/ink 按月），不分键的 sched 以 1000 字 ≈ 500KB 为上限计入 §9 预算。 **唯一的免事务写入** `storage.writeOne(key, value)`：只用于撞配额后把旧 ink 月键替换为其淘汰后的子集（单次 `setItem` 本身原子；值必须是原值的子集且更小；不用于任何其他域）——因为此时连 txn 的旧值副本都写不下；写完立即发布到内存，再重试原提交一次。**审查整改 F1 增加第二个免事务写入** `storage.writeRoute(raw)`（阻断页期间调用方不写）：只写路由提示键 `shizi.v2.route`（API 写死这个键，`writeAll` 拒绝它）。理由：它不是业务数据（不在 store 状态、不进备份、丢了只是「不恢复、落首页」），单次 `setItem` 原子、新旧值都合法，故不写 txn、不读回回滚、不阻断、不做预算回收，失败静默；若走 `store.commit`，每次导航都会多写一份 txn 旧值并通知全部 store 订阅者重渲染，撞配额时还会为了一个导航提示去折叠旧月份。它在 `writeAll` 之外，不改变「sessions 最后写」的提交顺序，也不会进 `txn.keys`——启动 `repair()` 回滚半写提交时路由提示保持离开时的值，由 `route-memory` 按修复后的状态再判能不能恢复（例如判断 commit 中断回滚后仍回到判断页，D07）。故障注入：不计入 `interruptAfterWrite` 次数（halted 后照样拒写），`failNextWrite` 只在 `matchKey` 明确指向它时命中。`repair()` 遇到坏的路由提示直接删除（`report.dropped`），不隔离、不触发坏值提示。启动时若存在 txn 即先回滚再做形状校验（进程被杀时的半写修复）。
- 配额：`QuotaExceededError` 单独分类；commit 撞配额时先按 §9 预算回收一次再重试，仍失败才进保存失败三段式并建议导出。启动时估算总占用，>80% 在备份页与首页状态句预警。
- `store.js`：`commit(label, mutate) → {ok, error}`。按域浅拷贝（copy-on-write）→ `mutate(draft)` → 形状校验 → 计算脏键 → `writeAll` → 成功才替换内存状态并通知订阅者。UI 只在 `ok` 后推进。
- **写入点 × 失败表现**（D07 全覆盖）：

| 写入点 | 失败表现 | 文案 |
|---|---|---|
| 判断 commit | 留在判断页，三段式 | C017「没保存上，你写的字还在。」 |
| 点「看答案」（没有确认框，D51 ⑧） | 弹失败框（先不保存 / 再试一次），不进看答案页；事件不重复 | C017 类 |
| 跳过 / 跳过撤销 | 不推进，三段式 | T01 |
| 修改判断（写字页 / 结果页 / 字详情记录格放大弹层，D66 ④） | 弹层内三段式，记录与 FSRS 不变 | C034 |
| 加入自选 / 移除撤销（查字卡；字详情「加入自选」同一个 commit，D66 ⑮） | 三段式 | C150 / C125 |
| 换库 | 就地重试 | C063 |
| 结束这组 | 留在写字页，重试成功后结束（D22） | 10.10 |

| 抬笔写 sessions | **不阻断书写**：笔迹留内存，下次抬笔或 `visibilitychange` 重写；顶部一次性提示（按配额/通用两句）；到判断 commit 由三段式兜底（P52） | 沿旧两句 |
| 迁移 | 单次 writeAll，失败回滚且不写 `v2.meta`，展示 R-B09 迁移变体并建议导出旧数据，下次启动重试 | R-B09 |
| 保护副本 | 不替换（R-B04） | C205 |

- 启动：逐键形状校验（单一形状表 `schema.js`）；坏值搬到 `shizi.corrupt.<key>` 并顶部提示一次；存储不可用 → 「现在存不了记录」阻断页（R-B09），不允许写字。

### 4.1 原生数据层（B1，D26 / D67）

iOS 壳里全部持久数据（记录、调度、会话、设置、笔迹、路由提示、隔离值、v1 旧键）存在 App 自己的 SQLite 库里；网页 / e2e 仍用 localStorage。两者是 `storage.js` 的两种后端，**store 对外 API 与语义不变**（`store.commit` 仍是唯一写入口，读仍同步返回内存状态），`test/store/store.test.mjs` 整套契约用例对两种后端各跑一遍。

- **库与文件**：`Application Support/ShiziStore/shizi.sqlite`（系统 libsqlite3，不引第三方库：只需「键 → JSON 字串」的事务读写，GRDB 等带来的是 ORM / 观察者，B1 用不上，等 B4 规则改 Swift 时再评估）。`journal_mode=WAL`、`synchronous=FULL`（WAL 下每次 COMMIT 都 fsync，掉电也不丢已确认的写入）、`busy_timeout=5s`。文件保护 `.completeUntilFirstUserAuthentication`（锁屏后进程可能还在提交最后一笔或做 checkpoint，`.complete` 会让这些写失败；这也是 iOS 默认等级，显式写明）。**进 iCloud / 电脑备份**（不设 isExcludedFromBackup）：记录与笔迹是用户自己产生、不可再生的数据，体量见 §9。进后台时做一次 PASSIVE checkpoint（数据在 COMMIT 时已落盘，这一步只让 WAL 不长大）。
- **表结构（schema 1，`PRAGMA user_version`）**：键按数据形状分表，键 ↔ 行一一对应（`NativeStoreSlot`），值原样存 store 序列化好的 JSON 字串（原生不解析业务形状，规则仍在 JS）：

| 表 | 主键 | 存哪些键 |
|---|---|---|
| `records` | `month` | `shizi.v2.records.<YYYY-MM>`（当月 Record[] 或折叠对象） |
| `ink` | `month` | `shizi.v2.ink.<YYYY-MM>`（`{recordId: Ink v3}`；B2 原生书写面接手墨迹后可升级为每条一行，schema 2） |
| `sched` / `sessions` / `settings` | `id = 1` | 各自一个键 |
| `docs` | `name` | `meta` `custom` `wordOff` `photos` `legacy` `backupMeta` `funnel` `safety` |
| `aux` | `key` | 其余 `shizi.*`：路由提示 `shizi.v2.route`、隔离值 `shizi.corrupt.*`、v1 旧键、未知键（原样保留） |
| `store_meta` | `key` | `createdAt`、`migration`（迁移标记，§12.1）、`diag`（最近 20 条诊断） |

  每张数据表另有 `body TEXT`、`updated_at INTEGER`。升级：`NativeStore.migrateSchema()` 逐级写（同一事务里改表并改 `user_version`）；库比 App 新（降级安装）拒绝打开（E_SCHEMA → store 不可用 → R-B09），不碰数据。
- **写入与耐久性（commit 成功的含义）**：一次 `writeAll` = 一个原生事务（`BEGIN IMMEDIATE … COMMIT`，原子；不再写 `shizi.v2.txn`）。走**同步** XHR（`POST /__native/store/v1/apply`），原生提交后才返回，所以 **`store.commit` 返回 `{ok:true}` 时数据已在 SQLite 里且已 fsync**；返回 `{ok:false}` 时原生已整笔回滚、内存也没发布（D07 语义不变）。每个值带 JS 算的校验和（UTF-8 字节数 + FNV-1a 32），原生入库前核对、写后在同一事务里读回逐字节比对，不符整笔回滚（E_VERIFY → `kind:'verify'`），这是 localStorage 时代「逐键读回比对」的原生等价物。磁盘满（E_FULL）当作 `quota`，照旧走 §9 回收后重试一次。原生超时（E_TIMEOUT）或传输失败（E_TRANSPORT）＝**结果未知**：`storage.js` 置阻断（`blocked.reason:'uncertain'`，R-B09），本次不再写；重启后以库里已提交的为准。因此「崩溃最多丢什么」：已确认的写入一条不丢；崩溃 / 被杀那一刻正在进行的那一次提交要么整笔在、要么整笔不在（页面还没收到确认，界面也没推进）。进后台 / 被杀前无需 flush——没有未确认的写。
  - 取舍：备选是「内存先提交、postMessage 异步落盘、有序带确认、进后台 flush」。它让 commit 不等磁盘，但要新增「内存已提交、磁盘没跟上」的中间态：写失败时界面已推进、要回滚已发布的状态或进阻断；被杀时丢最后一段未确认写入；store 的回收重试、保护副本「失败即没变」（R-B04）都得重写。同步确认保留了全部现有语义，代价是每次提交多一次进程间往返（模拟器 Debug 实测见下），对每次判断 / 抬笔一次的写入频率可接受，故选同步。同步 XHR 在窗口上下文不能设 timeout，期限由原生执行（写 10s、加载与迁移 30s，到期回 E_TIMEOUT）。
- **启动加载**：`src/platform/native-preload.js`（index.html 里紧跟样式表的经典脚本）在 HTML 解析时就异步发出 `load`；原生在 `loadApp()` 时已经 `prewarm()`：在数据层队列上开库、读全部行并编好回复（任何写入类 op 先清掉它，拿到的一定是最新提交的内容）。`app.js` 在建 store 前 `await prepareStorage()`（`store/native-boot.js`）取走这次 load，建内存镜像后端（`store/native-backend.js`）再 `bootStore`——UI 挂载前数据已全部就位，首帧不闪、不出现空态。模拟器（iPhone 17 / iOS 26.5，Debug，约 300 字 47 万字符）：`store-modules → store-native` 1–2ms（未提前发出时约 37ms：请求排在模块与字体请求后面）、`store`（repair + 解析）约 10ms，首帧（FCP）160–214ms，与 localStorage 版 155–192ms 同一量级。
- **写入耗时**（同上环境，真实 `store.commit`，含 JSON 序列化、校验和、同步往返与 SQLite FULL 提交）：判断形状的提交（当月 records + 当月 ink + sched，约 14 万字节）p50 7–8ms、p90 11–13ms；小提交（settings）p50 4ms。localStorage 版同一组提交 p50 2ms。其中原生库本身（XCTest，同形状事务含校验与读回）Debug 1.2ms / Release 0.4ms；约 100KB 单值 apply 往返 3.5ms（原生 2.9ms，Debug 下主要是 JSON 解析与字符串桥接）。真机待测（§14）。
- **回退与阻断**：本机没迁移完成时任何原生故障都回退 localStorage（它仍是权威）；迁移完成后原生读不出来 → 进阻断，不退回已过时的 localStorage（依据是 localStorage 里的标记 `shizi.nativeStore.v1`，§12.1）。`store.status.backend = {kind:'native'|'localStorage', action, migration?, fallback?, unavailable?}`（测试钩子 `getStatus` 可见）。
- **测试钩子**：`getRawKeys` / `reset` / `failNextWrite` / `interruptAfterWrite` 在原生后端上同义（注入落在一个事务上：命中任一键 = 整笔不写；中断点落在事务内 = 写前，否则写后）；`getWriteLog` 逐项记录原生事务里的每个键（via `storage`）。量测探针 `scripts/native-store-probe.js`（DEBUG 壳 `-shizi-smoke-stage probe`）。原生单测 `ios/ShiziApp/ShiziStoreTests`（scheme ShiziStoreTests，只测数据层）。

### 6.1 书写格与坐标
内部坐标恒为 345×345 单位；显示：标准 345pt，紧凑版 258pt，看答案页 200–345（核对-X08/V02）。**〔X08 已被 D36 覆盖〕**显示边长不再由紧凑版决定：D49（阶段 1 E9b）起 = clamp(258, min(屏宽 − 40, 400, 名义主区高 − 题面标称高 80 − 16 − 格下工具行 40 − 16), 400)（policy.writeGrid，P118 / P195；`src/ui/screens/write/layout.js` `writeGridSize` / `nominalMainHeight`；名义主区高 = 页面高 − 名义页头（44 + 上安全区）− 名义按钮行（116 + max(8, 下安全区)）：标准字号 L 档的版式，安全区取量到的，**与系统字号无关**，冷启动直接在 AX 档也对），题面 + 书写格 + 格下工具行作为一组在主区里居中（空余 40% 在上、至少 12；组的位置按**实际**量到的主区高、题面高与工具行高排，主区 = 页头底 → 按钮行顶 − 12，由 `compact.js useWriteLayout` 量出），与字号、题面提示行无关（算边长用标称题面高与标称工具行高），recall / trace / retrace 各阶段与点提示前后同一边长（非回忆 / 判断阶段沿用最近一次量到的值）；紧凑版只改控件排布；内部坐标与存储格式不变，只缩放显示。AX 档单独排：题面格 52 → 64，格下工具行 52（只影响组的位置），**书写格边长不缩**（D29 / D36：AX 档的页头、按钮行更高、实际主区更矮，边长仍按名义主区高算，P195），放不下整页可滚、按钮行上沿出现 hairline。看答案页卡片：标准排布取书写格边长，紧凑排布按剩余高度取、不超过书写格边长。指针事件按 `getBoundingClientRect` 缩到 345 空间，`t = event.timeStamp`，`p` 仅 `pointerType==='pen'`。

### 6.2 笔迹管线（`core/ink-math.js`）
以交接备注八.1 与 `决定-D09/D10` 为准，原型 `ink-第十稿交接版.js` 为参考实现：同一时间戳点合并；1€ 滤波（minCutoff 1、β .02、dCutoff 1）+ Catmull-Rom 3 点重采样；本体宽 `BASE × (1.06 − 0.12·min(v, 1.5))`，`α = 1 − e^(−Δt/35ms)`；起笔 0.85 → 1.08 → 1.0（0–6–12pt）、点画（<24pt）0.7 → 1.1 → 0.9、单点直径 0.9×；收笔看抬笔前 30ms 平均速度（窗口插值到 30ms），阈值 0.25 / 0.9 pt/ms；**有真实压力时用压力替代速度因子，不叠乘**（D10）。输出 `{x,y,w}`；存储用 §3.5 的紧凑抽点编码，渲染用完整点列。常量在 `policy.js` 标「待真机」。

### 6.3 渲染与指针
- 三层 canvas：固化层（抬笔追加一笔）、当前笔层、提示/描红层；`setPointerCapture`、`touch-action:none`；`getCoalescedEvents` 仅在存在时使用（iOS 15–18.1 WebKit 没有，退回原始 pointermove）；预测墨头留待真机。
- `pointercancel` / `lostpointercapture` 一律视为该笔中断：丢弃未完成的当前笔，不固化、不计笔数（本人墨迹按意图，D07）；已固化层不动。**M0-7 实测**：原生边缘识别器触发时 WKWebView 不给页面发 `pointercancel`（笔画照常 pointerup），所以 `shizi-native-back-progress {phase:'began'}` 也视为当前笔中断信号；书写格对 `pointerdown` 调 `preventDefault`（实测能让识别器不开始，作为门控之外的第二道保护，不依赖它）。WKWebView 里 touch 的 `pressure` 恒为 0，压感分支只按 `pointerType==='pen'` 走。
- 飞白、洇墨基元从现有 `paintBrushStroke` 抽取；减少动态效果或低端设备只保留首尾锥形。抬笔用 `final=true` 结果固化，实时与最终一致。

### 6.4 提示（决定-D25 / R-W05 / R-W06）
每点一次提示，在已给出的提示笔之后再多给一段，可一直点到整字都给出（已决定 D64 ①，取代 P17「每字 2 次」与 P01「按已写笔数」；被本人笔收掉的仍算已给出，`hintMax` / `hintStartRule` 已删）；有分组数据的字每段 `q = max(1, round(N/4))` 笔，无分组数据的字每次多 1 笔。整字都给出后按钮「提示已用完」不可点，同时按「看过答案」记录（与「看答案」同一函数 `commitAnswerSeen`，留在回忆页继续写）。画法（W1，D34 / D51 ⑧ 覆盖 D25，03 P210 / P211）：本人笔迹**不变暗**；提示 = 给出的那几笔用与描一遍同一种画法（`canvas/glyph-wash.js`：整层 .4 淡朱填充 + 外侧一圈 `--ink3` 外廓），画在参考字形层（本人墨下层），整组 150ms 淡入（网页阶段不逐笔写出，逐笔与拟合属阶段 2；`hintTimeline` 保留作原生基准）；写下一笔时提示 260ms 淡出；减少动态效果时改为 120ms 淡化（R-G01，与 §7 一致；M1-3 常量 `REDUCED_FADE_MS`）。笔顺数据加载中按钮同文案但 disabled；「有分组数据」= `GROUPS[字]` 存在且各组笔数之和等于总笔数，否则前 1 / 前 2 笔。按钮读屏名「提示，还有 {n} 次」（n = 还剩几段）「提示已用完」；无笔顺数据灰字「暂时没有提示」。用过提示后格下没有说明句（P41 已决定 D51 ⑧：删去「浅红色是提示……」）。

### 6.5 看答案（决定-D18）

### 6.6 判断页与结果行（决定-D19/D20/D03）

## 7. 导航与页面

- `router.js` 以 **history 为唯一真相源**：`push()` 只 `pushState({depth, name, params})`；UI 返回按钮调用 `history.back()`；页面栈与遮罩栈的变化都在 `popstate` 处理器中按 depth 差执行。各屏 `registerScreen(name, component)` 自注册，无中心路由表。tab 根页 `replaceState`；`back()` 先关最上层遮罩。
- 转场：推入 300ms `cubic-bezier(.2,.7,.2,1)` 带左投影，返回反向；减少动态效果 120ms 交叉淡化。iOS 主屏 PWA（`display-mode: standalone`）下 popstate 引发的返回跳过自定义转场，避免与系统快照动画叠加。
- **左缘右滑返回（R-G01）在单 WKWebView 下的含义**：Web 页面栈 + 原生识别器驱动的跟手转场，属工程近似（P54）。原生壳内手势唯一所有者是 Swift：`UIScreenEdgePanGestureRecognizer(.left)` 加一个「页边 20pt 起手、向右（容许斜着起手）」的平移识别器（要求前者先失败），都挂在 WKWebView 的容器视图上（避开 WebKit 的 deferring 手势），WKWebView 里滚动容器的平移识别器要求它们先失败（边缘起手不被下半屏的滚动列表抢走）——P272。在 `.began/.changed/.ended/.cancelled` 派发 `shizi-native-back-progress {phase, translationX, progress, velocityX}`，达到阈值时派发 `shizi-native-back`；JS 由 `router.createBackGestureController` 处理：began 时遮罩开着先关遮罩，否则冻结底层并跟手（底层视差 0.3），ended 按 `v > 500 || (x > 1/3 宽 && v > -200)`（P103，D55）完成——执行顶层页面页头左上键的同一个动作（`ui/back-action.js`，P270）——并在 600ms 内吞掉紧随的 `shizi-native-back`（旧壳或丢事件时仍按一层返回），减少动态效果只完成不跟随（淡化 150ms）。对外接口 `router.beginBack / setBackProgress(p) / endBack / finishBack / cancelBack`，样式由 `root.js BACK_TRANSITION` 决定（换进出动画只换它）。JS 通过 `postMessage({type:'backGestureEnabled', value})` 告知原生（root 只在「页深度（不含遮罩）、阻断、顶层页面左上是不是返回 / 关闭键」变化时发；tab 根为 false，即使根上开着弹层也保持 false——M5 修复回合 K1；写字页 R4-G1 起与其它子页一样为 true——书写格四周有 20pt 页边，边缘起手落不到格子里，落笔中被手势打断时当前笔丢弃；判断阶段左上是「接着写」，为 false），Swift 在 `gestureRecognizerShouldBegin` 拒绝识别。事件名以 `shizi-native-back-progress` 为准（M0-4 暂时兼容 `shizi-native-progress` 别名，M5-3 删除）。浏览器 / 主屏 PWA 下另有网页兜底（`ui/edge-swipe.js`，页头以下左缘 12px 起手带，派发同一事件；原生壳内不装，P271），系统返回仍走 popstate。
- **冷启动恢复（审查整改 F1，R-W13 / P32 / P108）**：同一页面内刷新从 `history.state` 恢复；但 App 进程被杀后 WKWebView 是全新会话（主屏 PWA、新标签页同理），`history.state` 为空。为此 `ui/route-memory.js` 把页面栈（只含页面，截到第一个遮罩为止——遮罩组件只活在内存里；`{n, p}` 与 history.state 同一份）写进 `shizi.v2.route`：挂载后写一次，之后页面栈或参数每变一次写一次（遮罩开关不写），`visibilitychange(hidden)` 与 `pagehide` 时刷新离开时刻 `at`。`router.start()` 发现 `history.state` 不是本模块写的时调用 `coldStart()`，按下列顺序判定，**任何一条不满足都整栈不恢复、落默认 tab 根（首页）**：① `policy.routeRestore.enabled`；② 阻断页优先（存储不可用 / 回滚失败 / 迁移失败）；③ 坏数据优先（本次启动隔离了坏值、要出顶部提示）；④ 提醒深链优先（桥上排着 `shiziOpenReminderTarget`）；⑤ 未过期（P108：离开不超过 `maxAgeMinutes`，过渡 360；`crossDay=false` 时跨本地 0 点不恢复）；⑥ 逐页有效性：写字页要该槽还有能续写的组（`resumableSession`，跨天作废的 daily 与写完的组不算）、结果页要 `lastEnded[slot]`（或槽里）还是那组、单字详情要这个字还在（题库 / 自选 / 有记录 / 旧照片）、旧照片页要照片还在、「现在没有要写的字」页不恢复；第一项必须是 tab 根、其余必须是已注册子页。通过后 router 用 `replaceState`（depth 0）+ 逐层 `pushState` 重建 history 条目（返回键照常按层退回），转场 `{kind:'none', cause:'restore', cold:true}`。写字页按 `sessions[slot].current` 的阶段与笔画自行恢复（§6；笔画抬笔即写、切后台再写，P52），所以回忆 / 判断 / 看答案 / 描一遍 / 自己写的阶段、笔迹与参考字形都在；备份页按 `cause:'restore'` 恢复撤销底栏（§9 P32）。**深链压过恢复**：iOS 冷启动时原生等 `pageReady` 才派发提醒深链，此时栈可能已恢复——`reminder.js` 经 `route-memory.runDeepLink` 执行：本次是冷恢复且用户还没动过（没导航、没切后台）→ 先 `switchTab(默认 tab)` 静默退回首页，`router.whenIdle` 等 history 落定后再开 B 组；否则直接叠在当前页上（热启动行为不变）。同页刷新从不读路由提示。
- 可访问性：所有可点控件用 `<button>`；禁用 `disabled + aria-disabled`；弹层 `role=dialog aria-modal` + 焦点陷阱 + 焦点归还；tab `role=tablist`；轻提示 `aria-live`。

### 8.8 冷启动到首页首帧（Q3；QA simA S3；03 P179 / P180）
现象：QA 在 iPhone 17 模拟器（Debug）上看到冷启动后 1.5–3.8s 只有纸色。结论：**这段空白几乎全是系统拉起进程的时间，页面自己的部分约 150–200ms**；1.5–3.8s 只在模拟器刚开机或宿主满载时出现。
- **打点**：`src/app.js` 在启动链上打 `performance.mark('shizi:…')`：`app-eval`（入口模块求值）→ `store-modules` → `store`（bootStore，含 repair）→ `migrate` → `ui-modules`（root.js 模块图求值完）→ `mounted` → `first-frame`（挂载后两次 rAF）→ `ready`（pageReady 前）。首帧以 paint `first-contentful-paint` 为准（body 起初只有空的 `#app`，首个内容帧就是挂好的首页）。原生侧量测用的是不入库的临时插桩（进程启动时间 `sysctl KERN_PROC_PID p_starttime`、`didFinishLaunching`、WKWebView 创建、`load()`、scheme handler 每个请求的起止、`decidePolicyFor`、`didStartProvisional/didCommit/didFinish`、pageReady 后 evaluateJavaScript 取页面打点，写进 App 的 Documents），专用模拟器 QA Q3（iPhone 17 / iOS 26.5），每个样本重装；「约 300 字」= `.review/qa-simA/seeds/rich.ink.json`（278 字 + 墨迹，先启动一次建库再直接写 LocalStorage 库），修复前后两个构建在同一台模拟器上交替冷启动各 10 次（抵消宿主负载漂移，量测时宿主负载 10–18）。

### 8.9 声音（阶段 1 S1；决定 D50 ⑦ / D46 ⑮ / D30；03 P24 / P200 / P201）
声音只有两种，**书写与描红不出声**：判断「收进」（写对了 / 写错了 / 修改判断，每字一次，两种判断同一声、无奖惩感）播 **j1「纸页落定」**，三个变体 `j1_page_settle` / `_b` / `_c` 按顺序轮换；结果页作品**首次呈现落款**时播 **s1「木印·闷实」**（网页阶段没有落印动画，作品出现即落款；每组一次，没有墨的衬底一行不响）。旧的 82Hz 盖章声、高频纸声及 `trace-stroke` 点位已删除（`policy.keySoundEvents = ['judge','seal']`）。
- **素材**：`assets/sound/` 的 4 个声音各一份 WAV（44.1kHz / 16bit / mono，网页 / PWA）与 CAF（LEI16，无编码、无 priming 补零，iOS 包），两者采样逐字节一致；由 `scripts/sound/gen.mjs` **程序合成**（噪声 + 滤波 + 包络 + 衰减正弦模态 + 自造短混响，固定种子，可复跑；没有采样、没有下载，因此无第三方素材、THIRD_PARTY 与关于页无需署名）。`test/platform/sound.test.mjs` 重新生成并逐字节比对。WAV 进壳清单与 SW 尽力预缓存（离线可用）；CAF 进壳清单（iOS `rsync --files-from`）但不进 SW（`build_shell_manifest.mjs swLists` 跳过 `*.caf`）。
- **入口**：`platform/sound.js keySound(event, {state|settings, key})`。判断由 `platform/haptics.js` 的 commit 反馈（`write:judge` / `write:correct` / `result:correct`）与 stamp 触觉同一处发；落款由结果页 `WorkSection` 挂载时发（`key = 槽:会话 id`，同一组只响一次；同一 key 不重复、没放出来不占 key）。事件不在 `policy.keySoundEvents`、没有对应文件（如 `trace-stroke`）一律无声。
- **开关与会话**：设置里「按键音」（`settings.sound`，缺省开）关着时**完全无声**（不请求素材、不播放，触觉照常）。原生 `AVAudioSession` 为 `.ambient` + `.mixWithOthers`：遵守静音键、不打断不压低后台音乐（不用 duckOthers / playback / soloAmbient）；网页在支持的 Safari 上设 `navigator.audioSession.type = 'ambient'`。
- **播放**：原生壳内 `postNative('sound', {kind: 文件名, gain})`，原生 viewDidLoad 预载 4 个 CAF 的 `AVAudioPlayer`，按文件名播、`gain` 夹在 0…1；浏览器 / PWA 用 Web Audio 播放预解码的 WAV（写字页 / 结果页挂载时 `warmSounds` 预载；没载好的那一声不出、不拖延；`GainNode` 取同一增益）。若真机测得 `AVAudioPlayer` 起播延迟 >20ms，阶段 2 改 `AVAudioEngine` + `AVAudioPlayerNode`。
- **响度（P201）**：判断声比落款低约 6–8dB（LUFS-M −31 对 −23，耳机差 8dB、外放估 6.1dB）——这个差已经在素材里，播放增益 `policy.soundGainDb` 两项取 0dB（不在播放端放大，放大会削波）；真机试听后只在这里或 `gen.mjs` 的 `TARGET` 调。
- **门禁**：`test/platform/sound.test.mjs`（事件映射、轮换、关开关、书写无声、素材格式与复跑一致、响度关系、壳清单 / SW）、`test/ios-sound.test.mjs`（原生静态核对）、`scripts/e2e/80-s1-sound.spec.js`（请求的音频资源只有 j1 变体与 s1，真播放的缓冲依次为 j1 ×N / s1，描一遍无声、关开关无请求无播放）、`55-reminder`（假原生桥消息）。真机试听项见 `ios/ShiziApp/DEVICE_QA.md` §13e。

- 被淘汰 / 回收墨迹的记录显示「没有笔迹」（10.12），不借别次墨迹（I03）。D27 下中间那次在写入下一次判断时就回收（§3.5），所以按时间段取「某一次」的页面（月字帖 P02 本月第一次、这次 / 这天的图片、年报首字）若只取偏好方向上的那一条，在旧月份常取到已回收的那次。**已决定 D42（解 P122）**：这类页面在该时间段内按原取法的偏好顺序（取第一次的从早到晚、取最后一次的从晚到早）找**留有墨迹**的那一次（共用纯函数 `core/ink-pick.js` `pickRecordInPeriod`，判「有没有墨迹」只做按月墨迹表的一次查找、不解码），时间段内一份都没有才如实显示「没有笔迹」；角标 / 说明行的日期随挑出的那一次，不拿时间段外的墨迹冒充（I03）。单字手写图片、字库墙、清单小图等本来取「最近一次」的地方不属于时间段视图，口径不变。
- **看后自写的容量（Q1，P176，`test/core/ink-math.test.mjs` 实测）**：每字至多多一份（新于最近一次判断的最新那份）。常用 300 字每字都有 = 0.90MiB（+0.30），仍在 1.2MiB 目标内；12 画以上 300 字每字都有 = 1.47MiB（+0.49），超 1.2MiB 目标、在 P05 1.5MiB 预算内；两成的字有看后自写时 0.66 / 1.08MiB。超预算时先回收判断其余层，再回收看后自写（4 → 5），D27 首末与开着的组里的不回收。折叠旧月份时开着的组里的看过答案记录随 `kept` 留下，其余随折叠删墨。
- **原生口径（B1，§4.1；`policy.nativeStorage`，`store/budget.js NATIVE_BUDGETS`）**：iOS 壳迁到 SQLite 后不再有 5MiB 硬上限。估算仍用同一把尺（键长 + 值长）× 2，回收与预警逻辑不变，只换数值：假定上限 `quotaBytes` 64MiB（预警线 80% = 51.2MiB）、目标合计 48MiB、records 16MiB（≈3.7 万条，每天 30 字约 3.4 年，400 天折叠通常先到）、墨迹 32MiB（≈2.2 万份，D27 每字两份可容约 1.1 万字，超过 8105 字全库；不再按每组字数分档）。理由：SQLite 存 UTF-8、JSON 以 ASCII 为主，模拟器实测约 300 字（估算 0.99MiB）库文件 0.65MB（0.65×）、值的 UTF-8 合计 0.48×、导出的备份文件 0.58×——估算 64MiB ≈ 库文件 40MB、备份约 37MB。真正的上限来自备份文件（导出 / 导入都是整份 JSON），故备份导入上限由 10MB 提到 64MB（`core/backup.js BACKUP_MAX_BYTES` 与原生预检同步），保证到预警线前的整份备份都导得回来；另一个约束是整份状态常驻页面内存、每次判断重写当月键，B2 起墨迹改为原生每条一行后再放宽。「我的 › 备份」行的提示机制（`storagePressureOf`）不变，原生壳里按上面的上限算比例。D27「原生数据层后保存全部历次」是留存规则变化，不在 B1（见 §14）。
- 容量监测沿用 §4 / P57：占用 > 80% 假定配额时备份页与首页状态句预警，撞配额时按上表回收后重试一次、仍失败走保存失败三段式并建议导出；不新增文案。300 字两份 ≤ 1.2MiB 时常规提交不触发墨迹回收（61-perf 断言预算回收零淘汰）。
- 折叠月份形状：`{folded:true, month, byDay:{localDay:[char]}, chars:[char], kept:Record[], paperOnly?:{localDay:[char]}}`（`paperOnly` 可缺省，P1-E78：那天只在纸上写过的字，年报 / 月字数不计，日历仍按 `byDay`），`kept` 保留该月里仍是某字最新 judged 记录、或某字第一次 judged 记录（D27，阶段 1 P1-E3：首次的墨迹随记录留下）的条目（写错过/快忘了与 D23 口径不受折叠影响）。
- 占用预警阈值与假定配额为 policy 项（P57）；测试钩子 `failNextWrite(1,{kind:'quota'})` 会被「回收后重试一次」吸收，要稳定制造配额失败用 `n≥2` 或 `kind:'generic'`（M4-4 的保护副本失败注入按此写）。
- **保护副本（R12 / 10.14 / O04）**：替换或清空前先写单键 `shizi.v2.safety = {version, kind:'restore'|'clear', createdAt, backupDate, count, payload}`（v2 业务键 + 当时的 `sessions`，不含 v1 键；替换/清空同时把 A/B 置空、保留 lastEnded——P79，撤销时连会话一起还原）。保护副本与撤销经 `store.commit(label, mutate, {reclaim:false, replace:true})`：撞配额直接失败、不回收，避免在告诉用户「记录没有变」的同时折叠旧月份。写后读回核对；失败（含配额）→ 不替换，R-B04「没能换成备份，你现在的记录没有变。可以再试一次。」；成功后 `writeAll` 目标数据（失败回滚并删 safety）→ 撤销底栏。撤销 = 用 payload 原样 `writeAll`（不再规范化，避免记录数变化），失败按 R-B05，副本保留可再点。删除副本：路由离开备份页、撤销成功、下一次替换开始前；离开时写 `backupMeta.lastConclusion` 供结论句。启动时发现残留副本（进程被杀后重载）按 P32 处理（过渡：仍在备份页则恢复撤销底栏）——同页刷新由 history.state、进程被杀后的冷启动由路由提示（§7，审查整改 F1）把备份页恢复出来，转场 `cause:'restore'` 时恢复撤销底栏；从别处重新推入备份页时遗留副本视为过期、删掉；冷启动未恢复（过期 / 深链 / 阻断）时副本留到下次进入备份页再删。内存缓存同一份快照只为加速。

### 12.1 localStorage → 原生 SQLite（B1）

iOS 壳里，库的迁移标记不是 `done` 时（新装或第一次启动新版本）每次启动都执行，可重入（`store/native-boot.js`）：
1. 同步通道探测（`callSync('ping')`）——写入要靠同步 XHR，不通就不迁移；
2. localStorage `repair()`（与旧版启动时一样：回滚半写的 txn、隔离坏值；**不做写探测**——localStorage 写满时正是最需要迁移的时候）；
3. 读出全部 `shizi.*` 键（去掉 txn、探针、冒烟键、迁移标记），算每项校验和与整体摘要（`count:总字节:FNV`，JS 与 Swift 同口径，单测共用向量）；
4. `import`：原生一个事务清空数据表、整批写入（逐项核对校验和、读回比对）、按库里的行重算摘要须一致，记 `migration.state = imported`；
5. 再 `load` 一遍逐项核对：条数相同、每个键的值逐字相等、摘要相同；
6. 在 localStorage 写标记 `shizi.nativeStore.v1`（写不进去不影响迁移，只少一道保险）；
7. `commitMigration`：原生再重算摘要一致才置 `done`。此后原生为准，`done` 的库拒绝再导入（E_MIGRATION），旧 localStorage 再也不会覆盖新数据。

**失败与回退**：任何一步失败，这次启动继续用 localStorage（一字不动），诊断记进原生库 `store_meta.diag` 与控制台，下次启动从头再迁；中途被杀同理（`import` 是单个事务，没到 `done` 就从头再来）。`commitMigration` 结果未知时再 ping 一次：`done` → 用原生；`imported` → 回退；问不到 → 阻断（不冒险让两边分叉）。已迁移（有标记或库为 `done`）后原生读不出来 → 阻断，不退回 localStorage。D26 写的「双写校验」落实为「一次性整批复制 + 逐项校验 + 旧数据保留」而非长期双写：迁移的起因就是 localStorage 的配额，双写会把它带回来。
**旧数据何时删**：本版本不删任何 localStorage 键（保留一个版本周期，万一要回到旧版本或人工比对）。规则（下一个版本实现）：库为 `done` 满 30 天、且 App 已在迁移之后的**另一个版本**上至少成功启动一次（原生 `load` 成功、条数不少于迁移时）→ 删除 localStorage 里的 `shizi.*` 键（保留 `shizi.nativeStore.v1` 标记）；删前再跑一次 `PRAGMA integrity_check`，不通过就不删。
实测（模拟器）：旧版（d0e1367）写入约 300 字种子 + 20 次判断（18 个键、45.7 万字符）→ 装新版 → 启动时迁移（整段 77ms）→ 主机侧逐键比对 localStorage 库与 SQLite 库：18 个键逐字相同；之后杀进程重开、写入中途 SIGKILL（`integrity_check` ok、无坏值隔离）、导出再恢复（白名单键逐字相同）都通过。

## 13. 性能与兼容目标

- 首屏：`index.html` + `app.js` 依赖树 < 150KB（不含 deck 与字体）；deck `defer` 不阻塞首绘；字体 `swap`。
- 书写：每帧只重画当前笔；15 画以上不掉帧（真机项）。
- 300 字：墙 ≤ 8 行 + 「还有 N 个字 ›」；有记录的字完整页按月折叠，一次 ≤ 72 格；总占用 < 3.2MiB（e2e 用 300 字一年量级种子断言）。
- 兼容：iOS 15.0 WKWebView、Safari 15+、Chromium。**禁用 API 表**（`verify:unit` 用 es-check/eslint-plugin-compat + browserslist `iOS >= 15` 拦截）：`structuredClone`、`Array.prototype.at`、`Object.hasOwn`、`inert`、`:has()`、顶层 `await` 以外的 ES2022+ 语法；`getCoalescedEvents` 特征检测。
