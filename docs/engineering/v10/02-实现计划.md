## 0. 工作方式

- **分支**：集成分支 `v10/integration`（从 `main` 639f592 切出）。功能分支 `v10/m<N>-<topic>`；合入集成分支须三层门禁全绿 + 架构侧验收。`main` 在整体验收前不动（GitHub Pages 从 `main` 发布 = 线上）。
- **角色**：开发代理（Opus 5.5，high）按任务卡执行；架构侧（本文作者）验收与修复回路；产品负责人裁决 03 的 P 项。
- **任务卡格式**：编号 / 目标 / 拥有文件 / 只读文件 / 依据（R-、决定-D、P、走查- 编号）/ 填充 copy（R 编号）/ 完成定义（可测）/ 不做什么。开发代理完成后提交：变更摘要、跑过的命令与结果、未覆盖项、新增待定项。
- **提交**：Conventional Commits；生成物（`sw-manifest.js`、`shell-manifest.txt`、`deck-meta.js`、`build-info.js`、`copy-source.json`）与生成器同一提交；不提交证书与构建产物。
- **门禁**：`pnpm test` = `verify:data`（governance + vector440 + content + assets + sw-unit）+ `verify:unit` + `verify:copy` + `verify:web`（e2e + pwa）。CI 从 M0-2 起三个 job 并行，`node --check` 遍历 `scripts/**/*.{js,mjs,cjs}`（排除 `scripts/legacy/`）。
- **验收记录**：`docs/engineering/v10/acceptance/M<N>.md`，每条：需求 ID / 版本 SHA / 前置数据（seed 注入 / 真实操作）/ 路径类型（真实存储 / 代表路径演示）/ 操作 / 实际结果 / 前后状态 diff 文件 / 失败重试结果 / 证据 / 设备环境（Chromium 版本 / Simulator 机型与 iOS 版本 / 真机）/ 通过或未通过 / 未覆盖范围。
