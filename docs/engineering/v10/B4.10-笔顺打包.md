# B4.10 笔顺数据打包（pack + 索引 + Swift 读取器）

计划依据：[B3B4-原生化架构与计划.md](B3B4-原生化架构与计划.md) §4.5 第 4 条、§6.2 B4.10 行——「7,221 个 JSON → 只读打包文件 + 索引」，验收「读取等价、体积下降」。

**本卡交付 pack 构建器、Swift 读取器与等价性证明；App 不换数据源**（Bundle 里仍是 `data/<字>.json`，接入是后续卡）。全部产物：`scripts/stroke-pack/build.mjs`、`ios/ShiziCore/Sources/ShiziStrokePack/`、`ios/ShiziCore/Tests/ShiziStrokePackTests/`、本文档。

## 结论（实测）

| 项 | 打包前（7,218 个文件） | 打包后（1 个 pack） |
|---|---|---|
| 逻辑字节 | 21,903,991 B（20.89 MiB） | 22,048,367 B（21.03 MiB）＝ 头 16 B ＋ 索引 144,360 B ＋ 数据 21,903,991 B |
| 磁盘分配（`du` 口径） | 33,546,240 B（31.99 MiB；`du -sk data/`＝32,928 KB，含 3 个非笔顺文件） | 22,048,768 B（21.03 MiB；`du -sk`＝21,532 KB） |

分配体积 **−11.0 MiB（−34%）**——收益全部来自消灭 7,218 份 4KB 块零头；pack 自身只多付 144,376 B（0.66%）索引。

查找耗时（1,000 个固定种子随机字，全部命中）：

- Debug（XCTest，-Onone）：6.7–10.6 ms（≈7–11 µs/次）；
- Release（`swiftc -O`，页已热）：0.52 ms（≈0.5 µs/次）；100,000 次 42–44 ms（≈0.43 µs/次）。

首次触页（冷 mmap）会慢一些，练习页一次只取 1 个字，感知不到。

## 格式（版本 1）

 Foundation 依赖、无压缩、不重编码——数据区是各 JSON 的**原始字节逐文件拼接**，等价性因此逐字节成立。

```
偏移        内容
0   4 B    magic  "SZPK"
4   2 B    version u16le ＝ 1
6   2 B    entrySize u16le ＝ 20（每条索引字节数）
8   4 B    count u32le（条目数 = 字数）
12  4 B    dataOffset u32le（数据区起点 = 16 + count × entrySize）
16  …     索引：count 条，每条 20 B，按 key 的 UTF-8 字节升序：
           key     8 B  字符的 UTF-8，右侧 0 填充
           offset  8 B  u64le，数据区**绝对**偏移
           length  4 B  u32le
dataOffset … 数据区：各 JSON 原始字节拼接，无对齐、无分隔
```

设计取舍：

- **key 固定 8 字节、右补 0**：单码点的 UTF-8 最长 4 B；合法 UTF-8 不含 0x00，补零不改字节序与相等性，二分可以整段 8 字节比较（UTF-8 字节序＝码点序，且单码点 key 互不为前缀）。
- **offset 用绝对偏移**：读取器拿到条目即可切数据，不用再加 dataOffset。
- **entrySize 进头部**：索引条目将来加字段不动版本（读取器要求 ≥ 20，多余字节忽略；本版恒 20）。
- 不用 SQLite / 不压缩：卡的原意是省文件系统块开销；压缩会破坏「逐字节等价」的平凡性，SQLite 的页/事务机制在这里没有用武之地。

## 构建器

```sh
node scripts/stroke-pack/build.mjs             # 写 build/strokes.pack
node scripts/stroke-pack/build.mjs --out p     # 自定输出路径（相对 CWD）
node scripts/stroke-pack/build.mjs --check     # 打到临时文件 → 读回 → 逐字校验 → 删临时文件
```

- **哪些文件算笔顺文件**：文件名去掉 `.json` 后恰好一个 Unicode 码点——与 `src/data/strokes.js` 的 `strokesURL` + `isSingleChar`、`ios/ShiziApp/ShiziApp/NativeGlyph.swift` 的 `data/<字>.json` 同一命名。据此**排除** `data/etymology.json`（词源数据，非每字）、`data/context-overrides.js`（非 JSON）、`data/LICENSE.md`（非 JSON）。库里含 2 个补充平面字（𬇕 𬜯），UTF-16 代理对文件名照常打包。
- `--check` 的读回校验用**独立于写路径**的二分查找（与 Swift 读取器同一套逻辑），等价于双实现交叉验证。
- 输出确定性：排序固定、布局无随机，重跑与换输出路径 sha256 相同（实测 `48dcc465…`）。
- pack 是构建产物，**不入库**（`.gitignore` 已加 `/build/`）。

## Swift 读取器

`ShiziStrokePack`（新 library target，只依赖 Foundation；Package.swift 只加了产品与目标行）：

```swift
let pack = StrokePack(url: packURL)   // failable init
pack.count                            // 字数
pack.data(for: "拾")                  // Data? ＝ data/拾.json 的原始字节（逐字节相同）
```

- `init?(url:)` 按 `.alwaysMapped` 内存映射，不整读进堆；打开时一次 O(count) 自检（magic / 版本 / entrySize / dataOffset 一致性、索引 key 严格升序、每条数据区在文件内），之后每次查找只剩二分。
- `data(for:)` 返回 `subdata` 拷贝（2–4 KB 量级），调用方持有安全；非单码点输入（空串、两字、带组合符、孤立代理）直接 nil。
- **线程安全**：struct 全字段 init 后不可变，映射只读，查找无锁；并发读测试覆盖。
- 打不开的 pack 一律 `init` 返回 nil（坏 magic、不认识的版本、count 与文件不符、索引乱序、offset 越界、截断文件、文件缺失）。

## 等价性证明（两层）

1. **node 层**：`build.mjs --check` 重新打包 → 从磁盘读回 → 二分取出每个字 → 与 `data/<字>.json` 逐字节比对，7,218/7,218 通过。
2. **XCTest 层**（`ShiziStrokePackTests`，9 个用例）：
   - `testEveryCharacterFileRoundTripsByteForByte`：**每一个**字 `pack.data(for:) == Data(contentsOf: data/<字>.json)`，全过；
   - count 与 data/ 文件数一致（7,218）；补充平面字 𬇕 𬜯 单测；未知字（A / Z / 龥 / 㐀 / 𠀀 / 空串 / 双字 / 组合符）返回 nil；
   - 合成小包的单测（打开、坏 magic / 坏版本 / entrySize 0 / count 不符 / offset 越界 / 截断 / 缺文件 / 索引乱序 → nil）；
   - 1,000 随机字计时（固定种子，打印不做紧断言）与 256 次并发读。

   **pack 来源**：测试读仓库根 `build/strokes.pack`（构建器预先产出），不在测试里调 node；文件缺失时 XCTSkip 并写明生成命令。选这条而不是「测试内跑 node」：XCTest 不该依赖 node 在 PATH，且 pack 缺失的失败模式（skip）不会把别人的构建环境变成红灯。
   仓库根定位用 `#filePath` 上推 4 层，不依赖工作目录。
