# B4.8 预备：真实数据双读核对

对应计划 [B3B4-原生化架构与计划.md](B3B4-原生化架构与计划.md) §4.4 第一行：切换到 Swift（B4.8）之前，在负责人真实数据的**脱敏副本**上做一次「JS 读 → 状态 A；Swift 读 → 状态 B；A == B」，再在这份状态上跑同样的随机操作，两边的状态仍要相等。

这张卡只造工具（`scripts/dual-read/`），不碰 App。仓库里没有真实数据，工具的门禁是 `--self-test`（合成数据）；真实数据由负责人把文件拷到电脑上后跑一次。

## 一、怎么拿到数据（只描述，工具不替你做）

两种输入任选其一，**备份 JSON 最简单，优先用它**。

**A. 备份文件（推荐）**
1. 手机上打开 拾字 › 我的 › 备份，点「导出备份」。
2. 在分享面板里存到「文件」，或用隔空投送发到电脑。文件名形如 `拾字备份-2026-10-30.json`。
3. 注意：备份只含白名单域（记录、调度、墨迹、自加字、设置、照片、v1 导入记录等），不含进行中的会话、保护副本、路由提示。这已足够核对规则；要连会话一起核对，用下面的库文件。

**B. 手机上的数据库文件**
1. 库在 App 沙盒里：`Application Support/ShiziStore/shizi.sqlite`（旁边可能有 `shizi.sqlite-wal`、`shizi.sqlite-shm`，三个都要带上，放在同一个文件夹里，名字不改）。
2. 常用做法：Mac 上用 Finder 的设备页（或 Xcode › Window › Devices and Simulators 选中 拾字 › 下载容器）把 App 容器拷下来，再从容器里取这三个文件。
3. 只拷副本，不要在手机上或原文件上做任何操作；工具只读输入文件。

## 二、命令

```sh
# 先确认 Swift 命令行已编好（没编会报错并退出码 2）
swift build -c release --package-path ios/ShiziCore

# 备份 JSON 或库文件（工具自己判断是哪一种）
node scripts/dual-read/run.mjs ~/Desktop/拾字备份-2026-10-30.json
node scripts/dual-read/run.mjs ~/Desktop/shizi.sqlite
```

可选项：`--seeds 50 --steps 200`（回放的序列数与每条步数，缺省即此值；合成数据约 2 分钟，数据越大越慢）、`--tz Asia/Shanghai`（时区，缺省上海）、`--now 2026-10-30T12:00:00Z`（回放用的时钟，缺省 = 数据里最晚的记录时间 + 1 小时）、`--no-replay`（只比载入，不回放）、`--keep`（成功也保留脱敏副本）、`--swift-bin <path>`。

门禁（合成数据，两种输入各跑一遍）：

```sh
node scripts/dual-read/run.mjs --self-test            # 每种输入 6 条 × 100 步，约 30 秒
node scripts/dual-read/run.mjs --self-test --seeds 50 --steps 200   # 满量
```

退出码：0 = A == B 且回放 0 差异；1 = 有差异；2 = 环境问题（没编命令行、输入读不了）。

## 三、它做了什么、输出怎么看

1. **脱敏**（`anonymize.mjs`）：把输入复制到 `os.tmpdir()/shizi-dual-read-*`（权限 0700），只在副本上改。
2. **载入**：副本交给两个引擎——JS 参考实现（`lib/js-engine.mjs` 里的真 store）与 `shizi-core-cli`（Swift 的 `Store` + 原生镜像后端，与 App 同一份键表）。库文件形态下，两边都是「磁盘上已有这些键，启动即 `load`」（含启动修复、墨迹 schema 迁移），与 App 冷启动同一条路径；备份形态下是「空库 + 恢复这份备份」。
3. **A == B**：载入后的**整份状态快照**（全部域、磁盘每个键的原始字串、状态句、启动修复报告、序号）经 `core-diff/lib/compare.mjs` 比对，值相等之外还要逐字节相同。
4. **回放**：以这份状态为起点，按种子生成随机操作序列（`core-diff/lib/gen.mjs` 的 store 域生成器，记录引用与月份取自真实状态），包含提交（判断 / 写墨 / 改设置 / 会话 / 预算修剪 / 坏形状 / 抛错）、重启、写失败与撞配额注入、恢复备份 / 清空 / 撤销 / 导出、v1 迁移启动等；每一步都比回包与整份状态。失败自动缩小到最短序列（`runner.mjs` 的 `shrink`）。
   纯函数类 op（与已有库无关）和会替换整库的 op（`store.open / seed / close`）不进回放。

输出示例（节选）：

```text
脱敏副本：/var/folders/…/shizi-dual-read-AbC123（sqlite；替换图片 1 处、报告字串 3 个，涉及 2 个键）
读入 1271 个键；时钟 2026-10-07T04:00:00.000Z，时区 Asia/Shanghai
各域计数：
  records月份：14   records条数：2125   折叠月：3   折叠月保留条数：39
  sched条数：39     ink条数：1245       custom自加字：2   wordOff：1
  settings键数：4   photos：1           legacy：1   进行中会话：0   funnel键数：0   保护副本：1   serial：2456
库状态：available=true blocked=no；启动修复：残留事务 none，隔离坏值 0，未知键 0，清掉 0
A == B（整份状态逐字节相同：JS 读 = Swift 读）
回放：50 条序列 × 200 步，共 10000 步，每步比回包与整份状态，0 差异（… 秒）
```

怎么读：
- **各域计数**先和自己的印象对一下（记录条数、折叠了几个月、墨迹条数）——数量对不上说明读入有丢失，即使 A == B（两边同样丢）。`records条数` 不含折叠月；折叠月里保留下来的条数单列。
- **库状态**里「隔离坏值 / 未知键 / 清掉」非 0，说明真实库里有坏值或旧键被启动修复处理了；两边处理得一样才算过，数量本身是信息，不是失败。
- **`A ≠ B：载入第 n 步 <kind> <path>`**：只给差异类型与路径（`value` 值不同、`encoding` 值相同但字节不同，路径如 `$.state.store.state.records.2026-10[3].help`）。路径指向哪个域哪个月哪一条，回头在**原始数据**里自己查，工具不打印值。
- **回放不同**：打印种子、缩小后的步骤（只有 op 名）、首个差异路径，并把复现文件写在临时文件夹（含脱敏副本，所以不会自动删，见下）。复现：`node scripts/core-diff/run.mjs --a js --b swift --replay <复现文件>`。
- 载入阶段两边一致地失败（例如库被判定损坏）会提示「两边一致，但库没能读进来」，不继续回放；这也是值得看的结果。

## 四、隐私说明

- 数据只在本机处理，工具不联网、不上传、不写日志文件。
- **先脱敏再读**：所有读取都发生在 `os.tmpdir()/shizi-dual-read-*` 里的副本上，输入文件只读不改；工具不会写临时文件夹以外的任何位置（成功时临时文件夹自动删除）。
- 被替换的内容（同长度占位符）：
  - 所有图片数据 `data:image/…;base64,…`（照片域、v1 抓拍、保护副本里的拷贝）；
  - `legacy.report`（v1 导入报告，自由结构）里所有字符串值，键名保留。
  - 按形状表，其余域没有自由文字：自加字 `custom` 只有单个汉字与时间，设置是固定枚举 / 开关，会话与调度是卡键与数字——这些正是要比的内容，**保持原样**。所以脱敏副本仍然带着「你练过哪些字、哪天练的、墨迹笔画」，不要把副本或复现文件发给别人；用完删掉。
- 控制台只打印计数与差异路径，不打印任何记录内容。差异路径里会出现月份、记录序号、字的键（如 `base:永`），不含笔画与文字内容。
- 失败时临时文件夹会保留（里面有脱敏副本与复现文件）；`--keep` 同理。路径会打印出来，核对完请 `rm -rf` 掉。
- 备份或库文件本身是你的私人数据：从手机拷出来的原文件放在哪由你自己管，用完也建议删除。
