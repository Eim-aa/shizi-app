## 5. 风险与未决问题

1. **Release 里仍在调引擎的代码路径**：B4.5a 尚未把 SwiftEngine 接进 App（`NativeStage.engine` 仍是 `WebEngine`，所有页面 API 都经 WKWebView）。B4.9 的启动条件（B4.8 + 负责人测试通过）没满足前**不能**开始删；否则 Release 无引擎可退，等于砍掉 §4.5 第 2 条的回退方案。
2. **D59 ④：网页构建（GitHub Pages / PWA）去留未决**。所以本卡把「仓库删文件」拆成 `--apply`（只删包内不再需要的）与 `--apply --web-retired`（连网页构建输入一起删）两档；`src/` **仓库不删**（§4.5 第 5 条冻结保留一个版本周期）。网页 e2e 130 spec、`verify:pwa/web/sw-unit/webkit-ax`、`verify_assets` 都还挂在缺省链上，随这个决定一并处置。
3. **声音与判断声轮换**：原生播放器读包内 `Web/assets/sound`（WebViewController.swift:978）；判断声 j1 轮换的规则在引擎侧 `installCommitFeedback`（B3Zf-1，`src/platform/haptics.js` / `src/ui/engine.js`）——删引擎后「第几个判断放哪个变体」的知识随之消失，必须确认原生写字页 / 结果页已全责发声（B3Zf-1 已补写字页 j1 轮换、结果页 s1 原生已有），否则 B4.9 会静默丢声音。窗口根更换时播放器搬迁是第 2 步的硬前提。
4. **`Web/` 目录本身不能整删**：原生在读 `Web/fonts`（NativeType.swift:306、ShiziScreen.swift:36）与 `Web/assets/sound`（WebViewController.swift:978）。B4.9 删的是 `Web/` 下的 `src/`、`vendor/` 与壳文件；若想连目录一起去掉，要先改这两处读取路径（可顺手把 fonts/sound 挪出 `Web/`，但那是额外改动，不属机械步骤）。`fonts/fonts.css`、`fonts/coverage-manifest.json`、`assets/branding/*.svg` 仅网页用，出包与否随 D59 ④ 一并定（合计 <0.1 MiB，不影响体积结论）。
5. **localStorage 未迁完的设备**：§4.4 明确「Swift 版遇到未迁完标记时先用 WebEngine 跑完迁移再切，**B4.9 前保留**」。B4.9 删 WebEngine 后这个兜底就没了——需要负责人定：确认线上设备已全部跑过 B4.x（迁移完成率 100%）、或 B4.9 前给 Swift 补一个 v1 localStorage 一次性导入、或接受未迁完设备走迁移阻断页（会丢旧记录入口）。
6. **QA-H1 参考图（84.14 MiB / 1,384 文件）依赖网页构建重取**（`capture.mjs --update-reference`）。停跑 spec ≠ 可删网页；第 8 步删网页输入前要确认参考图已冻结、不再重取（B3Z §5.2），否则逐屏对比从此失去标准答案。
7. **宿主测试的改写量**：`NativeStageTests / ShiziKitTests / NativeJudgeTests / NativeAnswerSkipTests` 都经页面驱动（等 `shiziNativeWrite` 就绪、读 tokens.css）。若 B4.8 没把 SwiftEngine 宿主做完，B4.9 卡内要同时背「换宿主」与「删引擎」两件事；建议 B4.8 收口时顺带把这批用例的宿主切过去，B4.9 就只剩删除。
