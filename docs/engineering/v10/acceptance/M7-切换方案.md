**C9 说明（开发代理在 M7 发现）**：GitHub Pages 从 `main` 根目录按分支发布时默认经 Jekyll 构建，Jekyll 不发布以 `_` 开头的目录。`src/ui/screens/_demo/sub.js` 在 `sw-manifest.js` 的核心壳列表里（核心壳 `Cache.addAll` 原子预缓存，任何一项 404 = 安装失败），所以没有 `.nojekyll` 时线上 v14 worker 会装不上：新用户没有离线能力，旧用户停在 v13 worker 下。M7 工作区已在仓库根加空文件 `.nojekyll`（让 Pages 原样发布静态文件）；所有者也可以改为把 `_demo` 移出壳清单或改名，但必须二选一后再合入。另外 `docs/engineering/v10/reference/` 里有 `{{ }}` 字样，Jekyll 处理 Markdown 时会当成 Liquid——有 `.nojekyll` 后不再处理。

## 3. 合入方式

- 用 **merge commit**（不要 squash / rebase）：保留 59 个提交的历史与各验收记录引用的 SHA，回退时可以 `git revert -m 1 <merge>` 一步还原。
- 合入即发布：Pages 一般一两分钟内生效（Actions 里的 `pages build and deployment`）。
- iOS：App 版本另走 TestFlight（`archive-testflight.sh`），与 Web 发布不必同时；新 App 构建同样会在首次启动时迁移 WKWebView 里的 v1 数据。

## 5. 回退

**做法**：在 `main` 上 `git revert -m 1 <merge-commit>` 并推送（新提交，**不 force-push**）。文件树回到 `639f592`，Pages 重新发布旧版。若在合入前就要放弃，只需不合并。

**旧版能看到什么**（回退窗口 = 迁移后 30 天，或用户完成一次 v2 导出，先到者；03 P53）：

- 窗口内：v1 键除 `shizi.session.v1`、`shizi.safety.v1` 外都在，旧版读到的是**迁移那一刻**的数据；新版里新写的记录在 `shizi.v2.*`，旧版看不到。未写完的旧会话（session v3）已随 `shizi.session.v1` 删除。
- 窗口外（或用户导出过一次 v2 备份）：v1 键已删，旧版看起来像新用户；数据仍完整保存在 `shizi.v2.*`，再切回新版即恢复。
- **v2 键不影响旧版**：旧版按固定键表读写、备份与清空（`BACKUP_KEYS`），不读也不改 `shizi.v2.*`；只是两套键同时占用 localStorage 配额（v2 预算 ≤ 3.2MiB），旧版更早碰到配额上限的可能性存在（旧版有配额失败提示）。
- **v2 备份文件不能导入旧版**（旧版只认 v1 键名，会报空备份）。回退期间需要恢复的用户只能用 v1 备份。

**再次前进时**：`shizi.v2.meta` 已存在 → 不再迁移，只做旧键回收。回退期间在旧版里新写的 v1 数据**不会**并入 v2，并会在窗口到期时随 v1 键删除。回退若超过几天，再次发布前需要所有者决定：接受这部分丢失，或先补一张「回退后增量再迁移」的工程卡。

**Service Worker**：旧 v13 `sw.js` 字节不同 → 浏览器安装旧 worker；它 `skipWaiting` + `clients.claim`，激活时删除所有非本版本的 `shizi-` 缓存（含 `shizi-v14-*`）。已打开的新版页面在下次导航时拿到旧版 HTML。此路径没有自动化回放（`verify:pwa` 只测旧 → 新），见 C10。

**iOS**：TestFlight / App Store 的回退是重新分发旧构建；数据行为与上面相同（同一个 WKWebView 数据存储）。
