# 拾字 · 第二轮设计审查 A2：包容与平台

视角：系统字号（xS…AX5 矩阵）、读屏语义、对比度、减少动态效果、色觉、触控目标、小屏 / 大屏、纸上写替代路径、平台契合。
证据：v1 = `.review/corpus/`（6fb6419）；v2 = `.review/corpus-v2/`（8adadfa，iOS 26.5 模拟器原生 App），下文 `v1:NNN` / `v2:NNN` 是两库的图号。源码按当前分支 HEAD 517f14d 阅读（证据库之后只多了声音，与本视角相关的部分没有变化）。
另外两类证据，都**不是真机结果**：
- 在桌面 Chromium 打开 `127.0.0.1:8872/?test=1`（402×874 与 375×667），用 Playwright 读无障碍树、模拟读屏状态和系统字号。读屏状态用 `shiziAccessibilityStatus({voiceOver:true})`，系统字号用 `shiziContentSize({category:'AX5'})`。
- 对比度按 `src/config/tokens.css` 的令牌，用 WCAG 2.x 公式算。色觉用 Machado 2009 重度矩阵模拟。提示笔画一项另外从 v2:219 / 220 的像素直接取色复算。

## 1. 结论

**本轮分数：5 / 10。上一轮：3 / 10。**
刻度和上一轮相同：1 = 核心任务对多数辅助技术用户不可用、平台控件全是仿制；3 = Web 语义比一般网页认真，但核心任务只服务「视力好、手稳、用手指」的人；5 = 达到 HIG 基本要求的合格 App；7 = 编辑推荐级打磨；8 = ADA 入围；9–10 = 获奖。

**涨了 2 分，原因如下：**
- 上一轮的四个 S1 里，有两个在网页阶段已经真正修好：
  - 系统字号：原生桥加 AX 分级字阶（v1:477 与默认像素级一致，v2:762 → 649 逐档变化）。
  - 书写格与字号脱钩：Pro Max 上 400pt，大字号下不再缩小。
- 另外两个有了实质进展：
  - 「在纸上写」替代路径，读屏 / 切换控制开启时会主动建议。
  - 判断页、题面空格有了读屏名称。
- 对比度令牌全部重算，控件边界和最淡墨色都 ≥ 3:1；中文本地化、启动底色、状态栏遮罩、假把手、撤销时长这些都落地了。

**还拿不到 6 分**，因为有三处会被评审当场看到：
1. AX 档的写字页上，书写格被底栏盖住（SE3 AX5 只露出约 55%）。
2. 提示笔画和压暗后的本人笔迹，对比度比 v1 还低（深色 1.10:1）。
3. AX5 下「我的」和练习记录的日历叠字。

**离 ADA 最大的三个差距：**
1. 【网页阶段现在就能修】**AX 档没有为「写字」单独设计版式。** 字阶放大了，但书写格、题面、底栏的取舍没有做：拼音和「3 / 5」放到 49pt，比题面汉字还大；底栏四个文字按钮各占一行；格子只能滚动才看得全。
2. 【网页可修 + 阶段 2】**读屏下的核心循环仍然「能走、不能用」。**
   - 书写格写了几笔不播报，提示画了什么也不播报。
   - 弹层没有可见的关闭按钮。
   - 参考字形只读「尴，gān，13 画」，没有结构和部件，盲人用户仍然无从对照。
   - 直通书写和逐笔播报要等阶段 2 的原生书写面。
3. 【阶段 2/3】**平台层面一眼还是网页。**
   - 键盘上方有 WebKit 的 ↑↓✓ 附件条，时间选择器是 WebKit 滚轮。
   - 不能长按查询一个字，轻点状态栏不回顶。
   - Tab 栏固定 11pt，又没有大内容查看器（Large Content Viewer）。
   - 粗体文本、智能反转、降低透明度都不生效。
   - 不支持 iPad / Pencil，没有小组件。
   - 这些都已经排进路线（D26/D32/D35），本轮不重复扣分，但它们是 8 分以上的门槛。

### A2-01 AX 档写字页：书写格被底栏盖住，撤销 / 清空 / 在纸上写落到折叠线以下 — **S1**
- **页面/状态**：写字页回忆（首练、续写）、看答案、自己写一遍；系统字号 AX3–AX5；SE3 与 iPhone 17。
- **证据**：
  - v2:652 / 646（SE3 AX5）：327pt 的格子只露出上面约 180pt，底栏顶部的分隔线横穿格子。
  - v2:666 / 660（iPhone 17 AX5）：格子底边约 13% 被盖住，格下的撤销 / 清空看不到。
  - v2:1180（看答案 AX5）：答案字「张」被说明句盖住一半。
  - Chromium 复现（375×667，AX5）：
    - 格子 y = 201–534，底栏顶 y = 413，有 121px（约 37%）在底栏下面；
    - `.sz-page__body` 可以滚动（641 / 343）；
    - 格下工具行在 y = 535–575，完全不可见。
  - 源码：`src/ui/screens/write/layout.js:4-6`（「AX 档放不下时整页滚动，不缩格子」）；`src/ui/components/ax.js:35-41`（底栏只改成上下排）；`src/config/tokens.css:160`（AX5 下 fs15 = 49px，拼音和「3 / 5」都用这一级）。
- **问题**：
  - 不缩格子是对的（D36），但 AX 档用滚动兜底，在写字页行不通：
    - 书写格是 `touch-action:none`，手放在格子上没法滚，只能拖题面那一小块；
    - 滚下去以后题面（拼音和空格）就离开了屏幕，用户写的时候看不到题；
    - 不滚的话格子下部被按钮盖住，写不到下半个字；
    - 撤销、清空，以及给读屏和运动障碍用户准备的「在纸上写」入口，都在折叠线以下。
  - 底栏在 AX5 下高约 250pt：「写好了」88pt，「提示 / 看答案」一行，「跳过」单独一行，每个都是 53pt 字。
  - 1180 / 1186 的按钮文字逐字折行，见 A2-11。
- **为何重要**：
  - ADA Inclusivity：最需要大字的人，恰好在核心任务上被挡住；
  - HIG《Typography》要求放大文字时优先保证主要内容可见；
  - 品味清单「一屏一个焦点」：AX5 写字页的焦点变成了按钮文字，而不是格子。
- **网页阶段可修**。
- **获奖级目标做法**：写字流程要有一套**AX 专属版式**，不只是放大字阶。
  1. 写字页**永不滚动**。格子边长 = min(屏宽 − 40, 实际可用高)，下限从 258 降到约 220pt（SE3 AX5 能放下）。理由：格子小一点，但完整可见、可写，好过大格子被遮住一块。
  2. 拼音、进度这类辅助信息在 AX 档封顶：拼音 ≤ 28pt，进度 ≤ 22pt，或者进度只留给读屏。
  3. 底栏在 AX 档只留「写好了」加一个「⋯」：提示、看答案、跳过、在纸上写收进菜单，菜单项按 AX 字号竖排。
  4. 撤销 / 清空在 AX 档挪到页头右侧（图标 28pt），保证永远在首屏。
  5. 看答案页的答案字形永远不被说明盖住：说明折叠到「ⓘ」或放在格子上方。
- **改动范围**：样式 + 写字页组件布局规则（`layout.js`、`ax.js`、`write/index.js`、`answer.js`）。

### A2-02 提示笔画和压暗的本人笔迹几乎分不开（比 v1 还差）— **S2（回退）**
- **页面/状态**：写字页点「提示」后，浅色与深色。
- **证据**：
  - v2:219 / 220。像素实测（WCAG 对比度）：
    - 浅色：提示 rgb(196,120,99) 对笔迹 rgb(172,168,162) = **1.43:1**；
    - 深色：提示 rgb(158,88,69) 对笔迹 rgb(107,100,89) = **1.10:1**；
    - 红色盲模拟下深色 **1.03:1**，绿色盲 1.18:1。
  - v1 同状态（v1:65 / 66）是 2.54 / 1.92。
  - 原因有两条：
    - `src/ui/screens/write/hint-layer.js:53` `INK_DIM_OPACITY = 0.35` 仍在用，提示时本人笔迹还是压到 35%。D34 定的是「提示保持本人笔迹不变暗」，网页没有跟上。
    - 淡朱令牌变浅了（`--danzhu` 浅 #C06D57、深 #A85C48）。
  - 单测 `test/ui/contrast.test.mjs:52` 只核对 `danzhu/hand`（未压暗时 4.43 / 3.54），**量的是不会出现在屏幕上的一对颜色**，所以没拦住这次回退。
  - 说明文案「浅红色是提示」（`copy/write.js:25`）仍然只用颜色指认。在深色下淡朱其实比笔迹还暗，「浅」字也不对。
- **问题**：深色模式下，红绿色觉异常的用户（约 8% 男性）看不出哪条是提示，现在只剩线宽能区分。普通视力的人在深色下也要细看才分得开。
- **为何重要**：WCAG 1.4.1 / 1.4.11 / 1.3.3；HIG《Color》要求不只靠颜色传达信息；ADA Inclusivity。
- **网页阶段可修**（完整的淡朱实心笔画和贴合属阶段 2，但不压暗今天就能做）。
- **获奖级目标做法**：
  1. 立即把 `INK_DIM_OPACITY` 改为 1，按 D34 不压暗。如果设计上一定要压，至少 0.7，并保证提示对压暗后的笔迹 ≥ 3:1。
  2. 提示笔画加第二通道：常驻 1pt `ink3` 外廓（现在只在增强对比度时才有），或者起笔处加墨点、带方向。
  3. 单测改为核对「提示 × 压暗后的本人笔迹 × 笺面」的合成色，并在三种色觉模拟下都 ≥ 3:1。
  4. 说明文案改成「细笔是提示」或「起笔有点的是提示」。
- **改动范围**：一个常量 + 令牌 / 单测 + 文案。

- **网页阶段可修**。
- **获奖级目标做法**：
  - AX 档月历改成按天的列表（「10 月 3 日 · 记了 5 个字」），或者每行 7 格、日期取 min(字号, 格宽 × 0.45)；
  - 字帖角标在 AX 档不显示，日期进读屏名称；
  - 周条改成「本周写了 5 天」一句话；
  - 区块标题与右侧链接在 AX 档上下排。
- **改动范围**：样式 + 两三个组件的 AX 分支。

### A2-04 AX 档题面层级倒置：拼音和进度比要回忆的汉字还大 — **S2**
- **页面/状态**：写字页 / 判断页题面，AX3–AX5（v2:666、646、657、1180）。
- **证据**：
  - `src/ui/screens/write/prompt.js:104-105`：题面格从 52px 只放到 64px，字形占格 80%（约 51pt）；
  - 拼音用 fs15，在 AX5 是 49px；
  - 进度「3 / 5」也用 fs15。
  - 666 上「zhāng」比「主」还醒目。
- **问题**：题面汉字（「主□」里的「主」）是回忆的线索，低视力用户最需要看清它，却几乎没放大；拼音这类辅助信息却放大了三倍多。
- **为何重要**：设计系统「楷只写字本身、字是主角」；HIG 要求按层级放大，正文与标题放大比例不同。
- **网页阶段可修**。
- **获奖级目标做法**：
  - 题面格按 AX 等级放大：AX1 72 → AX5 约 96pt，词语放不下时折成两行；
  - 拼音封顶 28pt；
  - 进度封顶 22pt，或在 AX 档隐藏，只留读屏名称。
- **改动范围**：样式。

### A2-05 弹层没有可见的关闭按钮；XXXL 下查字弹层顶到屏幕上缘，遮罩看不见 — **S2（读屏可达性要真机定级，可能升 S1）**
- **页面/状态**：查字 / 自己选字弹层，以及其他没有「完成」按钮的弹层。
- **证据**：
  - v2:1118 / 1120（XXXL）：弹层标题「查字」和上方遮罩都不在屏内，输入框紧贴灵动岛，屏幕上没有任何「关闭」入口；
  - v2:319（L 档）：同样只能点遮罩关闭。
  - `src/ui/components/Sheet.js:84-95`：
    - 遮罩 `aria-hidden` 且只是一个 `div`；
    - 面板 `aria-modal="true"`；
    - 组件里没有关闭按钮，只能靠点遮罩、系统返回、Esc。
- **问题**：
  - 视力正常的用户在 XXXL 下找不到出口，只能碰运气用左缘右滑。
  - 读屏用户被 `aria-modal` 限制在面板内，又摸不到遮罩，只能依赖 VoiceOver 的「两指 Z 形」退出手势。WKWebView 会不会把它转成网页的 Esc，没有验证过，我倾向于不会。
- **为何重要**：HIG《Sheets》要求弹层有明确的关闭 / 完成；WCAG 2.1.2（无键盘陷阱）的读屏对应项。
- **网页阶段可修**（阶段 3 由原生 Sheet 自然获得）。
- **获奖级目标做法**：
  - 所有弹层标题行右侧加「完成」文字按钮（44pt）；
  - 弹层最大高度按可视视口算，保证顶部始终留出遮罩；
  - 原生壳实现 `accessibilityPerformEscape`，转发给网页的 Esc。
- **改动范围**：组件 + 原生壳一个方法。

### A2-06 书写格和提示对读屏仍然沉默 — **S2**
- **页面/状态**：写字页回忆、提示、描一遍、自己写一遍。
- **证据**：
  - Chromium 无障碍树：写 3 笔前后都只有 `img "书写格"`（`src/config/copy/write.js:87`，`ink-canvas.js:436-437`）；
  - 提示层宿主 `aria-hidden`（`hint-layer.js:20`），点「提示」后读屏只知道按钮名称从「提示，还有 2 次」变成「还有 1 次」，不知道提示画了什么；
  - 描一遍完成几笔也不播报。
- **问题**：纸上写解决了「怎么写」，但仍然想在屏幕上写的低视力用户、用直通手势写的读屏用户，完全得不到反馈。
- **为何重要**：ADA Inclusivity；HIG《VoiceOver》要求状态变化要有播报。
- **一半网页阶段可修，一半阶段 2**：
  - 网页现在就能做：
    - 书写格名称随笔数更新（「书写格，已写 3 笔」）；
    - 每次抬笔后用 `aria-live=polite` 节流播报「第 3 笔」；
    - 撤销 / 清空后播报「撤销了一笔，还有 2 笔」；
    - 提示出现时播报「提示画出了第 4 到第 5 笔」；
    - 描一遍时播报「描到第 6 笔，共 13 笔」。
  - 阶段 2 原生做：`allowsDirectInteraction`、按笔画类型播报（横、竖、撇……，需要补笔画类型数据）。
- **改动范围**：文案 + 组件。

### A2-07 xS 档把最小字号缩到 9pt — **S3**

### A2-08 Tab 栏在 AX 档固定 11pt，又没有大内容查看器 — **S3**
