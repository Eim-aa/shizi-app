## 1. 结论

**本轮 4.5 / 10（上一轮 4 / 10，+0.5）。** 刻度和上一轮相同：
- 10 = 获奖作品；
- 8 = 入围水准，核心时刻有独到、可感知的手感；
- 6 = App Store 编辑推荐级，打磨完整、处处像原生；
- 4 = 逻辑周全、状态恢复可靠，但体感像「做得很好的网页原型」；
- 2 = 核心流程不顺或常出错。

**加分的原因**：阶段 0 的卫生问题基本清干净了（按压反馈、图层穿透、返回阈值、假把手、跳过撤销 5 秒），判断页改成上下两格，与书写格同顶边、同中线。这些让底子更稳。

**只加半分的原因**：
- 手里的感觉没有一项变好。墨还是记号笔，核心循环 5 个时刻仍是一帧硬切，求助梯子和 v1 一模一样（D34 没有落到网页）。
- 新出现了几处「互相打架」的问题：最后一字判断声和落款声叠在 1–2 帧内响；返回首页时 Toast 盖住「继续写字」；首次打开主按钮约 2.4s 后才出现。

**另评规格**：阶段 2 的规格（时刻编排时序表、触觉表、笔锋模型 1.0 + 20 条金标准向量）已经接近获奖级，按规格质量我给 7.5 / 10。但承担最大风险的原生书写面 spike（P1-S2）和真机测量 T1 都还没做。

**离 ADA 最大的三个差距**：
1. **墨与跟手**（阶段 2）：
   - 现在的笔迹仍是等宽圆头（`025`，真实触摸）。
   - 120Hz、延迟、掌托都没有测过，也没有 spike。
   - 规格已经到位，但「原生能否写出这种墨」还没有任何证据。
2. **核心循环硬切**：
   - 网页阶段现在就能修：交接 §0.4 约定的「150ms 交叉淡化 + 看得见的就绪 + 落款延后」一项都没做。
   - 完整编排属阶段 2。
3. **求助梯子仍是旧版**：
   - 网页阶段现在就能修：每次看答案都弹居中确认框；确认后本人笔迹被清空；提示把本人墨压到 35%，提示本身是一根中线铁丝；答案要逐笔播 4–8s。
   - 拟合、逐笔描到属阶段 2。

## 3. 新问题清单

### I2-01 阶段切换仍是一帧硬切；交接约定的 150ms 过渡和「看得见的就绪」没做　S2（网页阶段可修）

- **页面 / 状态**：写好了→对照、接着写←、判断→下一字、看答案→答案卡、答案→描一遍→自己写→下一个。
- **证据**：
  - `796→797`：书写格在 33ms 内变成上格；参考字 133–167ms 才淡入。
  - `806→807`、`843→844`、`826→827`、`962→963`、`818→819`。
  - 〔桌面 Chromium 实测〕阶段切换发生在第一帧；参考格透明度 0（0–115ms）→ 1（380ms），即 `compare.js:80` 的 `.26s .12s` 加 translateY 8px。
  - 判断两键从第一帧起就是 100%，但 0.4s 内点了无效（`Button.js:14`）。
  - 换字后 0.3s 的落笔被静默丢弃（`ink-canvas.js:220`）。
- **问题**：`实现交接.md` §0.4 写明网页阶段「页面状态之间一律用 150ms 交叉淡化（即『减少动态效果』版本，终态逐像素相同）」，现在没有任何一处这样做。更糟的是现存的唯一一段动效（参考格从下往上 8px 滑入）不在任何规格里：v2 设计已把上下两格设为「纯缩放、不平移」，这 8px 的位移正好和规格的空间语言相反。
- **为何重要**：品味清单 G1（关键时刻硬切）、G2；HIG Motion（表达状态变化）；上一轮 I02。网页阶段可能还要活 10–14 周，评审、TestFlight 测试者、T3 首用测试看到的都是它。
- **获奖级做法（网页阶段，不扩大 D46 授权）**：
  1. 写字页内做一层「阶段容器」：旧状态快照 150ms 线性淡出，新状态在下面淡入，终态与现在逐像素相同。去掉参考格的 translateY。
  2. 判断两键：0–320ms 不显示；320ms 以 60% 出现，`pointer-events:none`；440ms 变实可点，取代看不见的 0.4s。数值取 `moments.js` M1。
  3. 换字：250ms 起接受落笔（M3）。250ms 前的落笔**缓存，不丢**：动画瞬间收尾后照常画出。
  4. 减少动态效果时全部 0ms，触觉照发。
- **改动范围**：组件（`write/index.js` 加阶段容器；`compare.js` 两键、`ink-canvas.js` 落笔缓存）。约 2–3 天。阶段 2 的原生编排不受影响，`moments.js` 仍是验收基准。

### I2-02 求助梯子仍是 v1：每次确认框、清空本人笔迹、压暗本人墨、中线铁丝、答案逐笔播 4–8s　S1（拿奖硬伤；静态部分网页阶段可修，拟合和逐笔描到属阶段 2）

- **页面 / 状态**：回忆→提示；回忆→看答案→答案卡→描一遍→自己写。
- **证据**：`055`、`1102`（居中确认框加全屏遮罩）；`843→844`（确认后本人笔迹清空）；`037`（答案独占整格，标题换成「这个字这样写」）；`219`、`221`（本人墨压到 35% 灰，提示是 18/1024 宽的中线，画在标准位置，说明句点名「浅红色」）；`835–842`（描红前笔顺 2.8s）。源码：`answer.js:457-477`（Confirm）、`answer.js:6-9`（确认 commit 时「笔画清空」）、`answer.js:350`（`mode:'play'`，答案卡没有点按跳过）、`hint-layer.js:52-53,431-445`（INK_DIM_OPACITY 0.35）、`policy.js` `motion.answerSpeed 1.6 / answerStrokeGapMs 180`。
- **问题**：
  - D34（2026-10-03 已定）和交接 §0.4 给网页阶段的落地方式是：提示画在标准位置、danzhu 实心、带起笔点、本人墨不变暗；看答案只第一次说明，答案用 `under` 画在本人墨下层。这些都是静态的，网页一天之内就能做，现在一项都没做。
  - 用户每天在这里求助几次：每次都要过一个模态框，每次都失去「我写对了左半边」的那一刻，然后再等 4–8 秒看一段不能跳过的笔顺。
- **为何重要**：
  - HIG Alerts（常规操作不用警告框）。
  - 品味清单 F2「没有为预期之中的操作弹确认框」、C3「本人笔迹是屏上对比度最高的墨」（提示态把它压成最浅的灰，直接违反）、E1。
  - iA Writer 的一课：本人的最亮，外来的变暗。现在正好反过来。
  - ADA Interaction、Inclusivity：求助应当低成本、不羞辱。
- **获奖级做法**：
  - **网页阶段（M，约 3–4 天）**：
    1. 去掉 `openAnswerConfirm`。第一次点「看答案」时，格下说明位出现一块凹面说明（沿用 R-W07 两句），旁边一个「知道了」。以后点了直接看。
    2. 答案态不换卡：答案用 `under` 色画在本人墨**下层**，本人墨 100% 保持；400ms 透明度显影；不播笔顺。
    3. 提示：轮廓实心 `danzhu`（不是中线）+ 起笔点；本人墨不变暗；整组 150ms 淡入；格下说明改为「提示只给几笔，照着写，写过的那笔就收起。」（不再指认颜色）。
    4. 描一遍前的笔顺快放总长 ≤1.6s，按 D46-17 每字只在第一次播，落笔即跳过。答案卡如果保留逐笔，点任意处一帧到终态。
  - **阶段 2**：拟合（`fitHint`）、逐笔描到填墨、答案在墨下的显影动画，按 `moments.js` M4*。
- **改动范围**：组件（`answer.js`、`hint-layer.js`、`glyph.js` 动画参数）、文案（R-W06、R-W07、R-W08）。

### I2-04 返回首页时「已保存，下次接着写」Toast 盖住「继续写字」3.2 秒　S2（网页阶段可修）

### I2-09 退场为 0、动效没有令牌：时长和曲线散落各处　S3（网页阶段可修）

- **证据**：
  - 全仓入场动画：Sheet 280ms、Confirm 200ms、Toast 200ms、compare 260ms + 120ms、invite 300ms + 8px、图片 150ms、品牌 200ms，以及提示 240/260/120ms。曲线有 `(.2,.7,.2,1)`、`ease-out`、`(.4,0,.2,1)`、`linear` 等。
  - 退场 0 个：Toast 到期从 DOM 上直接消失（`Toast.js`），`UndoBar`、`Sheet`、`Confirm` 同样一帧消失。
  - `tokens.json` 的 motion 只有 press、release、easeOut 三项。减少动态效果的淡化时长：tokens 写 120ms，时刻规格写 150ms，`policy.motion.reducedFadeMs` 是 120，三处不一致。
- **为何重要**：ADA V&G「high-quality animations」「cohesive」；上一轮 I18。动效没有体系，阶段 2 的原生实现就没有可以对齐的「网页基准」。

- **改动范围**：设计系统 + 样式。

### I2-10 落款声在冷启动恢复到结果页时会再响一次　S3（网页阶段可修）

### I2-11 时刻规格的四处缺口与一处取舍值得重议　S2（阶段 2，规格层面，现在就该改稿）

`README-时刻与求助.md` 与 `moments.js` 整体已经是获奖级的规格：
- 时序是唯一数据源，可导出成 JSON 作为验收基准；
- 打断规则统一；
- 触觉挂在关键帧上；
- 减少动态效果有对等版本。

但开工前应补齐下面几处：

1. **「收进计数」与产品气质冲突。**
   - 现状：② 让本人墨飞进右上角的「3 / 5」，到达时数字翻动。拾字明确不做计数和打卡（D01、D02、D49-7 把首页计数都删了），全流程最有仪式感的一下，却是把墨「收进一个数字」。
   - 建议：把页头的「3 / 5」换成 5 个 14pt 的小帖格（已写的格里是本人墨的缩影，当前格只画框）。② 的落点就是本字那一格；⑤「归位成帖」就是这 5 格放大、落到结果页作品格。这样进度、收字、成帖是同一个物件，「拾」在交互上真正兑现，也符合品味清单 H3（格是贯穿母题）。
   - 读屏仍读「第 3 个，共 5 个」。
2. **触觉密度。**② 每字两次触觉（离纸 medium + 到达 Selection），一组 15 字就是 30 次，再加提示、描到每笔一次。建议每字只留一次，放在「到达帖格」那一帧：那是看得见的落点。离纸只给声音。T10 用这个作默认，再测加法。
3. **失败路径没有编排。**② 在第 0 帧墨就离纸，如果 commit 失败（配额、写入异常，现有三段式 `1023`），墨要不要飞回？规格没有写。建议：原生 SQLite 写入是同步的，**先 commit，成功再起飞**（增加 <5ms）；失败时墨不动，按钮行就地换成三段式。
4. **没有覆盖的高频动作**：
   - 撤销一笔（建议 140ms 淡出加收缩 2%）、清空（倒序 220ms）；
   - 写字页的左缘返回：上一轮 I10，规格应写明「格外起始的边缘手势放行、正在书写时拒绝」；
   - 判断页「‹ 接着写」的倒放（M1 已写 280ms，需在交接表列出）。
5. **触觉参数两处不一致**：时刻 README §4.2 写判断 Impact medium 0.7、落印 rigid 0.8；D50 ⑦ 写判断 soft 0.6–0.7。阶段 2 开工前定一个。

- **为何重要**：阶段 2 是 10–14 周的原生投入，规格里的缺口会直接变成返工。第 1 条关系到「拾字为什么是拾字」这一 ADA 评审最看重的独特性。
- **改动范围**：设计稿（`moments.js` M23、M5 落点，`scene.js`）；决定（第 1、2 条需产品负责人确认）。

## 5. 证据缺口（只能真机 / 真人验证）

1. **WKWebView 真机的按压反馈**：`data-pressed` 在 iOS WebKit 上 1–2 帧内出现（240fps 录屏）。本轮只在桌面 Chromium 实测到。
2. **点按→推入首帧的延迟**：〔桌面 Chromium 实测〕从「开始写字」点击到写字页第一帧约 130ms。真机若更长，需查是不是模块懒加载或 0.4s 防连点所致（需真机加 Web Inspector）。
