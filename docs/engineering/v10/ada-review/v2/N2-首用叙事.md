# 拾字 · 第二轮设计审查 N2：首用与情感叙事

- 视角：35 岁上班族，会写字，常提笔忘字，第一次打开。按 v2 证据走一遍：首次打开 → 首练「尴 赢 拾」→ 首练结果页与提醒邀请 → 第二天 → 一个月后的字库、月字帖、年报和分享。
- 证据：v2 = `.review/corpus-v2/`（提交 8adadfa，下文只写编号）；v1 = `.review/corpus/`（提交 6fb6419，写作「v1 编号」）。源码按当前 HEAD 517f14d 读，它比证据库多了 S1 声音。我没有起本地服务亲手操作，所有判断都来自截图、过渡帧和源码。
- 失真（主控已说明，这里再标一次）：
  - 绝大多数墨迹是种子笔画，只有首练第 1 字是真实 touch_path。
  - 「一个月以后」那批画面（字库墙、快忘了、年报）用的 rich 种子仍然是**字频序**的字（是 在 他 这 我、的 一……），看不出 D28 易忘度排序在一个月后的样子。
  - 跨 0 点采集，两批画面里的日期和题记不同。
- 刻度沿用上一轮：
  - 1–2 分：流程走不通；
  - 3–4 分：干净、克制、能用，但没有让人记住的地方，进不了 ADA 候选；
  - 5–6 分：工艺精致，有一两个出彩时刻，可以拿 App Store 编辑推荐；
  - 7–8 分：ADA 入围，有一个清楚的核心时刻，全链路工艺一致；
  - 9–10 分：获奖，重新定义了品类，用户会主动传播。

## 1. 结论

**本轮 5 / 10，上一轮 3 / 10，进步 2 分。** 加分原因：叙事的骨架立起来了。
- 首屏第一次讲清了「为什么」（005：竖排「提笔忘字，不是忘了，只是很久没写。」逐字写出后落一方印）。
- 首练改成 3 字弧线，结果页开头是一句人话「这三个字，很多人提笔就忘。」，然后是带落款和印的作品格，每个字有「N 天后再见」（235）。
- 本人笔迹终于留下来了：字墙、首页、月字帖、年报里都是你写的字（59 / 9 / 282 / 173）。年报卷尾的「同一个字，两次」（1326）是整个 App 第一次正面拿出「我在变好」的证据。
- 提醒邀请做到了首练结束的那一刻（235）。

还没到 6 分的原因：**核心时刻仍然没有形式。** 判断落定和进结果页都是一帧硬切（806→807、812→813）。新加的落款声 s1 是在这次硬切上响的，等于有声音、没有画面。「拾回」这个名字的隐喻在整个 App 里一次也没有兑现，墨迹还是等宽圆头的记号笔线。

离 ADA 最大的三个差距：

1. **收字和落款时刻（S1）。** 完整编排属阶段 2；但网页阶段现在就能做一枚和 s1 同帧的落印，作品格依次显现，成本 S。
2. **「拾」没有成为记忆点（S1）。** 首页的大「拾」就是第三题的答案，用户亲手写下「拾」以后什么都没发生；「拾回」这个词一次都没出现；品牌「拾」仍是印刷楷体。这一条**网页阶段现在就能修**，只差书家字形。
3. **墨成了全 App 的主角，墨的质感却是最大的短板（S1）。** 阶段 2 的原生笔锋解决；网页阶段能做的只有统一各处的线宽比例。

## 3. 新问题清单

严重度：**S1** 拿奖硬伤 / **S2** 明显拉低品质 / **S3** 打磨。范围：**S** 只改文案或样式（≤2 人日）/ **M** 单页或单组件 / **L** 跨页或涉及数据。

### N2-01 · 落款声响在硬切上，作品「出现」而不是「落成」（S1）

- **页面 / 状态：** 最后一字判断 → 结果页；每次判断 → 下一字。
- **证据：**
  - 过渡帧 812→813：判断页下一帧就是完整的结果页，作品、落款、印同时出现；806→807：写错之后 33ms 就是下一个空格子。
  - 源码 `src/ui/screens/result/work.js:124–131`：s1「木印·闷实」在作品首次渲染时响，注释写明「网页阶段没有落印动画，作品出现即落款」。判断时还会播 j1（`src/ui/screens/write/index.js:229` 预载）。
- **问题：**
  - 用户听到一声闷实的盖印声，眼前的印却早就静静地在那里了。声音描述的是一个画面上没发生的动作。
  - 判断时的 j1 纸声也一样：响完以后画面直接换成下一个字，没有任何东西「落定」。
  - 首页的品牌时刻里，印是有落印动画的（`src/ui/screens/home/index.js:122` `szBrandSeal`：0.3 秒，1.25 倍缩到 1）。所以 App 里第一次出现印时有动作，最该有动作的结果页反而没有。
- **为何重要：**
  - 清单 G1（关键时刻要有一个形式）、G3（有反馈的地方画面必须有对应变化）。
  - Pok Pok 获奖理由里的「spot-on sound effects」，前提就是音画同帧。
  - HIG「Create defining moments」。
  - 这是拾字唯一一个能被录进 App Preview 的时刻。
- **阶段：** 完整编排（收进字库、归位成帖，D30）属阶段 2。网页阶段可以做一个**最小版本**，属产品决定：D46 写过「网页阶段只做静态部分」，但现在声音已经上线，静态加声音比两者都没有更糟。
- **获奖级目标：**
  - **结果页：** 作品格从右到左依次显现（每格 60ms 错开，淡入加 2pt 上移），最后一格到位后，落款一行淡入，接着印用 `szBrandSeal` 的同一条曲线落下，s1 和印缩到 1 倍的那一帧对齐。全程 ≤750ms，点任意处立刻跳到终态。
  - **开启「减少动态效果」时：** 直接显示终态，s1 仍在终态出现时响。
  - **判断落定：** 至少给本人墨迹 120ms 的淡出加 j1，再进下一字，不要让下一个空格在 33ms 内顶上来。
- **改动范围：** S（复用现有 keyframes；动画放在 `WorkSection`；s1 改成在动画结束回调里播）。

### N2-02 · 「拾」没有成为记忆点：首页给了答案，写下它却什么都没发生（S1）

- **页面 / 状态：** 首次打开（005）→ 首练第 3 字「收□ shí」（499 / 1056）→ 结果页（235）→ 回首页（9 / 1060）。
- **证据：**
  - 005：首屏中心是一块大「拾」。第三题的题面是「收□」，拼音 shí。
  - 235：作品里有「拾」，下一行只写了「「拾」7 天后再见」。
  - 9：首页的字帖位从「拾」换成了本人写的「尴 这 拾」，没有任何过渡或说明。
  - `grep 拾回 src` 没有结果，全 App 一次都没出现这个词。
  - 顾问审读的设想是「收拾 → 拾回」的落点要自然（`docs/engineering/v10/phase1/顾问审读-1.0.md:24`），界面上没有接住。
  - 品牌「拾」仍是 ShiziKai 印刷楷体（`src/ui/screens/home/copybook.js:88–89`）；书家字在精修，本条以现有为准。
- **问题：**
  - 作为用户，我在第三题会心一笑：「哦，就是首页那个字。」但这一笑没有回应。它也可能被读成「白送一题」。
  - App 的名字「拾」（拾回、拾起）是品类里唯一一个能被记住的词，现在只是一张 logo 卡。
  - 对照两款同名竞品：它们叫「提笔忘字」，拾字的 motto 也以「提笔忘字」开头。用户要记住的应该是「拾」这个动作，而不是又一个「提笔忘字」。
- **为何重要：**
  - 清单 H3（贯穿全 App 的母题）。
  - ADA Visuals and Graphics「distinctive」，Delight「memorable」。
  - grug 获奖理由里的「clever simplicity」：一个字就是全部品牌。
  - App Store 关键词和副标题与竞品撞名（D48）。
- **阶段：** 网页阶段可修（文案、首页状态切换）。书家字形是设计资产，正在做。
- **获奖级目标：**
  1. **首练第 3 字写对或看后自写时：** 结果页标题下多一行事实陈述，不是夸奖（D30）：「你写下的第一个「拾」。」
  2. **第一次回首页：** 字帖位的印刷「拾」淡出，换成用户自己的「拾」（过渡 400ms），这是首页方案 B 的「交接」；之后才是「今天写的字」。只发生一次。
  3. **「拾回」只用在两处，克制使用：**
     - 首页有记录状态的读屏和副句：「这个月拾回 23 个字」，等 D46 ⑤ 题记随积累变化时一起做；
     - 年报卷首：「这一年，你拾回 275 个字。」
  4. **品牌「拾」定稿后：** 首屏、图标、启动屏、关于页用同一个书家字形；分享图的印仍用「字」（D46 ⑧）。
- **改动范围：** S（文案两行）+ M（首页一次性交接状态，需要一个 `settings` 标志位）。

### N2-03 · 墨成了全 App 的主角，等宽记号笔线成了最大的视觉短板（S1，阶段 2）

- **页面 / 状态：** 书写格、判断页、作品格、字墙、月字帖、年报、分享图。
- **证据：**
  - 1048 / 1050（真实触摸）：每一笔线宽相同，起收都是圆头。
  - 59 墙、282 月字帖、253 分享图：同一种线，但粗细比例随格子大小变化。墙上的字明显比结果页（235）的粗。
  - D37 笔锋模型已定，等阶段 2 原生。
- **问题：**
  - 上一轮墨迹很少露面，这个问题是 S2。现在每一个「作品」出口都在展示它：月字帖看起来像白板笔抄的生字表，分享图里两个记号笔字配上楷体落款和朱印，材质不一致。
  - 作品感的上限就卡在这里。
- **为何重要：** 清单 C3 和材质一节；ADA Visuals「skillfully drawn」；Zen Brush 和以观书法的用户反复称赞的都是墨。
- **阶段：** 阶段 2（D26 / D37）。网页阶段只建议做一件事：所有出口按格子边长统一线宽比例（现在墙、作品格、字帖看起来不是同一支笔），不碰笔锋。
- **获奖级目标：** 原生笔锋按速度、压力出粗细；起笔有顿，收笔出锋；全 App 共用一个渲染器；分享图按 3 倍分辨率离屏渲染。
- **改动范围：** L（阶段 2）；线宽统一为 S。

### N2-04 · 提醒邀请被底部主按钮压住，SE 上完全看不到「好」（S2）

- **页面 / 状态：** 首练结果页、日常结果页的第二次邀请。
- **证据：**
  - 126（SE3）：「明天晚上八点半，给你一个词？」和正文都在，「好 / 不用了」整个藏在吸底的「再写一组」下面。
  - 1058、241、1066（iPhone 17）：「好」只露出上沿的弧线。
  - README 的事实备注第 3 条也记录了这一点。
- **问题：**

  - 很多人会以为点「再写一组」就是答应，或者根本没意识到可以回答。
- **为何重要：**
  - HIG Notifications：在看得到价值的时刻请求，而且请求必须可见。
  - 清单 A4（主内容要有锚点）、E5（主次）。
- **阶段：** 网页阶段可修。
- **获奖级目标（二选一，T3 比较）：**

  - **B：** 邀请卡移到复现句上方，紧跟作品；吸底栏在首练结果页不显示，等滚到底才出现。

### N2-05 · 首练结束的主按钮是「再写一组」，收尾感不足（S2，待 T3）

- **页面 / 状态：** 首练结果页（235 / 1058 / 239）。
- **证据：** 唯一的大按钮是黑色「再写一组」，出口只有左上角 22pt 的「×」（D49 ③）。
- **问题：**
  - 首练刚结束，用户最自然的情绪是「好，知道这是干什么的了」。页面却用最重的视觉权重推他再来一组。这和 D01「自然停下」的气质相反，也让「明天见」那句邀请失去分量。
  - 日常组用「再写一组」没有问题，首练这一页是例外。
- **为何重要：** 清单 E5；Bears Gratitude「warm」的收尾；Gentler Streak 结果页结论先行，不催下一步。
- **阶段：** 网页阶段。D49 ③ 已写明要由 T3 决定。
- **获奖级目标：**
  - 首练结果页的底部只放邀请（见 N2-04 方案 A）。回答以后底部变成「完成」，「再写一组」降为它下方的文字按钮。
  - 日常结果页不变。

### N2-06 · 「哪些字算我的作品」有三套规则（S2）

## 5. 证据缺口（只能靠真机或真人验证）

1. **首练三字的情绪曲线（T3）：**
   - 「尴」13 画、「赢」17 画，这两个字很可能有人写不出来；
   - 「拾」在首屏就是答案，用户的反应是会心一笑，还是觉得被白送一题；
   - 全写错时（239），那句「这三个字，很多人提笔就忘」能不能接住人。
2. **提醒邀请的接受率和例词理解：** 「□尬」在锁屏上会不会被读成「口尬」；晚上 8:30 这个默认时间是否合适。
3. **音画同步：** j1 / s1 在真机外放和耳机上的听感，和硬切画面放在一起是否显得廉价（N2-01 的前提）；静音键和「按键音」开关的理解。
4. **真人笔迹：** 墙、月字帖、分享图在真人手写墨迹下的观感；「同一个字，两次」在真实进步数据下是否有说服力（证据里两个「不」几何相同）。
5. **一个月以后的真实字单：** rich 种子仍是字频序，D28 易忘度排序在第 2 天到第 30 天给出的字，「快忘了」和年报里会出现什么，都没有截图。需要用新排序重造种子，或者做 T7 日记研究。
6. **分享意愿（T9）：** 现版和「语境词 + motto」版、「考考你」版之间，发到家人群或朋友圈的意愿。
7. **品牌「拾」书家字形：** 定稿没有进证据库，记忆点评分以现有印刷字为准，换字以后要复评。

记录要求同上一轮：本报告是 AI 走查，不是用户数据；所有「用户会怎么感受」的判断都是待 T3 / T7 / T9 验证的假设。
