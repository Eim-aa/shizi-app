## 1. 结论

**本轮分数：6 / 10。上一轮：5 / 10。**
刻度沿用上一轮：
- 1：核心任务对多数辅助技术用户不可用，平台控件全是仿制；
- 3：Web 语义比一般网页认真，但核心任务只服务「视力好、手稳、用手指」的人；
- 5：达到 HIG 基本要求的合格 App；
- 7：编辑推荐级打磨；
- 8：ADA 入围；
- 9–10：获奖。

**涨 1 分的原因：** 上一轮的 S1（AX 档书写格被底栏盖住）在 iPhone 17 和 Pro Max 上真正修好了。几项 S2 也落地了：
- 提示和本人墨能分开了（1.10 → 外廓对笺面 5.3:1）；
- 弹层有「完成」，读屏两指 Z 形手势接进了原生；
- 写字过程有读屏播报，进度读成中文；
- 次级页在 AX 档不再叠字；
- 最小字号有保底，格框对纸面过 3:1。

**没到 7 分，是因为 WebKit 矩阵里有一批新的 AX 缺陷，评审一开大字就能看到：**
- SE3 在 AX3–AX5 下书写格被拉成 286×334 的长方形，本人笔迹按 1.17 倍纵向变形保存；
- `keep-all` 让中文在 WebKit 里不折行，按钮文字和说明溢出屏幕；
- 写字页的辅助字一律封顶 17pt，矫枉过正。

**离 ADA 最大的三个差距：**
1. 【网页阶段现在就能修】**AX 版式最后一公里没有在 WebKit 里验收。** 包括 A3-01 到 A3-04。缺的是一道「WKWebView × 三机型 × AX3 / AX5」自动门禁：格子是否正方形、文字是否溢出、说明位是否可见。
2. 【网页可修 + 阶段 2】**读屏只做到「能走通」。**
   - 参考字形只读「3 个部件」，同音字读不出区别；
   - 判断声 j1 和播报会不会互相盖住，没有验证；
   - 还没有真人读屏用户走过一组；
   - 直通书写、逐笔笔画名属于阶段 2。
3. 【阶段 2/3】**平台层仍然一眼是网页**，这些都已在路线里，本轮不重复扣分：
   - 键盘附件条、WebKit 时间滚轮；
   - Tab 栏没有大内容查看器；
   - 粗体文本、智能反转不生效；
   - 不支持 iPad / Pencil，没有小组件。

## 3. 新问题清单

### A3-01 SE3 在 AX3–AX5 下，书写格被拉成长方形，本人笔迹纵向变形 1.17 倍保存；格下说明位被底栏盖住 — **S1**
- **页面/状态**：SE3 写字页的回忆、续写、看答案、描一遍、自己写一遍，系统字号 AX3、AX5；浅色、深色都有。
- **证据**：
  - **书写格尺寸**（逐像素量格框）：
    - SE3 AX5（v3:502 / 506 / 573 / 576 / 1035 / 1041 / 1046 / 1057）一律是 **286 × 334pt**；
    - SE3 AX3（v3:393 / 397 / 470 / 474 / 1020）是 **304 × 334pt**；
    - 对照：iPhone 17 AX5 是 362 × 362，Pro Max 是 400 × 400，都是正方形。
  - **墨迹比例**（同一个种子字「弓」，高 ÷ 宽）：SE3 AX5 是 3.10，iPhone 17 AX5 是 2.62，相差 **1.18 倍 = 334 / 286**。也就是说，笔迹画布被纵向拉伸了。
  - **说明位**：
    - SE3 AX5 上格子底边在 545pt，底栏发丝线在 558pt，56pt 的说明位整个在底栏下面。
    - 对比 iPhone 17 AX5（v3:1043），格下能看到「这个字记为看过答案，后面再写只算练习。以后点「看答案」会直接显示。」，SE3（v3:1035）完全看不到。
    - 被藏起来的内容还包括：
      - 「凭记忆写，想不起来可以点提示。」；
      - 保存失败的说明；
      - 上一字的结果行（「「X」记为写错 · 修改 ›」，这是改判断的入口）；
      - 读屏开启时的「改为在纸上写 / 不用」两个按钮。Chromium 375×667 读屏模拟里，这两个按钮在 y = 554–598，底栏顶在 558。
  - **Chromium 不复现**：375×667 下格子是 307 × 307，说明位在 498–554，可见。所以这是 WKWebView 特有的问题。
  - **源码**：
    - `src/ui/canvas/ink-canvas.js:37`：`.sz-inkgrid` 只靠 `aspect-ratio:1/1` 保持正方形，可以被拉伸；
    - `ink-canvas.js:40`：图层是 `width:100%;height:100%`；
    - `ink-canvas.js:119-127`：位图按宽度做成正方形，再被 CSS 拉高；
    - `ink-canvas.js:187-191`：指针坐标 x 除以宽、y 除以高。所以手指画在哪就落在哪，但**存进 345 单位正方形坐标的笔迹被纵向压缩到 1 / 1.17**。拿到判断页、作品、月字帖、分享图这些正方形格子里，本人的字会矮约 15%。
- **问题**：
  - 最小的屏幕加最大的字号，正是低视力、年纪偏大的用户最常用的组合。他们写下的字被悄悄改了形，而且会进作品、进年报、进分享图，跟不上这个产品的核心承诺「本人笔迹攒成作品」。
  - 「修改」入口和读屏用户的纸上写建议同时不可见。
- **为何重要**：
  - ADA Inclusivity：不能只在大屏上包容；
  - HIG《Layout》要求内容在所有尺寸上完整；
  - 品味清单「三种尺寸构图完整」；
  - 这也是一个数据问题：作品不可逆地变形。
- **网页阶段可修**。
- **获奖级目标做法**：
  1. `.sz-inkgrid` 显式写 `width:${g}px;height:${g}px;align-self:center;flex:none`，不依赖 `aspect-ratio`。
  2. `ink-canvas` 的 `sample()` 加防线：`rect.width ≠ rect.height` 时取 `min(w,h)` 居中映射，并上报一次错误。
  3. `axWriteLayout` 在 WKWebView 里按**实测**的格下位置复核：`gridBottom + 56 ≤ footTop`，不满足就继续缩格，直到下限 220。SE3 AX5 算下来约 270pt，放得下。
  4. 门禁：给 `.review` 的 recipes 加一道 WebKit 断言，覆盖 SE3 / 17 / Pro Max × AX3 / AX5 × 回忆 / 看答案 / 描一遍。断言三件事：格框 w == h、说明位完全可见、页面没有横向溢出。CI 没有 WebKit 的话，至少每次发版前用模拟器跑一遍。
- **改动范围**：两三行样式、一个映射防线、一条门禁脚本。另外要排查一下：已经在 SE AX 档写下的记录要不要标记。

### A3-02 `word-break:keep-all` 让中文在 WebKit 里不能折行：AX 档按钮文字和说明溢出、被裁掉 — **S2**
- **页面/状态**：
  - 描一遍阶段的主按钮「描好了，自己写」：v3:1112 / 1113（iPhone 17 AX5，「己写」压在「⋯」下面）、v3:1067 / 1069（只剩「描好了，自」）；
  - 详情页没写过的字：v3:1076 / 1078，「判断过的每一次书写都会留在这里」一行冲出右边的页边，被屏幕边裁掉。
- **证据**：
  - 源码：
    - `src/ui/components/ax.js:35-36`：AX 档所有主按钮、次按钮、文字按钮都加了 `word-break:keep-all`；
    - `write/ax-menu.js:20,25`；
    - `detail/records.js:75-79`；
    - `mine/records.js:126`；
    - `Sheet.js:26`。
  - CSS 的 `keep-all` 对中日韩文字的意思是「CJK 字符之间不许断行」。中文句子没有空格，一整句就成了一个「词」。
  - Chromium 会在「，」后面断开，所以它不复现（「描好了，自己写」折成两行，高 136）。WebKit 在 v3:1067 / 1112 里整行不折。
  - 这一条源自我上一轮 A2-11 的建议，是我的写法错了。
- **问题**：
  - 主按钮文字被「⋯」盖住或被裁掉，用户读不全这个按钮要做什么；
  - 说明句冲出页边。
- **为何重要**：HIG《Typography》要求 Dynamic Type 下文字完整可读；A2-11 本来想修的是「词内折行」，现在换成了「完全不折」。
- **网页阶段可修**。
- **获奖级目标做法**：
  1. 全局删掉 `keep-all`。
  2. 需要「按词折行」的地方，用 `Intl.Segmenter('zh', {granularity:'word'})`（iOS 14.5 起支持）把词包进 `<span style="white-space:nowrap">`，或在词间插 `<wbr>`。做成一个 `<Words>` 小组件，按钮、菜单、说明共用。
  3. AX 档的主按钮文案缩短：「描好了，自己写」改成「自己写」，阶段由页头「描一遍」交代。
  4. 门禁加一条：AX5 下 `scrollWidth > clientWidth` 的文字节点数必须为 0，在 WebKit 上跑。
- **改动范围**：样式删除、一个小组件、两三处文案。

### A3-03 AX 档写字页的辅助字一律 17pt：拼音、说明、纸上写说明、读屏建议在 AX1–AX5 都和默认字号一样大 — **S2**
- **页面/状态**：写字页、判断页、看答案页，AX1–AX5。
- **证据**：
  - `write/index.js:131-132`：`.sz-write__below *`、`.sz-paper__title / __text / __back`、`.sz-write__progress` 全部写死 `font-size:calc(17px * 1)`；
  - `index.js:142-143`：页头标题 17pt，单行、超长省略；
  - `prompt.js:127-128`：拼音和提示行 17pt；
  - `config/policy.js:213`：说明位固定 56pt，正好两行 17pt。
  - 截图：
    - v3:1043：AX5 下说明是 17pt，而同屏按钮字是 53pt；
    - v3:502：拼音「gān」17pt，声调符号约 3pt 高；
    - Chromium iPhone 17 AX5 纸上写模式：362pt 的空格子里，「在纸上写 / 写好了点「写好了」，再自己对照。/ 改回在屏幕上写」都是 17pt，大半格子空着。
- **问题**：
  - 上一轮的病是「辅助字比要回忆的字大」，这次的药是「辅助字不随档放大」。可是对 AX 用户来说，下面这些都不是装饰，而是任务信息：
    - 拼音和声调：单字题的唯一线索；
    - 「这个字记为看过答案」：后果说明；
    - 纸上写的操作说明：这本来就是给看不清、手不稳的人准备的路径；
    - 结果行里的「修改」。
  - 选 AX5 的人，读 17pt 和读默认字号一样吃力。
  - 页头标题「这个字这样写」也被锁成 17pt 单行。
- **为何重要**：
  - HIG《Typography》「Support Dynamic Type」：可以给次要文字设上限，但不能让它停在默认大小；
  - 系统 Footnote / Caption 在 AX5 仍是 44 / 40pt；
  - ADA Inclusivity。
- **网页阶段可修**。
- **获奖级目标做法**：分层封顶，而不是一刀切。
  - 拼音：`min(var(--fs15), 28px)`；
  - 格下说明、结果行：`min(var(--fs15), 24px)`，说明位高度按两行实际高度算（约 64pt），书写格让出这一点（iPhone 17 AX5 从 362 降到约 354，SE3 降到下限 220 以上）；
  - 进度：`min(var(--fs15), 22px)`；
  - 纸上写模式不封顶：格子里本来就是空的，说明按 AX 全尺寸排在格内，「改回在屏幕上写」做成 44pt 高、AX 字号的次按钮；
  - 页头标题允许折两行，或者在 AX 档直接隐藏（阶段由主按钮交代）。
- **改动范围**：样式和 `policy.writeGrid.axNoteHeight` 改成计算值。

### A3-04 AX5 弹层内重叠：查字的「完成」压住输入框，分享预览的「3:4 / 1:1」分段控件叠字 — **S2**
- **证据**：
  - v3:1120 / 1121（AX5 查字弹层）：「完成」和占位文字「输入一个字或一个词」叠在同一行，「字或」和「完成」互相压住，下面的说明被裁掉半行。
  - v3:752（XXXL）：「完成」挤进了输入框的右端。
  - v3:1126 / 1127（AX5 分享预览）：分段控件读成「3:41:1」；标题「这次的图片」折成「这次的图 / 片」。
  - 源码 `QuerySheet.js:57-59`：全高时「完成」绝对定位在右上，输入框右侧只让出 `2 × fs15 + 16`。但按钮本身有 `--bx` 内边距，用的又是文字按钮的字号，在 AX5 让出的宽度不够。
- **为何重要**：弹层「完成」是上一轮 A2-05 的修复，现在恰好在最需要它的 AX5 档和输入框打架。HIG《Sheets》。
- **网页阶段可修**。
- **获奖级目标做法**：
  - 查字弹层全高时，「完成」单独占一行，放在输入框上方，靠右，17–24pt 封顶；或者在 AX 档把输入框的 placeholder 缩短为「查字」。
  - 分段控件在 AX 档改成两个满宽的单选行（✓ 3:4 / 1:1）。
  - 弹层标题在 AX 档用 `text-wrap:balance`，配合 A3-02 的分词。
- **改动范围**：两个组件的 AX 分支。

### A3-05 SE3 上跳过撤销条仍压住书写格下沿（A2-10 未动）— **S3**
- **证据**：v2:542 → v3:690（SE3 标准字号），撤销条盖住格子底部约 15%。读屏开启时撤销条常驻（`policy.js`），也就一直压着。
- **网页阶段可修**：撤销条放在格下的说明位（结果行同一位置），不浮在格子上。

### A3-06 练习记录的列表模式仍在讲「墨点」— **S3**
- **证据**：
  - v3:678 / 1080 / 1084（AX 列表）、v3:1088（AX5 空状态）：「墨点表示这天有记录，不分对错。」「写一个字并判断对错，这天就会有一个墨点。」
  - 源码 `mine/records.js:475` 不区分月历模式和列表模式。
- **网页阶段可修**：列表模式下图例改成「列出这个月有记录的每一天」，或者不显示；空状态改成「写一个字并判断对错，这里就会多一行」。

### A3-07 读屏细节：「⋯」菜单弹层没有名称；参考字形的同音字没法区分 — **S3**
- **证据**：
  - Chromium 树里，菜单是一个没有名字的 `dialog`，第一项是「完成」（`Sheet.js:105`：没有 title 时 `aria-labelledby` 为空）。VoiceOver 会读成「对话框」，不说明是什么。
  - 参考字形读作「尴，gān，13 画，3 个部件」（`ref-label.js`）。中文 VoiceOver 读单字时，同音字（甘、干、肝……）听不出区别。
- **网页阶段可修**：
  - 菜单弹层给 `aria-label="更多操作"`；
  - 参考字形和题面的读屏名称改用「词中字」读法：「尴尬的尴，gān，13 画，左右结构」。题面已经有词语，零数据成本。

### A3-08 「增强对比度」只影响描红，令牌不响应 — **S3**
- **证据**：全仓库只有 `canvas/glyph.js:79-84` 读 `prefers-contrast: more`，`tokens.css` 没有对应的令牌块。下面这几对都卡在 3:1 附近，增强对比度打开后没有任何变化：

  | 令牌对 | 浅色 | 深色 |
  |---|---|---|
  | 答案衬底 `--under` 对笺面 | 3.24 | 3.34 |
  | `--ink4` 对纸面（次按钮边） | 3.21 | 3.18 |
  | `--frame` 对纸面 | 3.23 | 3.62 |

- **网页阶段可修**（前提是 WKWebView 会映射这个媒体查询，要真机确认）：加 `@media (prefers-contrast: more)` 令牌块，把 `frame / ink3 / ink4 / under / guide` 各加深一档，目标 ≥ 4.5:1。原生阶段改用 `UIAccessibility.isDarkerSystemColorsEnabled`。
