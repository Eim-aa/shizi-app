## 1. 结论

**本轮 5.5 / 10（上一轮 4.5，+1）。** 刻度不变：10 = 获奖作品；8 = 入围，核心时刻有独到、可感知的手感；6 = 编辑推荐级，打磨完整、处处像原生；4 = 逻辑周全、状态恢复可靠，但体感像做得很好的网页原型；2 = 核心流程不顺或常出错。

**加一分的原因**：上一轮「网页阶段现在就能修」的几项大多落地了，而且做得规矩。阶段切换 150ms 淡化；判断键 320ms 出现、440ms 才能点；换字后早到的笔会缓存补画；看答案不再弹确认框，本人墨不变暗、也不清空；描一遍的笔顺 ≤1.6s，可以点掉；j1 和 s1 分开约 550ms；Toast 不再盖住主按钮；首次打开第一帧就能看到主按钮；撤销和清空的位置固定了；提醒邀请也不再被截断。核心循环第一次不再「一帧换屏」。

**只加一分的原因**：
- 手上的感觉还是没变：墨仍是记号笔，跟手和 120Hz 至今零证据（阶段 2）。
- 新做的过渡带进了新问题：淡化时本人的字会以两种尺寸重影，判断页的返回键每次横跳 18pt。
- 提示写下一笔就全部收起，这一条规格（时刻 README 第 8 条）写明不该这样。
- 全 App 最隆重的落印，触觉反而最轻（Impact light），盖章声比印「着纸」那一刻晚约 120ms，冷启动恢复时还会再响一次。

**规格另评仍是 7.5 / 10**：上一轮 I2-11 的五处缺口一处都没改（时刻 README 没有更新）；原生书写面 spike 和 T1 仍未开始。

**离 ADA 最大的三个差距**：
1. **墨与跟手（阶段 2）**：等宽圆头笔迹，没有任何原生书写面的证据。这是唯一可能拿奖的东西，至今只存在于 SVG 样张里。
2. **求助梯子还差最后一步**（网页阶段现在就能修）：提示写下一笔就全收（I3-01）；描一遍每次都重播、不逐笔（逐笔判定属阶段 2）。
3. **「一张纸」的连续性**（网页阶段能修一部分）：每字两次的淡化都有重影、返回键横跳（I3-02、I3-03）；结果页仍是硬切换屏，再在 24pt 的印上做一个小动作；落印的触觉、声音、画面三者不同步（I3-04）。完整的共享元素编排属阶段 2。

## 3. 新问题清单

### I3-01 提示：写下一笔，整组提示 260ms 就全部收起，用户还没来得及照着写　S2（网页阶段可修）

- **页面 / 状态**：回忆阶段点「提示」后，接着写下一笔。
- **证据**：
  - 〔桌面 Chromium 实测〕首练「尴」：写 1 笔后点提示，给出「尢」的 3 笔（`data-state=shown`）。下一笔一落下，状态变成 `fading`；抬笔时已是 `none`，3 笔全部消失。用户刚要写第 2 笔，参照就没了。截图在 scratchpad `i3/pw/hint-pair.png`。
  - 源码：`hint-layer.js:10`「写下一笔（接受了一次落笔）→ 提示 260ms 淡出，淡完清掉提示范围」，`:51` `HINT_FADE_OUT_MS = 260`。
  - 规格明文相反：`README-时刻与求助.md` §2 第 8 条写的是「用户写过哪一笔，那一笔提示 260ms 收起，其余留着照着写（**现版写下一笔就全收，用户刚要照着写就没了**）」；§3 对照表「写过哪笔收哪笔（D34）」。
- **问题**：
  - 一次提示给 max(1, N/4) 笔（「尴」是 3 笔），实际只能看一眼就得默记。提示的价值打了大折扣，用户只好再点一次，次数很快用完，接着就去看答案。
  - 这不需要拟合，也不需要逐笔写出，是纯静态的计数逻辑。设计稿在 v1 就已经点名了这个问题。
- **为何重要**：品味清单 F 组（不让用户重复操作）；ADA Inclusivity（求助应当低成本）；D34。
- **获奖级做法**：提示范围 [from, to)。用户每完成一笔（抬笔、笔数 +1），从 `from` 起收掉一笔（只淡出那一笔，260ms）；笔数达到 `to` 时整组清空。撤销一笔时，被收掉的那一笔回来。读屏照常播报剩余提示笔数。
- **改动范围**：组件（`hint-layer.js` 的 reduce 与绘制；`glyph-wash` 需要能只画一个子范围）。约 1 天。

### I3-02 淡化时本人的字以两种尺寸重影；页头、题面、按钮文字都在原位叠字　S2（网页阶段可修）

- **页面 / 状态**：写好了→对照（每字一次）、判断→下一字（每字一次）、回忆→看答案、答案→描一遍、自己写→下一字。
- **证据**：
  - `1146`（33ms）：362pt 的「弓」淡出，同时 255pt 的「弓」淡入，两层都在半透明，同一个字以两种尺寸叠在一起；书写格框与上格框也同时可见。
  - `1159–1161`：判断页两格加「张」淡出，下一字空格淡入；题面「主 / 应」、拼音「zhāng / gāi」叠成一团。
  - `1512–1514`：按钮行「自己写 / 写好了 / 描一遍」三个词叠在两块按钮上；文字行「提示个看答案」（「提示」与「下一个」叠字）。
  - 源码：`phase-fade.js:21-27` 把整页快照盖在新状态上，150ms 线性淡出；新状态从第 0 帧起就是 100%。
- **问题**：
  - 同一位置上内容不同的元素（字、词、按钮标签）做同时交叉淡化，中间帧是脏的。最显眼的是用户自己的字：用户一直盯着它，它却在 3–4 帧里「分身」。这两段过渡每字都要走一遍，一组 5–15 字，每天 10–30 次。
  - D51 ② 只授权了「150ms 交叉淡化」，所以这不是违规，而是「最小过渡」这个选择本身在几何变化的地方不干净。
- **为何重要**：品味清单 G1 / G2（过渡要表达连续性，不能添乱）；HIG Motion「Prefer… that convey continuity」；时刻规格 ① 的「只缩放不平移」本来就是为了让本人的墨在过渡里保持是同一件东西。
- **获奖级做法（网页阶段，约 1.5 天）**：
  1. 书写格的墨层不进快照。写好了→对照时，把真实的墨 canvas 用 FLIP 做一次纯缩放：以顶边中点为原点，362→255，200ms，`(.2,.7,.2,1)`。这是规格 ① 的最小子集，终态与现在逐像素相同。需要产品负责人点头扩大 D51 ②（一行决定）。
  2. 文字类元素改为「先出后进」：旧 0–75ms 淡出，新 75–150ms 淡入，不再同时叠。框线、背景仍可同时淡化。
  3. 减少动态效果不变（直接切换）。
  - 验收：重录 `trans-recall-to-judge-compare`、`trans-judge-wrong-settle`，任何一帧里本人的字只出现一次，同一位置不出现两个词。
- **改动范围**：组件（`phase-fade.js` 快照排除 `[data-phasefade="live"]`；`index.js` 墨层加 FLIP）。

### I3-03 判断页左上「‹」比写字页其它阶段右移 18pt，每字横跳两次　S2（网页阶段可修，回归）

- **页面 / 状态**：回忆 ⇄ 判断页（「写好了」与「‹ 接着写」、判断后换字）。
- **证据**：
  - 像素量：回忆 `081`、答案 `111`、描一遍 `127`、自己写 `136` 的「‹」笔画都在 x = 19.7–27.0pt；判断页 `093` 在 x = 37.7–45.0pt。v2 里两者都在 25.7pt（`027`、`031`）。
  - 过渡帧 `1146`、`1159`：两个「‹」并排出现。
  - 〔桌面 Chromium 实测〕返回图标 svg 的 x：写字页 13.3，判断页 31.0。
  - 原因：`compare.js:458-461` 的 `ContinueButton` 是裸 `Button variant="icon"`，没有带 `Page.js:31` 的 `sz-page__ico--back`（`margin-left:-17.75px`）。H1 把页头对齐到 20pt 线时（提交 0dfc121）漏了这一处。
- **问题**：页头唯一的控件在核心循环里每字跳两次，手指记住的位置也随之变了。这是一个一行就能修的回归，但它恰好落在全 App 最常走的一步上，比任何静态页的对齐问题都显眼。
- **为何重要**：品味清单 A1（对齐线）、H（重复元素同位）；HIG「控件位置稳定」。
- **获奖级做法**：`ContinueButton` 加 `class="sz-page__ico--back"`；在 `test/` 的边线测试里加一条「写字页所有阶段的返回图标 x 相同」。
- **改动范围**：组件 1 行加测试 1 条。

### I3-04 落印：触觉是全 App 最轻的一档，盖章声比着纸晚约 120ms，结果页本身仍是硬切　S2（网页阶段 + 原生壳可修）

- **页面 / 状态**：最后一字判断 →（或「下一个」）→ 结果页。
- **证据**：
  - 〔桌面 Chromium 实测，首练三字〕点「写对了」t=0：
    - j1 在 38ms；
    - 68ms 结果页整页出现，页头、各行、复现句、底栏全部 100%，只有作品格在淡入（`1166`、`1543` 同样）；
    - 作品格 68–335ms 依次淡入；
    - 印从 335ms 起，468ms 到 scale 0.927、透明度 0.98（keyframe 60%，也就是「着纸」那一刻），约 600ms 回弹到 1；
    - **s1 在 589ms 才响**，比着纸晚约 120ms。
  - 源码：`result/work.js:79` 的 `szResultSeal` 在 60% 处到最小缩放；`land()` 在 animationend 之后才 setState，`:196-203` 下一次渲染的 effect 里才调 `sealMoment`。因为注释说「声音响起时画面上的印一定已经落定」，所以设计上就是晚于画面。
  - 触觉：`work.js:71` 发 `haptic('action')`；原生 `WebViewController.swift:59,912` 把 action 映射到 `UIImpactFeedbackGenerator(.light)`。每次判断是 stamp → `.medium`（`:57,906`）。规格 §4.2 写落印 `Impact rigid 0.8`、「全 App 只此一处」。
- **问题**：
  - 一组的终点是全 App 唯一一次「盖章」，现在手里的感觉比每个字的判断还轻，与「看答案」「结束这组」同一档。
  - 声音在印已经回弹完才响：耳朵听到的是「印落定之后又响了一下」，不是「盖下去」。120ms 已经在冲击类声画同步的可察觉范围内，原生桥还会再加几十毫秒（需真机确认）。
  - 页面本身仍是一帧整页替换。最先出现、也最抢眼的是行文和深色的「再写一组」，作品格和印是后到的。仪式感压在一个 24pt 的小物件上，又放在屏幕右侧边缘，视线不在那里。
- **为何重要**：HIG Playing haptics（触觉与看得见的变化同步、强度与事件分量相称）；品味清单 G3；Pok Pok 获奖理由「subtle haptics, spot-on sound」；D30「落款」。
- **获奖级做法（网页阶段 + 原生壳，约 1 天）**：
  1. 新增触觉档 `seal`，原生用 `UIImpactFeedbackGenerator(.rigid)` 的 `impactOccurred(intensity: 0.8)`；`haptics.js` 的 HAPTIC_KINDS 加 `seal`，`sealMoment` 改发 `seal`。
  2. s1 与触觉改在「着纸」那一刻发：用 `setTimeout(sealDelay + 0.6 × sealMs)`，或者改 keyframe，让最小缩放落在 100%、回弹单独一小段。不要等 animationend。原生端在点按落款前就 `prepare()`。

### I3-06 「拾」的交接：300ms 同时交叉淡化，两个不同的「拾」半透明叠在一起，而且在首页出现的第一刻就开始　S2（网页阶段可修）

- **页面 / 状态**：首练写下「拾」后第一次回首页（D51 ④ 定的品牌记忆点，一生一次）。
- **证据**：`trans-shi-handoff-home` `1660–1667`（放大图见 scratchpad `i3/handoff-crops.png`）：品牌「拾」与本人的「拾」各约 50% 叠成一个灰色双影字，约 230ms 后才是本人的字。源码 `home/copybook.js:78-81`（brand out 与 mine in 都是 300ms ease-out，同时开始）；`home/index.js:281-295` 在首页成为顶层的那一刻就挂上。
- **问题**：
  - 用户从结果页回到首页，页面是硬切出现的，视线还没落到字帖格上，交接已经过了一半。最好的情况，用户看到的是一个模糊的双影字；最坏的情况，用户根本不知道这里发生过什么。
  - 两个字形不同的「拾」做同时交叉淡化，正是 I3-02 里最不干净的那种过渡。
- **为何重要**：D51 ④ 把它定为与图标、印同一个记忆点；ADA Delight & Fun；品味清单 G3（时刻要被看见）。
- **获奖级做法（网页阶段，不扩大授权）**：
  1. 首页出现后先停 500ms，完整显示品牌「拾」，让用户认出它。
  2. 品牌「拾」150ms 淡出到 0，本人的「拾」紧接着 300ms 淡入，先出后进，没有双影帧。
  3. 本人的字到位那一帧给一次 Selection 触觉。
  4. 减少动态效果：直接本人的字。
  - 阶段 2：本人的「拾」从结果页作品格里飞回首页格（共享元素），这才是「拾回」。
- **改动范围**：样式（`copybook.js` 两条 keyframes 加 delay），可加 1 次触觉调用。

### I3-07 描一遍每次进入都重播笔顺；规格是「每字只在第一次」　S3（网页阶段可修）

- **证据**：`answer.js:353`「先播一遍（每次进描一遍一次）」，`:363` 每次挂载都 `animate(...)`。规格 `README-时刻与求助.md` §2 第 11 条、D46-17：「每字只在第一次描时播放」。过渡帧 `1265–1306`：这一次快放约 1.3s，期间主按钮「描好了，自己写」是禁用灰（`1268` 起）。
- **问题**：「自己写→再描一遍」是练同一个字的往返，每回都要再看 1.3s 的同一段笔顺，或者先点一下把它跳过。
- **获奖级做法**：按 `session.current` 记 `tracePreviewed`，同一字第二次进入时直接是描红终态；首练第一个字仍然播。
- **改动范围**：组件。

### I3-08 冷启动恢复到看答案 / 描一遍 / 自己写时，书写格比回忆高 20pt，推进到下一字时整格下跳　S3（网页阶段可修）

- **证据**：
  - 像素量：`111`（看答案，恢复进入）、`127`（描一遍）、`143` 和过渡帧 `1203`（自己写）的格顶是 230pt；回忆 `081` 与 `1225` 是 250pt。过渡帧 `1203–1206`：两套框线和两套撤销 / 清空图标同时可见，竖向差 20pt。

  - 原因：`compact.js:129,166` 只在 recall / compare 量主区高度，其它阶段沿用上一次的量值。冷启动直接恢复到答案类阶段时，没有「上一次」，量到的是带说明行、更高的底栏，于是组顶上移 20pt。

- **获奖级做法**：所有阶段一律按回忆态的名义底栏（`NOMINAL_FOOT_H`）算组顶，不再依赖「上一次量到的值」。
- **改动范围**：组件（`compact.js` / `layout.js`）。

### I3-09 「已保存，下次接着写」Toast 仍然出现：不再挡按钮，但它是首页上唯一的深色大块，说的事首页本身已经说了　S3（网页阶段可修）

### I3-10 首练结果页：落印后约 1.1s 屏上没有任何主操作　S3（网页阶段可修）
