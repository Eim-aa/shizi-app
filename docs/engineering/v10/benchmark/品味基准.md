# 拾字 · 品味基准（获奖准则 + 获奖作品细节库 + 逐屏清单）

- 编写日期：2026-10-04。用途：给下一轮五位独立设计审查者对照截图逐项打勾，不是正式审查。
- 证据规则：凡是「准则原文」「获奖身份」「官方获奖理由」都附链接；查不到的写「未查证」。作品细节是我在内置浏览器里亲自看 App Store 截图后记下的，**只记截图上看得到的东西**；尺寸是目测比例，不是像素测量。
- 截图都在 `screens/` 下，文件名格式为 `作品-来源-序号-内容.jpg`，审查者可以用 Read 直接打开。
- 限制（先读）：
  1. 内置浏览器拦截了页面的所有子资源（CSS、图片），所以 App Store 页面本身渲染不出来。我的做法是从页面 HTML 里取出截图地址，再把每张截图作为顶层页面单独打开、截屏。截屏没有经过下载。
  2. App Store 截图是开发者做的**营销合成图**：带标语、机身、倾斜角度，和真机界面不完全一样。动效、触觉、声音、读屏都无法从中判断，凡涉及这些的条目都标为「需上手」或「需录屏」。
  3. 没有看官方视频，因为视频资源同样被拦截。

### 1.2 Apple Human Interface Guidelines：与「清晰、克制、层级、内容优先」相关的原则

**设计原则页**：https://developer.apple.com/design/human-interface-guidelines/design-principles 。变更记录显示「June 8, 2026 | Reintroduced design principles」。该页分为 Purpose / Agency / Responsibility / Familiarity / Flexibility / Simplicity / Craft / Delight 八组，与本任务相关的条目如下：

- **Keep focused**：把最重要的功能做到真正好。
- **Stay out of the way**：直接把人带到任务或内容；最好的设计「unobtrusive」。
- **Help people recover from mistakes**：可逆、可回退。
- **Keep visuals and interactions consistent**：一个元素的外观或行为一旦确立，就要全局沿用。
- **Include just what's necessary**：原文说「Simplicity isn't minimalism」，要让次要的东西退场。
- **Be concise**：用的词恰好够表达就行。
- **Establish hierarchy**：可辨认的控件，一致的结构。
- **Quality sets the tone**：原文举了「precise wording」，要求每个决定都是刻意的。
- **Don't mistake delight for decoration**：不要为了愉悦而愉悦。
- **Create defining moments**：从按钮到报错，每个时刻都可以带一点性格。

**各专题页的可检查条目**（下面每条都是原文要点的转述）：

| 主题 | 要点 | 页面 |
|---|---|---|
| iOS 总则 | 减少屏上控件数量，让人专注主任务和内容；次要细节和操作「discoverable with minimal interaction」 | https://developer.apple.com/design/human-interface-guidelines/designing-for-ios |
| 布局 · 层级 | 按重要性排序，最重要的放在顶部和起始侧；用对齐和缩进表达层级；用负空间、容器形状或分隔线分组；用渐进披露减少初始内容 | https://developer.apple.com/design/human-interface-guidelines/layout |
| 布局 · 适配 | 尊重安全区；准备好应对文字变大（并排的元素改为纵排） | 同上 |
| 字体 | 「Minimize the number of typefaces」；用字重、字号、颜色表达层级；iOS 默认 17pt、最小 11pt；避免 Ultralight/Thin/Light 这类细字重；用户放大文字后要保持相对层级 | https://developer.apple.com/design/human-interface-guidelines/typography |
| 颜色 | 「Avoid using the same color to mean different things」；不要只靠颜色传达信息；颜色要在浅色、深色、增强对比度下都成立；给 Liquid Glass 上色要克制，只用于状态或主操作 | https://developer.apple.com/design/human-interface-guidelines/color |
| 品牌 | 强调色「judiciously」，铺得太广会稀释；品牌要「defers to content」；不要处处放 logo；启动屏不是品牌位 | https://developer.apple.com/design/human-interface-guidelines/branding |
| 动效 | 动效要有目的，不能盖过体验本身；动效是可选的，不能是唯一的信息通道；反馈动画要短而准；高频交互尽量不加动效；动效可以被打断，不要让人等它播完 | https://developer.apple.com/design/human-interface-guidelines/motion |
| 反馈 | 反馈的分量要匹配信息的重要性；状态信息被动呈现；只有意外且不可逆的数据丢失才需要警告；预期之中的删除不必警告 | https://developer.apple.com/design/human-interface-guidelines/feedback |
| 文案 | 「If you can use fewer words, do so」；按钮用动词；不要为了可爱而含糊；空状态要给出清楚的下一步；报错贴近问题、不责怪、说明怎么修 | https://developer.apple.com/design/human-interface-guidelines/writing |
| 无障碍 | 17pt 以下文字的对比度 ≥ 4.5:1；控件默认 44×44pt，最小 28×28pt | https://developer.apple.com/design/human-interface-guidelines/accessibility |
| 加载 | 最好的加载是用户察觉不到的；尽快先显示点东西 | https://developer.apple.com/design/human-interface-guidelines/loading |
| 启动与引导 | 启动屏要几乎等同于首屏，不放文字和品牌；恢复上次的状态；引导要在动手中教，可跳过；能延后的设置就延后 | https://developer.apple.com/design/human-interface-guidelines/launching 、 https://developer.apple.com/design/human-interface-guidelines/onboarding |

### 1.7 提炼：评审在看什么

判断方式图例：**图** = 静态截图可判；**录** = 需录屏或过渡帧；**手** = 需真机上手；**文** = 需产品说明或数据。

| # | 评审在看的点 | 依据 | 判断方式 |
|---|---|---|---|
| J1 | 一眼看出这屏是干什么的，主角是谁 | HIG Keep focused / layout 层级；ADA「easy to scan」 | 图 |
| J2 | 删得够不够：没有多余的控件、说明、装饰 | HIG Include just what's necessary；ADA「nothing extraneous」「essentials」「uncluttered」 | 图 |
| J3 | 层级是否清楚：字号、字重、颜色是否成体系、不过量 | HIG typography / Establish hierarchy；ADA「hierarchy」 | 图 |
| J4 | 主题是否统一、独特：同一套母题贯穿所有屏 | ADA V&G「distinctive and cohesive」；Vocabulary「consistent…rhythm」；UXDA「consistent design」 | 图（需多屏比较） |
| J5 | 颜色是否克制、语义是否唯一 | HIG color / branding | 图 |
| J6 | 内容是否优先于品牌 | HIG branding「defers to content」 | 图 |
| J7 | 平台契合：系统控件、安全区、手势、Dynamic Type | ADA Interaction「tailored to their platform」；HIG iOS | 图 + 手 |
| J8 | 关键时刻是否有形式（落定、完成） | HIG Create defining moments；ADA Delight | 录 |
| J9 | 动效是否短、准、可打断 | HIG motion | 录 / 手 |
| J10 | 文案是否精确、少、有自己的语气 | HIG writing / Quality sets the tone | 图 |
| J11 | 空、错、加载状态是否被设计过 | HIG writing / loading / feedback | 图（需要状态截图） |
| J12 | 包容到具体机制：读屏、动态字体、色觉、运动障碍 | ADA Inclusivity；Procreate、Land of Livia 的获奖理由 | 图（对比度、色觉）+ 手 |
| J13 | 理念与差异化：为什么是它 | iF Idea / Differentiation；Red Dot Idea | 文 |
| J14 | 可理解性与情感意义 | Red Dot Impact | 图 + 手 |

## 2. 获奖作品细节库（11 个）

选取标准：气质安静、内容是主角、排版驱动、工艺讲究，题材是学习、书写、阅读或习惯类。

- 前 10 个是可在 Apple 官方 ADA 页面核实的获奖或入围作品。
- Things 3 的 2017 年获奖来自开发者官方博客，以及 App Store 页面上的「Apple Design Awards to its name」，Apple 2017 年的页面我没有找到。
- 没有收入「非获奖标杆」。

### 2.1 Vocabulary – Learn words daily（Monkey Taps）

- **身份**：2025 ADA Visuals and Graphics 入围。获奖理由称其插画「consistent」，形成「clean visual style and rhythm」。出处：https://developer.apple.com/design/awards/2025/
- **App Store 页**：https://apps.apple.com/us/app/vocabulary-learn-words-daily/id1084540807
- **看过的截图**：`Vocabulary-appstore-01-word.jpg`、`02-lockscreen`、`03-practice-correct`

**可观察细节**

- **构图**：单词页只有一个单词，水平居中，竖向位置略低于屏幕中线。词下面依次是音标胶囊和一行释义，再下面是 4 个图标排成一行（信息、分享、收藏、书签）。顶部只有一个「0/5」小胶囊进度。整屏没有卡片框，内容直接放在暖米色纸底上。
- **字体与层级**：用两种字体。单词和标语用衬线粗体，音标、释义和标签用无衬线。单词页可见的字号是 3 级：单词、释义、Tab 标签。
- **颜色**：一屏基本只有米色底加墨色字。插画配色（灰蓝、珊瑚）只出现在营销图外框上，App 内单词页里没有。
- **线与形**：4 个图标线宽相同、间距相等；进度胶囊和音标胶囊的圆角一致。
- **反馈**：答对时，选项变成绿底并加勾（形状和颜色两个通道），底部升起结果面板，标题「That's correct!」用衬线，附一个例句，只有一个全宽「Next word」按钮。反馈是从底部升起的面板，不是弹窗。
- **删掉了什么**：单词页没有标题栏、没有分隔线、没有计分。

**一课**：一页纸上只放一个字，下面只跟一行辅助信息和一排同规格图标。字不装框，纸就是框。

### 2.2 grug（Ocho）

- **身份**：2026 ADA Delight and Fun 获奖。获奖理由用了「clever simplicity」「no login, no cloud syncing, nothing extraneous」，并点名手绘状态栏。出处：https://developer.apple.com/design/awards/ ；App Store 编辑故事：https://apps.apple.com/us/story/id1896834607
- **App Store 页**：https://apps.apple.com/us/app/grug/id6751649802
- **看过的截图**：`grug-appstore-01-cover`、`02-today-white`、`03-today-green`、`04-today-blue`

**可观察细节**

- **构图**：今日页从上到下依次是：
  - 左上一个小号「grug.」字标，右上一个小色点（换主题入口）；
  - 中上部一幅单线手绘；
  - 中下部 3 到 5 行左对齐文字；
  - 文字下面是「grug. 5.11」这样的签名式日期；
  - 底部一条历史日期栏（小图标加日期），中间是一个手绘椭圆的分享按钮。
- **对齐**：文字块、签名和左上字标在同一条左边线上。
- **字体**：全 App 只用一种手写字体。正文和日期属于同一字号级别，字标略大。一屏目测 2 到 3 级字号。
- **颜色**：一屏只有一种平涂底色加一种线色（白底黑线、墨绿底米白线、天蓝底墨线），没有阴影、卡片和分隔线。主题色由用户自己换。
- **空状态和未来**：历史栏里「明天」那一格不用灰色占位，写的是「grug back sun rise」，用文案代替空状态。
- **删掉了什么**：截图里看不到连续天数、统计数字或成就。官方理由也写明「no login, no cloud syncing」。

**一课**：每日一页就是「一幅图、几行字、一个落款日期」。历史只是一排日期，不需要统计。拾字的「今天写的字加落款」可以做到这种程度的少。

### 2.3 iA Writer（Information Architects）

- **身份**：2025 ADA Interaction 入围，理由是「distraction-free writing with intuitive interactions」。出处：https://developer.apple.com/design/awards/2025/
- **App Store 页**：https://apps.apple.com/us/app/ia-writer/id775737172
- **看过的截图**：`iAWriter-appstore-01-focus`、`02-authorship`、`03-syntax`、`04-editing`（均为横版营销合成图，含 iPhone 界面）

**可观察细节**

- **构图**：编辑界面里只有正文和光标。截图中看不到工具栏、标题或字数。
- **字体**：正文用一种字体（iA 自家的等宽系字体），只有一级字号。
- **颜色**：默认状态下唯一的彩色是蓝色光标和选区。颜色只在用户主动打开的模式里出现：语法高亮按词性着色；Authorship 模式把粘贴来的文字调暗，突出自己写的字。
- **焦点处理**：区分「自己写的」和「外来的」靠调暗明度，不靠加框或底色块。
- **删掉了什么**：没有格式工具栏，没有任何装饰。

**一课**：写字页的默认状态应当接近「一张纸加墨」。提示和答案是用户主动叫出来的「模式」，叫出来以后才出现颜色。另外，「本人的字最亮，外来的变暗」正好对应拾字「本人笔迹 vs 参考」的区分方式。

### 2.4 Chineasy（Chineasy）

- **身份**：2022 ADA Delight and Fun 入围（官方页只列名单，没有理由文字）。出处：https://developer.apple.com/design/awards/2022/
- **App Store 页**：https://apps.apple.com/us/app/chineasy-learn-chinese-easily/id1318941705
- **看过的截图**：`Chineasy-appstore-01-cover`、`02-charcard`、`03-roadmap`、`04-review`

**可观察细节**

- **字卡页**：一屏一个词（「火山」）。字形居中，约占屏宽的 2/3。下面只有一个英文词，底部是页点，左上是返回箭头。整页一种平涂底色（黄）。
- **字形与装饰**：插画（火焰、山）叠在笔画上，但**笔画始终是黑色线，字形没有被插画替换**。
- **复习页**：搜索框、「20 Cards」一个卡堆、主题横滑、底部 4 个 Tab。元素和彩度都明显多于字卡页。
- **路线图页**：游戏化路径节点、「WORDS 92」计数胶囊、吉祥物。**这正是拾字明确不做的方向**（不做打卡、排名、强制数量），列在这里作为反例对照。

**一课**：同类产品里，字卡页那种「字加一行释义加页码」的少才是它最好的屏，游戏化的屏反而是它最吵的地方。字的黑线永远不让给装饰。

### 2.5 Bears Gratitude（Isuru Wanasinghe）

- **身份**：2024 ADA Delight and Fun 获奖，理由是「warm and welcoming」，帮人建立并「maintain」每日感恩习惯。出处：https://developer.apple.com/design/awards/2024/
- **App Store 页**：https://apps.apple.com/us/app/bears-gratitude/id6443609622
- **看过的截图**：`BearsGratitude-appstore-01-todaycard`、`02-rewards`、`03-reminder`

**可观察细节**

- **颜色**：每一屏只用一个色相家族（黄、鲑红、紫），按钮、文字和底都是同一色相的深浅变化。颜色看着多，但一屏之内只有一族。
- **母题**：文字按钮统一加竖线前缀或后缀（「| Home」「| Entries」「| Rewards」「Edit |」），所有屏通用。这是一个小而一致的母题。
- **日期**：今日卡左上是日期角标（大号「14」加小号「Sep」）。卡片结构是插画、标题、正文三段。
- **文案**：提醒页的语气平和，引导写一条，不施压，例如「Brick by brick. Day by day.」。
- **删掉了什么**：截图里看不到连续天数计数器。

**一课**：给全 App 定一个小母题（它用的是竖线括号），让每个文字按钮都带上它。拾字的「格」和「印」也应该这样一以贯之，不要每屏发明新的框法。

### 2.6 Gentler Streak（Gentler Stories）

- **身份**：2024 ADA Social Impact 获奖；2023 年 Visuals and Graphics 入围。出处：https://developer.apple.com/design/awards/2024/ 、 https://developer.apple.com/design/awards/2023/
- **App Store 页**：https://apps.apple.com/us/app/gentler-streak-workout-tracker/id1576857102
- **看过的截图**：`GentlerStreak-appstore-01-greateffort`、`02-wellbeing`、`03-sleep`

**可观察细节**

- **结论先行**：结果页先给一个大字结论（「Great Effort Today」「Excellent」），接一段白话解释，然后才是数据。
- **状态用词**：用「Normal」「As Usual」这样的中性词，不打分。
- **数字排版**：单位缩小，例如「8h 19m」里的 h 和 m 比数字小一号；标签是小号灰字，放在数值上方。
- **插画**：角色插画每屏只在一处出现。
- **删掉了什么**：它的口号就是「not about closing rings」。截图里没有红色警告和断签惩罚。

**一课**：结果页先给一句人话，数字退后，单位缩小。拾字不评分，但可以借用它的「判词」语法，只是换成中性的「记下了几个字」。

### 2.7 Structured（unorderly）

- **身份**：2026 ADA Inclusivity 入围，理由是「Visually sharp and easy to scan」，神经多样性用户称赞其「simple layout」。出处：https://developer.apple.com/design/awards/
- **App Store 页**：https://apps.apple.com/us/app/structured-daily-planner-todo/id1499198946
- **看过的截图**：`Structured-appstore-02-timeline`

**可观察细节**

- **行模板**：时间轴每一行都是同一个模板：左侧一个彩色胶囊图标，中间两行文字（上面小号灰色时间，下面粗体标题），右侧一个空心完成圆。所有完成圆在同一条竖线上对齐。
- **状态表达**：完成状态由形状（空心变实心）加颜色共同表示。
- **顶部**：日期标题「13. May」加一行周条，今天用一个实心圆标出。

**一课**：列表只用一个可重复的行模板，右端操作对齐成一列。状态靠形状变化，不只靠颜色。

### 2.8 Halide Mark II（Lux Optics；App Store 现名 Halide Mark III）

- **身份**：2022 ADA Visuals and Graphics 获奖，理由是「focuses on the essentials」「uncluttered, smartly organized UI」。出处：https://developer.apple.com/design/awards/2022/
- **App Store 页**：https://apps.apple.com/us/app/halide-mark-ii-pro-camera/id885697368
- **看过的截图**：`Halide-appstore-02-editing`、`03-viewfinder`
- **注意**：当前截图是 Mark III，不是获奖时的 Mark II 界面。

**可观察细节**

- **构图**：取景器占屏幕上部约 60%，控件全部放在下方黑底上。
- **控件尺寸**：小圆控件（RAW、AF、焦段）直径一致。屏上只有一个最大的白色快门，居中；左边缩略图、右边滤镜，左右对称。
- **颜色**：黄色只出现在「当前激活」的状态上（AF、2×），编辑页的确认勾也是黄色。其余界面全是灰阶。
- **删掉了什么**：拍摄界面上没有文字说明。

**一课**：一个主操作，尺寸最大，位置固定；强调色只表示「现在激活的是哪个」。

### 2.9 Crouton（Devin Davies）

- **身份**：2024 ADA Interaction 获奖，理由点名「organization and information hierarchy」和「clean」的界面。出处：https://developer.apple.com/design/awards/2024/
- **开发者自述**（Apple 官方访谈）：花很多时间想「what to leave out」；分步模式「only the current step, ingredients, and measurements」。出处：https://developer.apple.com/news/?id=9x75y43e
- **App Store 页**：https://apps.apple.com/us/app/crouton-recipe-manager/id1461650987
- **看过的截图**：`Crouton-appstore-01-detail`、`04-stepmode`

**可观察细节**

- **分步模式**：一屏只有一步。步骤标题是灰色小字（「Prepare filling」「Step 1」），正文是大号黑字。右上三个工具图标收进一个胶囊组；右下只有一个蓝色圆形「下一步」按钮；底部是页点。
- **颜色语义**：蓝色只用于可交互或可换算的用量（「1 cup」「2 cloves」）和「下一步」，一种颜色只有一个意思。
- **详情页**：用量数字是蓝色，名称是黑色，在同一行里形成两级。

**一课**：拾字的写字流程本质上就是一个分步模式：一屏一个字，一个「下一步」，其余工具收进角落的一组。

### 2.10 Mela – Recipe Manager（Silvio Rizzi）

- **身份**：2025 ADA Interaction 入围，理由是在恰当时刻突出步骤与用量。出处：https://developer.apple.com/design/awards/2025/
- **App Store 页**：https://apps.apple.com/us/app/mela-recipe-manager/id1548466041
- **看过的截图**：`Mela-appstore-01-recipe`、`03-cookingmode`

**可观察细节**

- **详情页**：菜品抠图直接放在白底上，不加框。标题用衬线粗体。元信息一行（人数、准备时间、总时间）用细竖线分隔。三个动作（Cook、Groceries、Adjust）都是「图标加文字」，图标用同一个强调色。正文和配料之间只有一条**短的、居中的**分隔线，不是通栏。
- **烹饪模式**：当前步骤是全对比黑字，其他步骤被调到很淡（目测 15% 到 20%），焦点靠明度表达，不靠框或底色。屏上只有两个小灰圆按钮（关闭、计时）。

**一课**：表达焦点和对照时调明度，不要加框、加卡片。分隔线能短就短，能不画就不画。

### 2.11 Things 3（Cultured Code）

- **身份**：开发者博客写明 2017 年 WWDC 新版 Things 获 Apple Design Award（2009 年也获过）。出处：https://culturedcode.com/things/blog/2017/06/back-from-wwdc/ 。App Store 页也写有「Apple Design Awards to its name」。Apple 2017 年的官方 ADA 页面**未查到**。
- **App Store 页**：https://apps.apple.com/us/app/things-3/id904237743
- **看过的截图**：`Things3-appstore-01-lists`、`02-today`

**可观察细节**

- **对齐**：列表有两条竖向对齐线，图标一列、文字一列。
- **分组**：组和组之间（收件箱 / 今天…… / 日志簿）靠**留白**分开，组内不画线。只在大区块（Family、Work）之间画一条细线，而且这条线**内缩**到文字列，不通栏。
- **层级**：二级信息是标题下一行小号灰字（所属项目）。计数右对齐，灰色。
- **颜色**：红色只用于「today」旗标和徽标。屏上只有一个浮动「+」按钮。

**一课**：分组用留白。线只用在大区块之间，并且内缩到内容列。

### 2.12 作品之间的共性：它们共同「没有做」的事

1. **屏上没有说明这个屏怎么用的长句**（grug、Vocabulary、iA、Halide）。
2. **内容不装进卡片框**，直接放在纸或底上（Vocabulary、grug、Mela 的菜品图）。
3. **强调色只有一个意思**（Crouton 的蓝、Halide 的黄、Things 的红）。
4. **主操作只有一个**，其余操作降为图标或文字，收在角落（Crouton、Halide、Vocabulary 练习页）。
5. **焦点用明度表达**，不用边框（Mela 烹饪模式、iA Authorship）。
6. **不做打卡、统计、成就的喧哗**（grug、Gentler Streak、Bears）。Chineasy 做了路线图和计数，它那几屏也正是最吵的。

## 3. 拾字品味清单（34 条，分 8 组）

使用方法：每屏逐条判定「过 / 不过 / 不适用」，不过的要写出截图文件名和位置。

- 每条都写成**能在截图上判定**的表述。需要录屏或上手才能判的条目标了（录）或（手）。
- 「出处」栏的编号指本文第 1 节的 J 条目、第 2 节的作品，或 HIG 页面。

### A. 构图与留白（6）

| ID | 检查项（截图可判） | 出处 | 为什么对拾字重要 |
|---|---|---|---|
| A1 | 一屏只有 **1 个视觉焦点**。把截图眯眼缩小到 1/4，最先看到的东西只有一个，而且是字或主操作 | J1；Vocabulary、grug | 「字是唯一主角」；有两个焦点就是在和字抢 |
| A2 | 所有内容共用**同一对左右页边**（推荐 16 或 20pt）。没有某一块比其他块缩进或外扩，例外必须有理由 | HIG layout 对齐；grug、Things | 字帖感来自稳定的版心，页边乱就不像一本帖 |
| A3 | 留白是**分组用的**：组内间距明显小于组间间距（目测 ≤ 1/2）。不存在既不属于上面也不属于下面的大块「漂浮空白」 | HIG layout 分组；Things | 现在几屏的问题不是留白多，而是留白不成组 |
| A4 | 主内容的**竖向位置有锚点**：要么贴着顶部内容流，要么明确居中。不能一半挂在上面、一半掉到下面 | Vocabulary 单词竖向略低于中线；Halide | 首页、结果页的「中段塌陷」感就是缺锚点 |
| A5 | 同一个元素（田字格、字帖、按钮组）在相邻页面里**位置和尺寸不跳** | HIG Preserve a person's context；V12 | 写字到判断是连续动作，格子一跳，注意力就断 |
| A6 | 内容**不装进多余的框**：能放在纸上的就不加卡片和外框；一个元素最多一层边界 | Vocabulary、Mela、grug | 纸、笺、格已经是三层，再加框就是「框套框」 |

### B. 字体与层级（5）

| ID | 检查项 | 出处 | 为什么重要 |
|---|---|---|---|
| B1 | 同一屏**字号 ≤ 4 级**（不计状态栏和 Tab 标签），理想是 3 级 | HIG typography 层级；Vocabulary 单词页 3 级、grug 2 到 3 级 | 字号一多，大字（练习字）就不再显得大 |
| B2 | **字体家族 ≤ 3**（楷：练习字；宋：标题和大数字；黑：界面），而且每种只出现在规定的角色上 | HIG「Minimize the number of typefaces」；设计说明 v1 | 楷体被当作装饰用，就会稀释「字是主角」 |
| B3 | 练习字（楷）在本屏**最大**，没有任何标题或数字比它大或和它一样大 | J1；Chineasy 字卡 | 主角必须在尺寸上赢 |
| B4 | 同一信息层级只用**一种**样式：所有「次要说明」同字号、同色；所有「数字」同一种处理 | HIG Keep visuals consistent | 层级不能靠每处临场决定 |
| B5 | 正文 ≥ 15pt，任何文字 ≥ 11pt；没有细字重；**放大到 AX 档后层级关系仍在**（手 + 图） | HIG typography / accessibility | 用户是成年人，包括视力下降的人 |

### C. 颜色与材质（5）

| ID | 检查项 | 出处 | 为什么重要 |
|---|---|---|---|
| C1 | **朱色每屏 ≤ 2 处**，而且只有两种意思：写错的朱点、落款或品牌的印。数一下屏上朱色元素的个数和种类 | HIG「same color…different things」；Crouton、Halide；设计说明 v1 第 1 条 | 朱是批改的颜色，一多就失去分量 |
| C2 | 除朱和淡朱以外，界面颜色只有**纸、墨的灰阶**。灰阶 ≤ 4 档，而且能说出每一档是什么角色 | J5；Things、Mela | 「过多灰阶」是不干净最常见的来源 |
| C3 | **本人笔迹是屏上对比度最高的墨**；参考字、提示、示意都比它浅或冷 | iA Authorship（本人最亮）；Mela 焦点靠明度 | 「参考不能冒充本人笔迹」，这在视觉上要成立 |
| C4 | 状态**不只靠颜色**表达：写错、自选未写、看过答案等都另有形状或文字通道。用灰度截图验证 | HIG inclusive color；Structured | 色觉障碍；也是 ADA Inclusivity 的评点 |
| C5 | 深色模式是**另外设计的**，不是反色；纸和笺的层级在深色下仍然看得出（对比 light/dark 两张同屏截图） | HIG color 深色；设计说明 v1 第 4 条 | 夜里写字是真实场景 |

### D. 形状与线条（4）

| ID | 检查项 | 出处 | 为什么重要 |
|---|---|---|---|
| D1 | 圆角只有 **3 档**（作品 0、控件 12、容器 24），屏上找不到第 4 种 | 设计说明 v1 第 9 条；Vocabulary 胶囊一致 | 圆角乱是「不精致」最直接的信号 |
| D2 | 线宽 **≤ 2 档**（格框、分隔线）；同一个组件内部不出现 3 种线（实线粗、实线细、虚线混用要有明确角色） | HIG consistency；Things 细线 | 田字格本身已有外框和十字两层，不能再加 |
| D3 | 分隔线是**最后手段**：能用留白分组就不画线；画了的线内缩到内容列，不通栏 | Things、Mela 短分隔线 | 多余的分隔线让纸面变成表格 |
| D4 | 图标同一套（同线宽、同视觉尺寸、同端点）；同一排图标等距 | Vocabulary 4 图标；Halide 同径圆控件 | 自绘图标与系统符号混用很显眼 |

### E. 信息密度与文案（5）

| ID | 检查项 | 出处 | 为什么重要 |
|---|---|---|---|
| E1 | 一屏的**说明句 ≤ 1 句**。标题已经说清楚的，正文不再重复 | HIG writing「fewer words」；grug、iA | 拾字现在常出现「标题一句、底部又一句」 |
| E2 | 同一信息**只出现一次**（例如答案字只在一个地方出现，计数只在一个地方出现） | J2 | 重复就是噪音，也会制造数值不一致 |
| E3 | 按钮文案是**动词或结果**，同一流程内用词一致（写好了、写对了、写错了、再写一组） | HIG writing 动词 / 一致 | 已有好的基础，要守住 |
| E4 | 数字排版：**大数字加小单位**，数和单位不同号；中文数字和阿拉伯数字的使用规则统一 | Gentler Streak「8h 19m」；Bears 日期角标 | 落款、统计是品味最容易露馅的地方 |
| E5 | 每屏可点的元素 **≤ 5 个**（不计 Tab 栏和返回），超过的收进「更多」或渐进披露 | HIG iOS「limiting the number of onscreen controls」；Crouton 收进胶囊组 | 写字页现在有 6 个可点项 |

### F. 状态与边界（3）

| ID | 检查项 | 出处 | 为什么重要 |
|---|---|---|---|
| F1 | 空状态有**内容和下一步**，用产品自己的语气，而不是灰框加「暂无」 | HIG writing 空状态；grug「grug back sun rise」 | 首次打开就是空状态，是第一印象 |
| F2 | 错误或失败**贴近发生处**、不责怪、能撤销；没有为预期之中的操作弹确认框 | HIG feedback / writing | 「看答案」每次都弹模态，这一条已被指出过 |
| F3 | 内容不进入状态栏和灵动岛区域，不被 Home 指示条压住（图） | HIG layout safe area | 上一轮的 S1 外壳问题 |

### G. 动效与反馈（3，多需录屏）

| ID | 检查项 | 出处 | 为什么重要 |
|---|---|---|---|
| G1 | （录）关键时刻（判断落定、一组结束）有**一个**短而准的形式，而不是硬切；高频动作（写下一笔、下一字）没有多余动画 | HIG motion / Create defining moments；ADA Delight | 上一轮核实过：落定是 33ms 硬切 |
| G2 | （录）动画可以被打断，不用等它播完就能继续写 | HIG Let people cancel motion | 练字节奏不能被动画拖住 |
| G3 | （手）触觉和画面同步：有触觉的地方，画面上一定有对应的变化 | Pok Pok 获奖理由（subtle haptics）；I13 | 「画面什么也没有、手里却震了一下」很廉价 |

### H. 品牌与记忆点（3）

| ID | 检查项 | 出处 | 为什么重要 |
|---|---|---|---|
| H1 | 印章**一屏 ≤ 1 枚**，只在落款或品牌位，从不当按钮或装饰角标 | HIG branding；设计说明 v1 第 19 条 | 印少才贵 |
| H2 | 品牌**让位于内容**：题记、字标、印加起来占屏面积小于练习字和主内容 | HIG「defers to content」 | 首页题记目前在和标题抢 |
| H3 | 有一个**贯穿全 App 的小母题**，而且每屏都只用这一套（格框、落款、朱点三者的画法每屏一致） | Bears 竖线母题；ADA「distinctive and cohesive」 | 记忆点来自重复，不来自每屏一个新花样 |

**分组条数**：A 6 / B 5 / C 5 / D 4 / E 5 / F 3 / G 3 / H 3，共 34 条。

### 3.1 「不够干净」的常见信号（看到即记一笔）

1. **框套框**：纸上放笺，笺里有格，格外又加卡片或描边。
2. **多余分隔线**：通栏线、上下各一条线夹一行、线和留白同时用。
3. **一屏两个指令**：标题一句「写对了吗？」，底部又一句「你来判断」。
4. **同一信息出现两三次**：答案字出现在顶部词条、参考格、底部列表。
5. **并列按钮权重相同却没有主次**。拾字的「写对 / 写错」是有意等重（D20），属于例外；其余地方要有主次。
6. **装饰元素和内容抢注意力**：大号竖排题记、印、插画比练习字更早被看到。
7. **圆角或线宽不统一**：同屏出现 3 种以上圆角，或者实线、虚线、粗线、细线混在一个组件里。
8. **灰阶过多**：说明文字有 3 种以上不同的灰，而且说不出各自代表什么。
9. **控件样式过多**：同一屏里同时有实心按钮、描边按钮、下划线文字、无下划线文字、带箭头文字，5 种可点样式。
10. **左右对不齐**：标签挂在内容块外侧，或者某一块的宽度和页边不一致。
11. **强调色多义**：同一个朱色既表示「写错」，又表示「图例」「自选」「品牌」。
12. **中段塌陷**：内容聚在顶部，主按钮贴底，中间有一大块不属于任何组的空白。
13. **图例依赖**：一屏需要一行图例才能看懂编码，说明编码本身不够自明。
14. **说明文字解释交互**：例如「查到的字可以直接练，也可以加入自选的字」这类句子。
15. **数字不一致或格式混杂**：同一个数在两屏不同；「278 个字」与「两字」的数字体例混用但没有规则。

## 4. 对拾字 5 屏的初步对照（提示，不是正式审查）

- **截图来源**：`.review/qa-simA/shots/` 下的 `home-large-light.png`、`write-recall-large-light.png`、`judge-large-light.png`、`result-large-light.png`、`library-large-light.png`。
- **新旧判断**：文件时间是 2026-10-04 17:07 到 17:17，属于本轮 qa-simA 的产出，我按「最新实现」处理，**但没有核对对应的构建提交号**。
- **规格**：iPhone 模拟器，1206×2622 像素（3 倍），浅色，默认字号。
- 下面的位置用「上 / 中 / 下」加目测比例描述；每屏列 3 条最明显的不合格项。

### 首页（home-large-light.png）

1. **A1 / H2 不过：三个焦点在抢。**
   - 左上的宋体大标题「今天写几个字」，右上竖排题记（两列，字号与标题相近）加朱印，中部五格字帖，再加底部黑色主按钮，眯眼看是 3 到 4 个块。
   - 题记加印的面积接近标题，品牌没有让位于内容。
   - 主角应是「今天写的字」，也就是字帖那一排。
2. **A3 / A4 不过：中段塌陷。**
   - 标题和题记组（上 0 到 27%）与字帖（41% 到 49%）之间，有约 13% 屏高的空白。
   - 「字库里有 277 个字了 ›」（约 56%）与主按钮（约 77%）之间，又有约 20% 屏高的空白，不属于任何组。
   - 字帖悬在中间，与上下都没有关系。
3. **B1 / E5 / 信号 9 不过：层级和控件样式太多。**
   - 可见字号约 7 级：日期、标题、题记、题记署名、字帖楷字、「这一组还有 3 个字」、「字库里有…」、按钮字、「自己选字」，还不计 Tab。
   - 可点样式有 3 种：实心按钮、下划线文字（「自己选字」）、带箭头文字（「字库里有 277 个字了 ›」）。
   - 字帖格本身用了 3 种线：赭灰外框、黑色粗框（当前格）、淡虚十字（空格），违反 D2。

### 写字页（write-recall-large-light.png）

1. **E5 / 信号 9 不过：可点项 6 个，分布在 3 排，样式有 4 种。**
   - 6 个可点项是：撤销、清空、提示·还有 2 次、写好了、看答案、跳过；样式包括无下划线文字、描边按钮、实心按钮、下划线文字。
   - 「撤销 / 清空」右对齐悬在格下，「看答案 / 跳过」推到左右两端。
   - 对照 Crouton：除「写好了」外，其余可以收成角落的一组。
2. **C3 / 材质不过：墨是等宽圆头记号笔。**
   - 「扌」三笔线宽一致，起收都是圆头，与「纸、墨、朱」的气质不符。这与上一轮 V01 / I01 一致。
   - 本人墨对比最高这一点是成立的（C3 的另一半过）。
3. **A2 / A3 不过：版心和留白不成组。**
   - 顶部词条「根□」整组偏左，左缘约在屏宽 29%，右缘约 57%，与下方书写格的中线不对齐（格的中线在 50%），只是让空格落在拼音下面。
   - 「撤销 清空」与按钮组之间有约 12% 屏高的空白。
   - 标题「凭记忆写出这个字」是一句操作说明（E1），对熟练用户每次都在重复。

### 判断页（judge-large-light.png）

1. **E1 / 信号 3 不过：两个指令。**
   - 顶部标题是「对照一下，写对了吗？」，底部又有一句「你来判断，点一下就记下。」。
   - 另外答案字「据」出现了两次：顶部词条格和参考格（E2）。
2. **A2 / 信号 10 不过：对照块与页边不一致。**
   - 上下叠放的对照卡宽度只占屏宽约 21% 到 79%，比其他内容窄。
   - 「你的书写 / 参考字形」两个标签挂在卡的右外侧，贴近右页边。
   - 结果是这屏有三套左右边界：页边 46、卡边 193、标签右缘 870 像素位置。
3. **A5 不过：与写字页之间的位置跳动。**
   - 写字页的书写格是满宽（5% 到 95%），判断页的本人笔迹卡缩到 21% 到 79%，同一笔迹的尺寸和位置都变了。
   - 左上的返回控件也从「‹」变成下划线文字「接着写」。
   - 说明：「写错了 / 写对了」两按钮等重，是 D20 的有意设计，**不算违反信号 5**。

### 结果页（result-large-light.png）

1. **A6 / 信号 1 不过：框套框。**
   - 字帖是一张笺色卡（与纸色差极小，边缘几乎看不出），里面又有一个赭灰外框，框内再用竖线分格。
   - 下面三行，每行是一个带框的字，上下又夹着通栏细线。
   - 一屏用了 4 种分隔手段：笺面、外框、格线、通栏线。
2. **C1 / 信号 11 需复核：朱色两处两义。**
   - 两处是：落款印（品牌）和「求」行前的朱点（写错）。按设计说明 v1，这是允许的上限（≤ 2 处）。
   - 但朱点放在行首文字前，而不是像设计说明第 15 条那样放在「墨迹外框右上」，同一符号在结果页和字墙上的位置规则不一致（H3）。
3. **E1 / E2 / B4 不过：文字密度高。**
   - 三行状态句都用「」引号重复字名，最后一行「「求」明天再来找你，「据」过两天，「类」过几天。」几乎通栏，有 6 个引号。
   - 状态词风格不一致：「写错了，没放进图里」「看过答案」「跳过了」。
   - 灰字「程、北」与黑字「求」靠灰度区分状态，没有形状通道（C4）。

### 字库页（library-large-light.png）

1. **E1 / E5 / B1 不过：一屏塞了 6 个区块。**
   - 6 个区块是：标题、搜索框加一行说明、练习范围行、大数字统计加一行副统计、双栏「写错过 / 快忘了」、图例加字墙。
   - 可见字号约 8 级：标题、搜索占位、说明、范围、278、个字、副统计、栏标题、栏数字、栏说明、样字、链接、图例。
   - 搜索框下的「查到的字可以直接练，也可以加入自选的字。」属于信号 14。
2. **C1 / 信号 11、13 不过：朱色出现得最多、最响。**
   - 朱或淡朱出现在：栏标题前的朱点、每个样字右上的朱点（4 个）、图例的朱点和淡朱方框、字墙上的淡朱双钩字（完设式）、字墙上的朱点。目测超过 12 处。
   - 依赖两行图例（4 档墨线加 2 个符号）才能读懂编码。
   - 「写错过」一栏，标题有朱点、每个字又有朱点，标记重复。
3. **D3 / 信号 2 不过：分隔线多且不统一。**
   - 「练习范围」行上下各一条通栏细线。
   - 双栏上方各有一条短线，左右两段长度和间距不同。
   - 统计与双栏之间又靠留白分组，线和留白混用。
   - 数字体例混用：「278 个字」用宋体大数字加小单位（好），而「58」「12」用宋体小号数字右对齐，同一屏两套数字样式（B4 / E4）。

### 给下一轮审查者的提示

- 第 4 节只看了每屏的一张默认态截图，**没有覆盖**以下内容：深色、AX 大字、空状态、加载、动效、读屏。
- 动效和触觉（G1 到 G3）必须看录屏或过渡帧序列。
- 深色与大字可以直接对照同目录下的 `*-large-dark.png`、`*-accessibility-*.png`。
- 首页「277」与字库页「278」两个数不同。可能是拍摄间隔里又记录了一个字，也可能是口径不同，**需核对种子数据后再判断**，不要直接记为缺陷。
