> 阅读范围：`package.json` scripts、`.github/workflows/verify.yml`、`scripts/verify_*.{js,py}`、`scripts/fixtures/`、`scripts/summarize_backups.py`、`ios/ShiziApp/scripts/validate-native-smoke.py`，以及 `origin/pr-175` 新增的内容门禁。所有路径相对仓库根 `/Users/orange/Documents/ChatGPT/astraworld/shizi-app`。产品决定以 `docs/handoff/decisions.md`（D01–D25）与 `docs/product/04-v10-handoff.md` 为准。

## 1. 概览

1. 测试入口只有 `pnpm test` = `verify:data`（两条纯数据门禁）+ `verify:web`（三条 Playwright 门禁 e2e / ui / pwa），见 `package.json:6-15`；CI（`.github/workflows/verify.yml`）在 ubuntu + Node 22 + pnpm 11.16.0 + Playwright 1.62.0（`pnpm-lock.yaml:22-39` 锁定）上起 `python3 -m http.server 8000` 后顺序跑这两组，30 分钟超时，`verify:native-smoke` 不在 CI 内。
2. 主 e2e `scripts/verify_8105_app.js` 是一个 293KB、2762 行、245 条 `assert` 的**单体顺序脚本**：先在 Node 侧做约 60 条对 `index.html`/`sw.js`/iOS Swift 源码/数据文件的**字符串级静态断言**（L90–183），再启动一个共享的 Chromium page，从 `localStorage.clear()` 开始按固定顺序走完全部旧产品流程（欢迎页→15 字校准→盖章→撤销→补记→字帖→备份导入等）。任何一条断言失败即整体退出。
3. 驱动方式是**白盒**：大量 `page.evaluate` 直接读写 `index.html` 的顶层全局（`memory` 119 处、`funnel` 73 处、`roundStats` 52 处、`calibration*`、`restoreBackupPayload` 13 处、`resumableSession` 11 处等），只用了约 50 个 `#id` 选择器，`page.click` 仅 53 次。因此任何 UI 重写（改 id、拆模块、改全局名）都会让它在第一条浏览器断言（`verify_8105_app.js:324` 的欢迎页文案“先练15个字”）就红。
4. 真正与 UI 无关、必须在 v10 重写后仍然保留的**数据/资产门禁**是：`verify_library_governance.py`（8105 规范字 → 7294 可练 / 811 不可练，四库 3500/2976/818/2500，全部 SHA-256 钉死）、`verify_vector_data_440.js`（440 字矢量补充的证据链 + 浏览器 SVG 渲染）、`verify_pwa_upgrade.js`（回放真实 v10 SW 升级到 v13，503 回落缓存，字节级 deck 校验）、以及 `verify_8105_app.js:90–148` 的字源/题记/许可/CSP 静态块和 L214–248 的 SW 配额隔离单元测试。
5. `verify_ui_copy.py` 是**文案禁用/必含词表**，与旧产品文案强绑定（要求 `index.html` 含“盖章 ${monthDays}天 · 累计 ${totalDays}天”“第 1 步：描红”“看看写得不稳的字”等），在 `verify_8105_app.js:9` 模块加载时同步执行，v10 文案一落地它会先于任何浏览器测试把 e2e 打红。
6. `verify_redesign_v3.js` 是第八稿（“v4 视觉”）的截图 + 几何检查脚本，断言调色板十六进制值、“一屏至多一个实心朱红”、六列记忆墙、45 条释义 × 8 组显示矩阵；截图只落盘（`generated/redesign-v4/`，已 gitignore）**没有任何像素/基线比对器**。
7. PR #175（`origin/pr-175`，单提交 `fe85323`）新增纯 VM 内容门禁 `content-corpus.cjs` / `verify_content_corpus.cjs`（340 条已批准题面修订、重复目标字全部遮住）与浏览器版 `verify_content_ui.cjs`，并把 `verify:content` 追加进 `verify:data`；D16 已确认它落地，但它靠 `index.html` 里若干精确字符串锚点抽取代码，重写时要重新锚定。
8. 现有测试覆盖与 D17–D25 冲突的地方非常多（详见第 4 节）：欢迎页与 15 字校准（D17）、不会写→描红记 miss（D18）、1.8s 改判窗口与“重盖”撤销条（D19）、“写对了/写错了”顺序与第三个“不确定”键与软确认（D20/D03）、分离的查字/加字入口（D21）、补记与“短暂显示撤销”（D24）、“点拨”金色提示语义（D25）。

## 5. 风险与坑

1. **单体顺序脚本的“第一条红”效应**：`verify_8105_app.js` 共享一个 page 与 localStorage，245 条断言线性依赖前文状态（例如 L2296-2299 用 `restoreBackupPayload` 复位库状态，L2606-2607 注释专门提到 `visibilitychange` 保存会污染“干净设备”前提）。v10 落地后它会在 L324 立即失败，后面 2400 行的数据契约断言全部得不到执行——因此**必须先把 L90-158、L185-248、L2394-2723 抽成独立脚本**，否则数据门禁会随 UI 门禁一起失效。
2. **`verify_ui_copy.py` 在 e2e 模块加载时同步执行**（`verify_8105_app.js:9`），且必含表锁死旧文案。v10 “文案修改清单”一落地就红。它的机制（按文件的禁用/必含表）适合直接改成 v10 文案清单的检查器。
3. **白盒耦合**：测试直接读写 ~120 个 `index.html` 顶层全局（第 2 节列举），`page.evaluate` 223 次。若 v10 实现把 `index.html` 拆模块或改用 `let/const` 作用域，所有现存用例失效；PR175 的 `content-corpus.cjs` 更依赖 6 个精确字符串锚点（`const CARDS=[];`、`// ---- 本地存储 ----`、单行 `function promptHTML(c){`、`$("hint").textContent=`、`const LIBRARIES=[`、`function defaultLibraryId()`），任一改动即抛 “boundaries changed”。
4. **哈希常量分散在多处**：语料再生成要同时更新 `verify_library_governance.py:14-30`、`verify_pwa_upgrade.js:27-32,36-45`、`verify_8105_app.js:97-99,604,650`、PR175 `content-quality-baseline.json`（`deckSha256/identitySha256/protectedCardDataSha256`）、`verify_redesign_v3.js:392`（45/360 → 87）。没有单一来源。
5. **PWA 门禁对 git 历史的依赖**：需要 `origin` 可达并能按 SHA 取到 `4d6e8e59…`（浅克隆下走 `fetch --depth=1 origin <sha>`，`verify_pwa_upgrade.js:158-180`）；每次运行还会 `git clone --depth=1` 一份仓库做中文路径控制（L214-238），并修改临时克隆里的 `data/水.json`。历史重写/仓库迁移/离线环境都会让它红；它比较的是**工作区**而非 HEAD（L182-186 注释）。CI 的 `node --check` 列表漏掉了它（`verify.yml:28-30`）。
6. **浏览器可执行文件**：`verify_vector_data_440.js:691` 找不到 Chrome/Chromium 即失败（不像 e2e/ui 会回落到 Playwright 自带 chromium）；它列出了 Linux 路径，GitHub ubuntu 镜像通常自带 `google-chrome`，但自托管 runner 可能没有。main 上的 `verify_8105_app.js:46-51`、`verify_redesign_v3.js:37-42` 只认 macOS 路径（PR175 补了 `CHROME_PATH`）。
7. **没有像素级截图比对**：`generated/*.png` 与 `generated/redesign-v4/` 均 gitignore（`.gitignore:7-8`），截图只是副产物；所有“视觉”断言实为计算样式/几何/对比度数值。不要指望“截图比对器”可复用——可复用的是 `computedContrast`（含 alpha 合成，`verify_8105_app.js:69-88`）、`verify_redesign_v3.js:289-303` 的尺寸×主题×页面矩阵循环、以及 `scrollWidth<=innerWidth`、`getBoundingClientRect` 不重叠/不裁切的写法（`verify_content_ui.cjs` 的 `assertLayout`）。
8. **网络错误白名单机制**（`verify_8105_app.js:284-309,760-797`）：只按完整 URL、只消费一次、支持迟到消息。有注释说明 CI 曾因此误红。若新实现增加任何跨源或预期失败请求，要按此机制登记，而不是放宽正则。
9. **备份/安全副本的原子性依赖 `Storage.prototype.setItem` 猴补**（L2374、L2717、L2740-2744）：新实现若改用 IndexedDB 或封装存储层，这些注入点失效，需要提供可替换的存储驱动或等价故障注入。
10. **配额/容量断言写死旧政策**：`FSRS_RAW_RETENTION_DAYS=120`、`ACTIVITY_RAW_RETENTION_DAYS=400`（L168）、funnel 512/256/180（L2715）、近墨 96 份/420 KiB（L1947）。决定表明言“不以旧 96 份/420KiB 当新政策”“新逐判断存储暂停”，这些数值不能原样搬到 v10 测试。
11. **原生冒烟契约是旧产品的镜像**：`validate-native-smoke.py` 90+ 个布尔位与 `stampGuide/summaryPocket/traceTutorial/calibrationReturn/monthlyRhythm/bookAchievement` 等旧概念绑定；`WebViewController.swift` 的 `#if DEBUG` 冒烟代码要同步重写，`verify_8105_app.js:158` 还断言其源码形状。CI 不跑它，容易漂移。
12. **时间预算**：单个 CI job 30 分钟（`verify.yml:17`）内要跑 vector440 全量 440 字浏览器渲染 + e2e 245 断言 + ui 360 组释义矩阵（PR175 起 87×8=696）+ pwa 七步含两次 SW 生命周期等待（最长 120s）。v10 重写期间若新增用例，应先拆 job 并行。
13. **PR175 的双重来源**：`reviewedOverrides(legacy, approval)` 把旧 `context-overrides-approved.json` 与新 340 条合并，`w` 覆盖会删 `gloss/preserveCommon`，`gloss` 覆盖会删 `w/ci/promptHint`（`content-corpus.cjs:51-59`）。D13 提醒“旧语料覆盖不自动覆盖 #175 或未来句库”，合并顺序是隐含契约。
14. **`summarize_backups.py` 的隐私前提**：它是唯一“分析”工具，只读本地导出备份；D01 不做排名，v10 若删除校准与 makeup，这个脚本的大部分指标为空，需决定保留或删除，避免 CI 里留死代码。
