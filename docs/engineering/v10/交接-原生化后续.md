## 6. 卡片通用规则（派卡时写进说明）

- 每张卡在自己的 git worktree 里做，`git reset --hard <主线基线>`；不碰主仓库目录；没有 node_modules 就软链主仓库的（不提交）。
- 标准答案 = 现行网页版（B3.3 已取齐全部参考图，`ShiziUITests/States/`、`Reference/`）。逐屏 0 差异；段落换行用网页量出的行起点（B2.7 `webLineStarts` 做法），不靠豁免；豁免只给真正的平台差异并写理由。
- 页面卡做法见计划书 §10.9 末「给页面卡」：`Screens/<Page>.swift` + `@objc(ShiziScreen_<name>)`；`registerScreen` 加 `native: true`；填 `src/session/api/<page>.js`；契约测试 `test/ui/native-<page>.test.mjs`（网页路径 == API 路径）；夹具改 `native: true` 并填 `keys/<screen>.mjs`；补 ShiziUITests 里该页的待填流程测试。不改共享文件。
- 原生源码不写汉字字面量；文案走 `src/config/copy`；不改用户可见文案（要改先记决定）。
- 模拟器自建、名字带卡号、用完删；不动别人的模拟器、不 erase；不连真机；绝不 pkill e2e；不杀不是自己起的进程。
- 中文提交，前缀 `feat/fix/test/docs(<卡号>)`，结尾 `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`；卡不推送不合并（由主控合并）。
- 模型分配：架构 / 原生核心 / 跨页 / 难 → Opus；有明确标准答案的页面、规格、机械移植 → Sonnet；琐碎机械活 → Haiku。
