# 设计师交付接口

分工已确认：设计师提供当前有效设计源文件及依赖；产品负责人提供产品依据、决定、验收材料和团队接手说明。本文只定义接收核对，不假装已拿到正式交互，也不复制未经整理的旧快照为当前设计。

## 设计师需标清的内容

| 交付 | 接收检查 |
| --- | --- |
| 当前冻结版主画布、页面与组件源文件 | 明确第八稿及后续修订版本；主入口、字体、颜色、尺寸和状态位置可查，不混入已废弃稿 |
| 令牌、动效和组件规范 | 标清真实文本/数据、装饰图、系统控件的边界；减少动态效果及适配规则能找到 |
| 引用脚本、字体引用说明和素材 | 相对依赖完整、来源/许可清楚，离开设计师电脑仍能查看；字体生产候选另见 #180，不重新分发全量上游字体当运行包 |
| 笔迹参考 JS、规格样例、回放格式 | 标清“原型参考”，尤其点画分支以 D09 文字裁决为准；真人录制未提供时不能把合成样例当真人 |
| 正式交互交接（目前尚未收到） | 页面入口/返回、状态、数据来源、成功/失败/禁用条件可连续演示；对照 I01–I04 和已定规则，不只给截图 |
| 交接备注与改动清单 | 哪些已改、待定、未实现、仅演示；与本包决议冲突时逐项列出，不能静默采用旧稿 |

## 当前交付缺口

本 PR 不含上述设计原件。此前本地持有的“第八稿交接版”快照可用于追溯，但本包不将其认定为设计师最终的完整交互交付。接收时登记文件清单/版本或 SHA、打开方法、验收人及缺项；在设计师提供位置后更新本页链接。

不必把每份历史试稿、旧评审图片和重复压缩包转交新团队。需要的是可打开的当前有效版本及其规则来源。旧图与当前决定冲突时，产品负责人按 [decisions.md](decisions.md) 核对，设计师更新对应说明。
