# 产品方向与前四步资料状态

## 已确认的产品方向

拾字面向已经学过汉字、想回忆字形的人。主要场景是自愿打开，安静地写几个字，想停就停；查找或添加某个特别想练的字是补充入口。

- 三个主导航为“习字／字库／我的”。首页保留一个清楚的开始／继续主入口；不叠加重复续练卡或每日完成压力。
- 用户写字后，将本人笔迹和参考字形分区对照，自行判断“写对了／写错了”。参考不能冒充本人笔迹，也不以书法美观给用户评分。
- 提示、完整答案、描写、再试和跳过的含义分开。看过答案、描过或跳过不能直接当作写对或有效记录。
- 修改上一条判断更新同一条记录，不增加次数，不丢当前正在写的笔迹和帮助状态；入口留至当前字提交。
- 自己选字、查字、添加自选的字区分意图；输入或取消查询不提前新增练习记录。
- 真实字库、记录、需要再练、设置、图片、年度报告及备份恢复等能力应合理可达。简化外观不等于删除已有功能。

普通或首次练习与临时自选练习分别保存：临时练习暂停后优先续临时练习；明确结束后返回来源，首页可继续原练习，不自动跳入原练习；不能静默覆盖未完成现场。字母 A/B 只用于工作文档，不进入产品界面。

## 前四步完成了什么

| 前序资料 | 已有成果 | 不能声称已经完成 |
|---|---|---|
| 1. 项目简报 | 定位、问题、目标、阶段门槛 | 成功指标阈值、预算和发布日期尚未确认 |
| 2. 研究证据与验证计划 | 产品主导者反馈、内部及外部评审的来源整理；目标用户研究方案 | 没有本轮目标用户招募、访谈或完整可用性测试结果，不能把 AI 走查或参与者计划当成真实用户数据 |
| 3. 需求范围与验收标准 | 核心能力、必须保留功能、暂缓项、失败与数据后果的检查条件 | 部分产品规则仍未定；旧需求表中的术语、历史字数与兼容门槛不能整表直接用作当前开发规格 |
| 4. 用户旅程与信息架构 | 三导航及开始、帮助、自判、更正、暂停、临时练习和数据管理的目标路径 | 目标旅程不是已观察的普遍用户行为，也不是第八稿完整跨页交互已交付 |

不将“写出了四份资料”表述为前四阶段全部验收完成。后续研究若执行，应记录实际样本、版本、任务、观察和局限，不填入虚构成功率或留存数据。[既有产品验证议题 #46](https://github.com/Eim-aa/shizi-app/issues/46)可作为相关历史讨论入口；本次不重复立项，也不启用增长或打卡实验。

## 当前视觉方向

第八稿视觉已冻结。采用温暖纸色、墨色文字、克制的暖红主行动、统一导航与卡片层级；标题和题记服务于开始写字入口，不与主行动争夺注意力。楷体用于练习字词，宋体用于标题、题记与大数字，界面文字使用清楚易读的黑体。

已有第八稿的细纸纹、柔和光影和有限印章表达不等于恢复旧版复杂桌面场景。原型使用人工笔迹时须明示；不能把生成或测试笔迹当作真人书写证据。

不新增连续打卡奖惩、排名、强制每日数量、自动书法评分、账号云同步、拍照识字或新的诗词内容平台。

## 工作与验收方式

产品负责人整理决定与范围，设计交付结构和交互，工程落实真实数据与行为，独立验收核对证据。已确定的要求无需反复确认；新的实质产品取舍须有具体方案与影响。每项结论标明版本、实际检查范围和未覆盖部分，作者自检、独立复核与用户签收分别记录。
