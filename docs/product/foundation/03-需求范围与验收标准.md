# 03 · 需求范围与验收标准

版本：接手整理版 · 2026-09-27。保留前期资料的 G/E/H/R/J/O 编号；已按本 session 最新决定更新。来源与适用边界见 [总览](README.md)。

## 1. 适用范围与优先级

本轮是拾字的简化版体验与 UI 改版：保持“习字／字库／我的”，保留真实功能，改清入口、流程、文案和视觉层级。它不是重做内容平台，也不是新增打卡模式。[S02、S03、S06]

本表是目标需求；底层和内容成果的实际状态见团队接手清单。“必须”表示设计和后续实现需满足，**不表示当前生产代码已实现或第八稿交互已验收**。

- **M1 核心必需**：开始、书写、帮助、自判、会话与记录保护。先形成连续原型并验证。
- **M2 完整性必需**：字库、我的、设置、图片与数据管理等既有能力。不能因为优先做核心就从最终版本消失。
- **L 后续可选**：未获本轮授权的新能力或复杂装饰，不投入当前实现。

优先级不同于缺陷严重度。验收中，数据覆盖、误记与破坏性操作问题属于发布阻断风险；当前资料没有据此声称生产发生过这些事故。

## 3. 关键业务规则

### 3.1 记录规则

| 事件 | 已定含义 | 不允许的推断 |
|---|---|---|
| 输入／查字／看详情 | 浏览或选择行为 | 自动记为练过、掌握或一次正确尝试 |
| 获取帮助／看完整答案 | 保留真实帮助事实 | 自动判错、判对；再试时清掉曾看过答案的历史 |
| 仅描写／仅跳过 | 与独立回忆及有效自判区分 | 直接增加有效练习、正确数或掌握数 |
| 本人书写后明确判断且保存成功 | 新规则中的有效尝试依据 | 把一次尝试数量等同于去重字数；把自判写对等同于稳定掌握 |
| 修改上一条 | 更新同一尝试的判断及相关汇总 | 创建第二条、重复累加错误，影响当前正在写的字 |
| 保存失败 | 尚未完成本次提交 | 跳到下一字、关闭失败现场或展示“已保存” |

首页 N 的定义沿用现有实现；N≤8 显示 N 项，N>8 显示最近判断的 8 项但数字仍为 N。它与当前会话状态独立。其他统计和“需要再练”的退出仍需确认映射；不借此新增目标或压力机制。[S02、S03、S06]

### 3.2 会话规则

A 表示普通／首次练习；B 表示从选字等入口开始的临时练习；C 表示 B 未完时又想创建的另一段临时练习。这些是规格术语，不展示给用户。

| 前置／动作 | 结果 |
|---|---|
| A 未完，明确选择一些字开始 B | 保存并保护 A；B 独立进行，不能覆盖 A 的位置、笔迹和帮助状态 |
| B 暂停并返回 | 保留 A 与 B；首页中央入口优先继续 B |
| B 明确结束 | 进入 B 的结果／相应收尾；返回来源后解除 B 的待续状态。若 A 未完，首页中央入口恢复继续 A，不自动进入下一字 |
| B 未完又想开始 C | 保留原选择现场并说明已有待续练习，提供继续已有 B 或取消；不覆盖 B、不偷偷结束它 |
| B 未完，只查一个字 | 可以查询和查看详情；到真正开始新练习时才检查会话限制 |
| 任意保存失败 | 保持原阶段、笔迹与帮助状态，重试提交同一次操作；结果不能凭动画假定成功 |

数据保护是已定要求；实现机制、崩溃与冲突恢复仍需工程方案和正式验证。[S02、S06、S08]

### 3.3 内容与兼容边界

- E1 核实的候选基础字库含 7294 个唯一可练字；四库可练量为 3500／2976／818／2500，第四库与第一库重叠，不能相加当总量。这是该候选数据事实，最终显示从已确认的数据源读取，不永久硬编码为产品承诺。[S05]
- 首次既有 15 字安排保留；短演示片段不等于完整首次流程已验证。
- 取消历史测试记录兼容硬约束；必要数据调整仍保证当前功能关联。缺少对应本人笔迹时如实说明，单字图片和月/次图片区分处理；月/次可用浅色参考，不能伪装成本人笔迹。
- 不用旧代码行为否决已定体验；也不把设计样例中看起来存在的内容当成生产真实能力。

## 6. 验收怎么做

### 证据分层

| 阶段 | 必须交付的证据 | 不能替代什么 |
|---|---|---|
| 结构稿 | 页面／状态 ID、入口和去向、文案、缺稿列表、指定尺寸截图 | 不能证明按钮行为、真实存储或连续体验 |
| 连续交互原型 | 任务步骤、实际前后状态、路径与失败演示、数据／能力边界 | 不能证明真实调度、完整数据迁移或所有设备可用 |
| 正式实现 | 确定版本、真实调用路径、隔离测试数据前后对比和失败重试结果 | 代码存在或单测通过不能替代设备触控与系统行为 |
| 真机及产品验收 | 设备／系统／构建、关键任务、后台恢复、字号、安全区、权限和数据结果 | 单设备通过不能宣称所有平台通过 |

每项结果至少写 `需求 ID / 版本 / 前置条件 / 操作 / 实际结果 / 证据路径 / 通过或未通过 / 未覆盖范围`。已有详细场景沿用 S09，按本文件及最新裁决校正，不重新把旧计划当已通过。

### 必须保留的关键反例测试

1. 首页今日记录 0／有 × 未完成会话无／有四种组合，加首次状态。
2. 没落笔就看答案、描写或跳过，不能被误计为独立有效尝试。
3. 当前字已写几笔且用过帮助，再改上一判断；当前现场不变、旧尝试不增条数。
4. A 暂停→B 开始→B 暂停／结束两条分支；中央入口分别继续 B／恢复 A。
5. B 未完时只读查字允许，真正开始 C 则保护已有 B。
6. 保存失败与重试、重复点击／响应；不推进、不丢现场、不重复计数。
7. 坏备份、保护副本失败、恢复失败、取消；不得静默覆盖原数据。
8. 短屏、大字、长文本、输入键盘；主操作可达，正文与底栏不相互遮挡。

这是待执行的验收清单。当前 D2.1 和 E3.1 的有限通过情况仅按 S07、S08 的列明范围引用。
