# 冻结的真实 v10 一代

`scripts/verify_pwa_upgrade.js` 回放的旧 PWA 一代，取自 main 的 `4d6e8e59d499e968c398ce662aff69eaff714f9d`（合并 PR #153 后的 main）。

这里只冻结两份小文件，让"被回放的旧缓存策略"在代码评审里直接可读：

| 文件 | 作用 |
| --- | --- |
| `sw.js` | 真实 v10 worker。HTML 网络优先、同源静态资源缓存优先、缓存键是不带指纹的裸路径、`activate` 删除所有非当前版本缓存。 |
| `core-strokes.js` | 真实 v10 的核心 600 字派生逻辑。它从 `SEED` 排序取前 600，所以 v10 的 `importScripts` 必须先加载 `deck-data.js`。 |

## 这两份文件不是门禁的数据源

门禁运行时从 `LEGACY_COMMIT` 直接取 blob 到临时目录并按 SHA-256 校验，再断言取出的字节与这里冻结的副本完全一致。因此：

- 冻结副本被改 → 门禁失败；
- 上游 commit 被改写 → SHA-256 校验失败；
- 两边一起改 → 仍需与脚本里钉死的摘要一致才能通过。

`index.html` 与 `deck-data.js` 体积较大（约 2.2 MB），不在这里重复保存，只在脚本里钉死它们的 SHA-256。旧一代的 `data/` 静态资源直接用当前工作区提供，但门禁会先用 `git ls-tree` 证明旧 commit 的每个 `data/` blob 在当前树中逐字节相同，不相同就直接失败。

## 为什么不能用手写的迷你 v10

手写复刻很容易把 HTML 也写成缓存优先。那样"升级失败后普通刷新仍是旧题库"这类断言会在真实路径上不成立，却照样通过，从而把关键资源 503 不回落缓存这类问题假绿。
